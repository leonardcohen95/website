🏆 考场必胜技巧

① 每道题的开头都是 ssh 命令
题目格式：ssh cka00000X，必须先切到正确集群，否则零分！所有题目做完要 exit 回 base 节点。
② 开卷考，善用官方文档
允许访问 kubernetes.io/docs、github.com/kubernetes。但搜索结果排序和平时不同，建议用左侧导航栏找。每道题也给了参考链接。
③ 多用 Tab 自动补全
考试环境有自动补全，比手打快 3 倍。例如：
kubectl -n au↑Tab autoscale↑Tab deploy↑Tab apache↑Tab
④ 编辑 YAML 报错要小心
kubectl edit 改错了，第一次 :wq 会报错；第二次 :wq 会回滚所有修改！建议先导出 YAML 改完再 apply。
⑤ Ctrl 快捷键注意区别
操作考试终端说明
复制Ctrl+Shift+C不是 Ctrl+C
粘贴Ctrl+Shift+V不是 Ctrl+V
不杀标签页Ctrl+Alt+WCtrl+W 会关掉 Chrome 标签
⑥ 查字段用 explain
kubectl explain deployment.spec.template.spec.containers.resources —— 不确定 YAML 字段怎么写就查！

⏰ 时间管理红线

🚨 3 条绝对红线，超过必挂
  1. 单题卡超过 8 分钟 → 写 YAML 骨架占坑，exit 跳下一题，回头补
  2. edit 第二次 :wq → 直接 :q! 退出不保存，重来
  3. 剩余时间 < 20 分钟 → 跳过 #9 Gateway，确保其他 15 题至少有骨架
✅ 节省时间的习惯
• ssh 之后再读题（利用延迟时间扫题）
• 做完立刻 exit 回 base 节点
• sudo -i 的题（15、16）放一组做，只切一次 root
• etcd 修复题改完 manifest 必须 restart kubelet

1、HPA 自动扩缩容 ↑ 返回做题顺序

你必须连接到正确的主机。不这样做可能导致零分。

[student@k8s-master1] $ ssh cka000001

Task

在 autoscale namespace 中创建一个名为 apache-server 的新HorizontalPodAutoscaler(HPA)此 HPA 必须定位到 autoscale namespace 中名为 apache-server

的现有 Deployment 。

将 HPA 设置为每个 Pod 的 CPU 使用率旨在 50% 。将其配置为至少有 1 个 Pod，且不超过 4 个 Pod 。此外，将缩小稳定窗口设置为 30 秒。

参考链接

https://kubernetes.io/zh-cn/docs/concepts/workloads/autoscaling/horizontal-pod-autoscale/

解答
1按照题目要求,在base 节点上执行,切换到题目要求节点

确保在 student@k8s-master1:~$下,再执行切换集群的命令

ssh cka000001  MAC模拟环境直接做题，所有题都不需要SSH
2创建 HorizontalPodAutoscaler
kubectl -n autoscale autoscale deployment apache-server --cpu=50% --min=1 --max=4

提示 autoscaled,表示成功

第一个 autoscale 是 namespace 的名字,这个题目里要求的“在 autoscale namespace 中”第二个 autoscale 是指要自动扩容 deployment

3修改 HorizontalPodAutoscaler 缩小稳定窗口为 30 秒
kubectl -n autoscale edit hpa apache-server

在 maxReplicas: 4 这一行下面新增 3 行

behavior:
scaleDown:
stabilizationWindowSeconds: 30

提示 edited,表示修改成功。如需查看再次edit，字段的位置是移动到后面。因为字段会自动按规则排序

考试时会显示如下多余的字段是原来或自动生成的，不用管：

4检查 HorizontalPodAutoscaler
kubectl -n autoscale get hpa apache-server
5别忘记,做完后,退回到base 节点,这样下一道题才能继续切节点。
# 退出 cka000000 节点,返回到 student@k8s-master1 用户和节点下

2、Ingress ↑ 返回做题顺序

您必须连接到正确的主机。不这样做可能导致零分。

[student@k8s-master1] $ ssh cka000002

如下创建新的 Ingress 资源：

名称： echo

Namespace： sound-repeater

使用 Service 端口 8080 在 http://example.org/echo 上公开 echoserver-service Service。

参考链接

https://kubernetes.io/zh-cn/docs/concepts/services-networking/ingress/

1按照题目要求,在base 节点上执行,切换到题目要求节点
ssh cka000002
2查询ingressClassName,发现名字为 nginx,这个下面要用到

！20260109更新 注意ingress-nginx停止维护，目前考试环境最新更新为edge-proxy

kubectl get ingressclasses.networking.k8s.io
3创建ingress
vim ingress.yaml

添加如下内容

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
name: echo
namespace: sound-repeater
spec:
ingressClassName: edge-proxy  # 上一步查询到的名字，最新的考试是edge-proxy。模拟环境用nginx！！！
rules:
- host: "example.org"
http:		#与上一行对齐，word排版有问题，复制此段是正常的，考试时如果是复制官网的，记得删掉前面的 - 。
paths:
- path: /echo
pathType: Prefix
backend:
service:
name: echoserver-service
port:
number: 8080

创建

kubectl apply -f ingress.yaml

提示 created,表示创建成功

4检查，模拟环境使用以下命令测试，考试时用题目中的命令测试。不用管30080端口哪来的，考试时他给什么链接你就复制什么链接。他是不带30080。
curl http://example.org:30080/echo
5别忘记,做完后,退回到base 节点,这样下一道题才能继续切节点。

3、sidecar ↑ 返回做题顺序

您必须连接到正确的主机。不这样做可能导致零分。

[student@k8s-master1] $ ssh cka000003

Context

您需要将一个传统应用程序集成到 Kubernetes 的日志架构(例如 kubectl logs)中。实现这个要求的通常方法是添加一个流式传输并置容器。

Task

更新现有的 synergy-leverager Deployment，

将使用 busybox:stable 镜像，且名为 sidecar 的并置容器，添加到现有的 Pod 。新的并置容器必须运行以下命令：

/bin/sh -c "tail -n+1 -f /var/log/synergy-leverager.log"

使用挂载在 /var/log 的 Volume，使日志文件 synergy-leverager.log 可供并置容器使用。

除了添加所需的卷挂载之外，请勿修改现有容器的规范。

参考链接

https://kubernetes.io/zh-cn/docs/concepts/cluster-administration/logging/

1按照题目要求,在base 节点上执行,切换到题目要求节点
ssh cka000003
2导yaml，也可以在线直接edit，但不建议，如果改错了麻烦。
kubectl get deployment synergy-leverager -o yaml  > sidecar.yaml
3编辑 yaml
vim sidecar.yaml

注意从官方复制过来的空格不对,每行少 4 个空格。这是因为官网的是 Pod 的示例,而考试要修改的是 Deployment。

在 dnsPolicy: ClusterFirst 上面添加的下面,添加如下内容

volumeMounts:
- name: varlog
mountPath: /var/log
- name: sidecar
image: registry.cn-hangzhou.aliyuncs.com/fizz_1024/cka:busybox-unstable #国内环境有这个镜像代替， MAC用registry.cn-hangzhou.aliyuncs.com/fizz_1024/busybox:latest。考试时用题目中提供的镜像！！！
args: [/bin/sh, -c, 'tail -n+1 -f /var/log/synergy-leverager.log']
volumeMounts:
- name: varlog
mountPath: /var/log

在 status: 的上面添加如下内容

volumes:
- name: varlog
emptyDir: {}
4应用更新
kubectl apply -f sidecar.yaml

提示 configured,表示配置成功

5检查

检查新 Pod 是否 Running

kubectl get pod | grep synergy-leverager

显示 2/2 Running

4、StorageClass ↑ 返回做题顺序

您必须连接到正确的主机。不这样做可能导致零分。

[student@k8s-master1] $ ssh cka000004

Task

首先，为名为 rancher.io/local-path 的现有制备器，创建一个名为 ran-local-path 的新 StorageClass

将卷绑定模式设置为 WaitForFirstConsumer

注意，没有设置卷绑定模式，或者将其设置为 WaitForFirstConsumer 之外的其他任何模式，都将导致分数降低。

接下来，将 ran-local-path StorageClass 配置为默认的 StorageClass

请勿修改任何现有的 Deployment 和 PersistentVolumeClaim，否则将导致分数降低。

参考链接

https://kubernetes.io/zh-cn/docs/concepts/storage/storage-classes/

1按照题目要求,在base 节点上执行,切换到题目要求节点

确保在 student@k8s-master1:~$下,再执行切换集群的命令 ssh cka000004

2创建 ran-local-path StorageClass
vim storage.yaml

添加如下内容

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
name: ran-local-path
annotations:

storageclass.kubernetes.io/is-default-class: "true"

provisioner: rancher.io/local-path
volumeBindingMode: WaitForFirstConsumer

实际考试时要创建的sc的名称叫local-path，但模拟环境已经有了同名的存在，所以换成ran-loca-path来创建

kubectl apply -f storage.yaml

提示 created,表示创建成功

！！！提醒，如果时间来得及，改默认StorageClass true的操作，可以分开做，因为按题目的要求来说是先创建再修改。

3验证 local-path 是否为默认的 StorageClass
kubectl get storageclass

ran-local-path 提示 default,表示对的

4别忘记,做完后,退回到base 节点,这样下一道题才能继续切节点。

6、Pod 优先级   PriorityClass ↑ 返回做题顺序

您必须连接到正确的主机。不这样做可能导致零分。

[student@k8s-master1] $ ssh cka000006

Task

请执行以下任务：

为用户工作负载创建一个名为 high-priority 的新 PriorityClass ，其值比用户定义的现有最高优先级类值小一。

修改在 priority namespace 中运行的现有 busybox-logger Deployment ，以使用 high-priority 优先级类。

确保 busybox-logger Deployment 在设置了新优先级类后成功部署。

请勿修改在 priority namespace 中运行的其他 Deployment，否则可能导致分数降低。

参考链接

https://kubernetes.io/zh-cn/docs/concepts/scheduling-eviction/pod-priority-preemption/

1按照题目要求,在base 节点上执行,切换到题目要求节点

确保在 student@k8s-master1:~$下,再执行切换集群的命令 ssh cka000006

2查找现有的用户自定义 PriorityClass
kubectl get pc

其中 system-cluster-critical 和 system-node-critical 是集群默认带的,而max-user-priority 是用户自定义的。其值为 1000000000(十位数),所以小一就是九个 9(999999999)

3创建新的PriorityClass
kubectl create pc high-priority --value=999999999

提示 created,表示创建成功。

4验证 PriorityClass 是否创建成功：
kubectl get pc
5在线修改 Deployment 的 priorityClassName
kubectl -n priority edit deployment busybox-logger

在 spec.template.spec 部分,或者说 dnsPolicy: ClusterFirst 上面,添加以下内容,并输入:wq 保存退出。

priorityClassName: high-priority

提示 edited,表示更新成功

6验证 Deployment 是否成功启动
kubectl -n priority get deployment busybox-logger

考试时,新 busybox-logger Pod 是大约需要 2 分钟,才能从 Pending 或者 Terminating 状态转换成 Running 状态。

所以马上新开命令行窗口，做下一题，这个窗口放着，有空回来看下确认就行。

7别忘记,做完后,退回到base 节点,这样下一道题才能继续切节点。

设置 cri-dockerd ：

安装 Debian 软件包 /home/student/cri-dockerd_0.3.6.3-0.ubuntu-jammy_amd64.deb Debian 软件包使用 dpkg 安装。

启用并启动 cri-docker 服务

配置以下系统参数:

net.bridge.bridge-nf-call-iptables 设置为 1

net.ipv6.conf.all.forwarding 设置为 1

net.ipv4.ip_forward 设置为 1

net.netfilter.nf_conntrack_max 设置为 131072

确保这些系统参数在系统重启后仍然存在，并应用于正在运行的系统。
