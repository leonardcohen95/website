    1. Web 框架选型

    Flask —— 轻量灵活

    定位：微框架，核心只提供路由和请求响应，其余靠扩展。
    优势：灵活、学习曲线平缓、适合微服务和小型项目。
    劣势：需要自己选型数据库、认证、表单，工程化靠团队自律。
    适用：API 网关、微服务、快速原型。

    Django —— 全家桶

    定位： batteries-included，内置 ORM、Admin、认证、表单、中间件。
    优势：ORM 强大、Admin 开箱即用、适合中大型后台系统。
    劣势：偏重、灵活度低、异步支持相对弱（3.0+ 有 ASGI）。
    适用：内容管理、企业内部系统、数据密集型后台。

    FastAPI —— 现代异步

    定位：基于 Starlette + Pydantic，原生 async/await。
    优势：性能高、自动生成 OpenAPI 文档、类型注解驱动、参数校验强。
    劣势：生态不如 Django 成熟、生产部署需 Uvicorn/Gunicorn。
    适用：高并发 API、AI 推理服务、微服务。

    FICC 投研系统选型建议

    券商 FICC 投研系统通常数据量大、接口多、与行情/风控系统耦合深。 推荐：核心交易/查询服务用 FastAPI（高并发、自动文档）， 后台管理用 Django（Admin + ORM 提效）， 轻量网关/聚合层用 Flask（灵活组合多个下游服务）。

    from flask import request, jsonify, Response

@app.route("/api/bonds", methods=["GET", "POST"])
def bonds():
    if request.method == "GET":

        return resp

    3. Django 实战

    3.1 MVT 架构

    Django 采用 MVT：Model（数据模型，ORM 映射数据库表）、 View（业务逻辑，接收请求返回响应）、 Template（模板，渲染 HTML）。 与传统 MVC 对应：M≈Model，V≈Controller，T≈View。

    3.2 ORM 基础

    # models.py
from django.db import models

class Bond(models.Model):
    code = models.CharField(max_length=20, unique=True)
    name = models.CharField(max_length=100)
    coupon_rate = models.FloatField()          # 票面利率
    maturity_date = models.DateField()
    issuer = models.CharField(max_length=100)

    def __str__(self):
        return f"{self.code} {self.name}"

# 查询操作
Bond.objects.all()                              # 查全部
Bond.objects.filter(issuer="财政部")            # 过滤
Bond.objects.exclude(coupon_rate__lt=3)         # 排除
Bond.objects.get(code="019547")                 # 查单个（不存在抛 DoesNotExist）
Bond.objects.order_by("-coupon_rate")           # 排序，- 表示降序

# annotate 聚合
from django.db.models import Avg
Bond.objects.values("issuer").annotate(avg_rate=Avg("coupon_rate"))
    select_related vs prefetch_related

    select_related：用 SQL JOIN 一次性查出外键/一对一关联对象，只支持 Forward 关系，减少查询次数但单条 SQL 更重。 prefetch_related：先查主表，再用 WHERE id IN (...) 单独查关联表，在内存中拼装，支持多对多和反向关系。 一对多用 prefetch，多对一/一对一对一用 select_related 更高效。

    3.3 CBV 与 FBV

    FBV（Function-Based View）用函数写视图，灵活直观； CBV（Class-Based View）用类继承 Django 内置 View（如 ListView、DetailView），复用性强但学习曲线高。 

    # FBV
from django.http import JsonResponse
def bond_list(request):
    bonds = Bond.objects.all()
    return JsonResponse({"data": list(bonds.values())})

# CBV
from django.views.generic import ListView
class BondListView(ListView):
    model = Bond
    template_name = "bonds/list.html"
    context_object_name = "bonds"

    3.4 Django REST Framework（DRF）

    DRF 是 Django 做 RESTful 的首选

    DRF 提供 Serializer（序列化/反序列化 + 校验）、ViewSet（把 CRUD 集中到一个类）、 Router（自动生成 URL）、分页、过滤、认证权限等，是 Django 生态做 RESTful API 的事实标准。 

    # serializers.py
from rest_framework import serializers
from .models import Bond

class BondSerializer(serializers.ModelSerializer):
    class Meta:
        model = Bond
        fields = "__all__"          # 全部字段

# views.py
from rest_framework import viewsets
from .models import Bond
from .serializers import BondSerializer

class BondViewSet(viewsets.ModelViewSet):
    queryset = Bond.objects.all()
    serializer_class = BondSerializer
    # 自动提供 list / retrieve / create / update / partial_update / destroy

# urls.py
from rest_framework.routers import DefaultRouter
from .views import BondViewSet

router = DefaultRouter()
router.register(r"bonds", BondViewSet)     # 自动生成 /bonds/ /bonds/{id}/ 等

urlpatterns = router.urls

    4. RESTful API 设计

    4.1 REST 六大原则

    • 客户端-服务器分离：前后端解耦，各自独立演进。
    • 无状态：服务端不保存客户端会话状态，每次请求自带全部信息。
    • 缓存：响应明确标注可缓存性，减少重复请求。
    • 统一接口：资源用 URI 标识，操作通过 HTTP 方法语义化。
    • 分层系统：客户端无需感知中间层（代理、网关、负载均衡）。
    • 按需代码（可选）：服务端可下发可执行代码扩展客户端功能。

    4.2 HTTP 方法与资源操作

    方法       语义              幂等  安全   典型用途
GET       查询资源           是    是     列表 / 详情
POST      创建资源           否    否     新建债券
PUT       全量更新资源       是    否     覆盖整条记录
PATCH     部分更新资源       否    否     只改部分字段
DELETE    删除资源           是    否     删除债券

    4.3 状态码规范

    200 OK          查询/更新成功
201 Created     资源创建成功（POST）
204 No Content  删除成功，无响应体
400 Bad Request 请求参数错误
401 Unauthorized 未登录/Token 无效
403 Forbidden   已登录但无权限
404 Not Found   资源不存在
409 Conflict    资源冲突（如重复创建）
500 Internal Server Error 服务端内部错误

    4.4 URL 命名规范

    资源用名词复数，不用动词；用 HTTP 方法表达操作； 版本号放在 URL 中：/api/v1/bonds。 

    # 好的设计
GET    /api/v1/bonds              # 债券列表
GET    /api/v1/bonds/019547       # 债券详情
POST   /api/v1/bonds              # 创建债券
PUT    /api/v1/bonds/019547       # 全量更新
PATCH  /api/v1/bonds/019547       # 部分更新
DELETE /api/v1/bonds/019547       # 删除
GET    /api/v1/bonds?issuer=财政部&page=1&size=20   # 过滤+分页

# 反模式（避免）
GET  /api/getBonds               # 动词入 URL
POST /api/deleteBond/019547      # 用 POST 表删除
GET  /api/v1/bond/019547         # 单数名词
GET  /api/bondsAll               # 驼峰、无版本
    RESTful 设计反模式

    ①把动词放进 URL（/getBond、/createUser）。②用 GET 做修改/删除操作（不安全）。 ③返回 200 但 body 里写 "code": 500（状态码语义失效）。④过度嵌套 /users/1/orders/2/items/3（最多两层）。 ⑤不做版本化，改动直接破坏老客户端。

    5. 认证与授权

    5.1 Session / Cookie 认证

    传统方式：用户登录后服务端生成 session 存在服务器，返回 session_id 写入 Cookie， 后续请求浏览器自动带 Cookie。缺点：服务端有状态、跨域麻烦、水平扩展需 session 共享（Redis）。

    5.2 JWT 认证

    JWT（JSON Web Token）是无状态认证：服务端签发 token，客户端存储并每次在 Authorization: Bearer <token> 头携带。服务端只验签不存会话，易水平扩展。

    JWT 不加密，敏感信息不要放 payload

    JWT 由 header.payload.signature 三段组成，payload 只是 base64 编码， 任何人都能解码看到内容。绝不要把密码、身份证号等敏感信息放 payload。 signature 只防篡改，不加密。要加密需用 JWE。 

    import jwt
import datetime

SECRET = "ficc-secret-key"        # 生产用环境变量，强随机

# 签发 token
def create_token(user_id: int, username: str) -> str:
    payload = {
        "user_id": user_id,
        "username": username,
        "exp": datetime.datetime.utcnow() + datetime.timedelta(hours=2),  # 过期时间
        "iat": datetime.datetime.utcnow(),                                   # 签发时间
    }
    return jwt.encode(payload, SECRET, algorithm="HS256")

# 验证 token
def verify_token(token: str) -> dict:
    try:
        payload = jwt.decode(token, SECRET, algorithms=["HS256"])
        return payload
    except jwt.ExpiredSignatureError:
        raise Exception("token 已过期")
    except jwt.InvalidTokenError:
        raise Exception("token 无效")

# 使用
token = create_token(1, "trader01")
print(token)
data = verify_token(token)
print(data["username"])     # trader01

# 刷新 token 机制：签发一个长有效期 refresh_token，用于换新 access_token
# access_token 有效期短（2h），refresh_token 长（7d），降低泄漏风险

    5.3 OAuth 2.0 简述

    OAuth 2.0 是授权框架（不是认证），让第三方应用在用户授权下访问其资源， 而无需暴露用户密码。核心角色：Resource Owner（用户）、Client（第三方应用）、 Authorization Server（授权服务器）、Resource Server（资源服务器）。 常用授权码模式（Authorization Code）用于 Web 应用，简化模式用于前端。

    # auth_api.py —— 登录签发 JWT
from flask_restx import Namespace, Resource, fields
import jwt, datetime

auth_ns = Namespace("auth", description="认证接口")

login_model = auth_ns.model("Login", {
    "username": fields.String(required=True),
    "password": fields.String(required=True),
})

@auth_ns.route("/login")
class Login(Resource):
    @auth_ns.expect(login_model)
    def post(self):
        """用户登录，返回 JWT"""
        data = auth_ns.payload
        # 简化：实际应查数据库校验密码
        if data["username"] == "trader" and data["password"] == "123456":
            token = jwt.encode(
                {"user_id": 1, "username": data["username"],
                 "exp": datetime.datetime.utcnow() + datetime.timedelta(hours=2)},
                "ficc-secret", algorithm="HS256",
            )
            return {"token": token}, 200
        return {"error": "用户名或密码错误"}, 401
    # bonds_api.py —— 债券 CRUD（带 JWT 鉴权）
from flask import request
from flask_restx import Namespace, Resource, fields
from functools import wraps
import jwt

bonds_ns = Namespace("bonds", description="债券接口")

bond_model = bonds_ns.model("Bond", {
    "code": fields.String(required=True),
    "name": fields.String(required=True),
    "coupon_rate": fields.Float(),
})

# 内存模拟数据库
BONDS = {"019547": {"code": "019547", "name": "21国债11", "coupon_rate": 2.95}}

# JWT 鉴权装饰器
def token_required(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        auth = request.headers.get("Authorization", "")
        if not auth.startswith("Bearer "):
            return {"error": "缺少 Token"}, 401
        token = auth.split(" ", 1)[1]
        try:
            jwt.decode(token, "ficc-secret", algorithms=["HS256"])
        except jwt.InvalidTokenError:
            return {"error": "Token 无效"}, 401
        return f(*args, **kwargs)
    return wrapper

@bonds_ns.route("/")
class BondList(Resource):
    @bonds_ns.doc(security="Bearer")
    @token_required
    def get(self):
        """获取债券列表"""
        return {"data": list(BONDS.values())}

    @bonds_ns.expect(bond_model)
    @token_required
    def post(self):
        """创建债券"""
        bond = bonds_ns.payload
        BONDS[bond["code"]] = bond
        return bond, 201

@bonds_ns.route("/<string:code>")
class BondDetail(Resource):
    @token_required
    def get(self, code):
        """获取债券详情"""
        return BONDS.get(code, ({"error": "债券不存在"}, 404))

    @token_required
    def delete(self, code):
        """删除债券"""
        BONDS.pop(code, None)
        return "", 204
    这个项目如何对应实际工作场景

    券商 FICC 投研系统中，交易员/研究员需要查询债券基本信息、行情、持仓等。 该实战项目对应债券主数据查询接口：蓝图按业务拆分（auth/bonds）， JWT 保证只有登录用户能访问，Swagger 文档供前端联调，错误处理统一 JSON 返回。 生产中把 BONDS 内存字典换成数据库（SQLAlchemy），加缓存（Redis 热点债券）、 限流、审计日志，就是一个可上线的微服务。

    8. 面试高频题

    Q1：Flask 和 Django 的区别？

    参考答案要点

    ①Flask 是微框架，核心精简，靠扩展（Flask-SQLAlchemy、Flask-Login 等）组合，灵活但需自行选型。 ②Django 是全家桶，内置 ORM、Admin、Auth、Form、中间件，开箱即用但重、约定强。 ③Flask 适合微服务、API 网关、快速原型；Django 适合中大型后台、内容管理、企业系统。 ④性能：裸 Flask 略快，但生产差异主要在数据库和缓存。

    Q2：RESTful 设计原则？

    参考答案要点

    ①资源用 URI 标识，名词复数，不用动词。②用 HTTP 方法（GET/POST/PUT/PATCH/DELETE）表达操作语义。 ③无状态，请求自带全部信息。④状态码语义正确（201 创建、204 删除、4xx 客户端、5xx 服务端）。 ⑤URL 版本化 /api/v1/。⑥支持过滤、分页、排序（查询参数）。⑦响应统一 JSON 格式。

    Q3：JWT 和 Session 的区别？

    参考答案要点

    ①Session 有状态，会话存服务端，客户端只存 session_id；JWT 无状态，token 自带用户信息，服务端只验签。 ②JWT 易水平扩展（无 session 共享），适合分布式/微服务；Session 需共享存储（Redis）才能多实例。 ③JWT 无法主动失效（除非黑名单），注销要等过期；Session 服务端可直接删除。 ④JWT payload 不加密，不能放敏感信息；Session 数据在服务端更安全。

    Q4：select_related 和 prefetch_related 的区别？

    参考答案要点

    ①select_related 用 SQL JOIN 一次查出，只支持外键/一对一的 Forward 关系，查询次数少但单 SQL 重。 ②prefetch_related 先发主查询再发 IN 查询，内存中拼装，支持多对多和反向关系，查询次数固定 2 次。 ③一对多、多对多用 prefetch_related；多对一、一对一对一用 select_related 更高效。 ④两者都是为了解决 N+1 查询问题。

    Q5：蓝图（Blueprint）的作用？

    参考答案要点

    ①把大型 Flask 应用按业务模块拆分，每个蓝图有独立路由、静态文件、模板、错误处理。 ②可指定 url_prefix 命名空间，避免路由冲突。③蓝图可被多次注册到不同应用，提升复用。 ④本质是应用的「子集」，注册到 app 后才生效，便于团队并行开发和代码组织。

    本章小结

    • Flask 轻量灵活适合微服务，Django 全家桶适合中大型后台，FastAPI 异步高性能适合高并发 API。
    • Flask 路由支持变量转换器，request 取请求，Blueprint 按业务拆分模块，before/after_request 做钩子。
    • Django MVT 中 Model 用 ORM 映射表，filter/exclude/annotate 完成查询，CBV 复用性强、FBV 灵活。
    • DRF 用 Serializer 做序列化校验，ViewSet 集中 CRUD，Router 自动生成 URL，是 Django 做 RESTful 首选。
    • RESTful 核心：名词复数 URI + HTTP 方法语义 + 正确状态码 + 版本化 + 无状态 + 统一 JSON。
    • JWT 无状态易扩展但不加密、无法主动失效；Session 有状态更安全但需共享存储。
    • 接口文档用 Flask-RESTX / drf-spectacular 自动生成 Swagger，保证代码与文档一致。
    • 实战项目整合蓝图 + JWT + RESTX + 错误处理，对应 FICC 债券主数据查询的真实工作场景。
