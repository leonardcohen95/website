    第 4 章 核心能力 约 20 分钟

    给 Agent 加记忆

    上一章的 ask_llm 只能一问一答，模型记不住上一轮说了什么。 这一章我们给 Agent 加上「记忆」，让它能进行连贯的多轮对话。

    学习目标

    • 理解上下文窗口的含义
    • 用消息列表实现对话记忆
    • 写出一个能多轮对话的 Agent
    • 了解记忆的分类（短期/长期）

    1. 为什么需要记忆

    大模型本身是「无状态」的——它不会记得上次对话的内容。每次调用 API， 都是一次全新的请求。所以如果我们想让模型记住之前聊了什么， 就必须把历史对话一并发给它。

    类比理解

    把大模型想象成一个「每次见面都失忆的人」。你想让它理解上下文， 就得每次见面都把之前的聊天记录念给它听。这个「聊天记录」就是记忆。

    2. 用消息列表实现记忆

    原理很简单：维护一个 messages 列表，每轮对话都把用户问题和模型回答追加进去， 下次调用时把整个列表发给模型。 

    import os
from dotenv import load_dotenv
import dashscope

load_dotenv()
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")


class Agent:
    def __init__(self, system_prompt="你是一个乐于助人的助手。"):
        self.messages = [{"role": "system", "content": system_prompt}]

    def chat(self, user_input: str) -> str:
        # 1. 把用户输入加入记忆
        self.messages.append({"role": "user", "content": user_input})

        # 2. 调用模型（传入完整历史）
        response = dashscope.Generation.call(
            model="qwen-turbo",
            messages=self.messages,
            result_format="message",
        )
        answer = response.output.choices[0].message.content

        # 3. 把模型回答也加入记忆
        self.messages.append({"role": "assistant", "content": answer})
        return answer


if __name__ == "__main__":
    agent = Agent()
    print(agent.chat("我叫小明，今年 10 岁。"))
    print(agent.chat("我叫什么名字？"))  # 模型会回答「小明」

    运行试试，第二个问题模型能答出「小明」，说明记忆生效了！

    3. 对话流程图

    第一轮：
  messages = [system, user("我叫小明")]
  → 模型回答 → messages = [system, user, assistant]

第二轮：
  messages = [system, user, assistant, user("我叫什么")]
  → 模型根据历史回答「小明」

    4. 记忆的分类

    短期记忆（上下文窗口）

    就是上面代码里的 messages 列表。它存在于一次会话中， 关掉程序就没了。受限于模型的上下文窗口大小（如 8K、32K token）。

    长期记忆（持久化存储）

    把重要信息存到数据库或文件中，下次启动程序还能读取。 比如记住用户的姓名、偏好等。常见方案：SQLite、向量数据库。

    5. 实现长期记忆

    我们用一个 JSON 文件来保存用户信息，实现简单的长期记忆。 创建 memory.json： 

    import os
import json
from dotenv import load_dotenv
import dashscope

load_dotenv()
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")

MEMORY_FILE = "memory.json"


def load_memory() -> dict:
    if os.path.exists(MEMORY_FILE):
        with open(MEMORY_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    return {}


def save_memory(data: dict):
    with open(MEMORY_FILE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)


class Agent:
    def __init__(self):
        self.messages = [{"role": "system", "content": "你是一个乐于助人的助手。"}]
        self.long_term = load_memory()

    def chat(self, user_input: str) -> str:
        # 把长期记忆拼接到 system 提示中
        if self.long_term:
            context = "已知用户信息：" + json.dumps(self.long_term, ensure_ascii=False)
            self.messages[0]["content"] = "你是一个乐于助人的助手。" + context

        self.messages.append({"role": "user", "content": user_input})
        response = dashscope.Generation.call(
            model="qwen-turbo", messages=self.messages, result_format="message"
        )
        answer = response.output.choices[0].message.content
        self.messages.append({"role": "assistant", "content": answer})

        # 如果用户提到了姓名，保存到长期记忆
        if "我叫" in user_input:
            name = user_input.split("我叫")[-1].strip("。.！!")
            self.long_term["name"] = name
            save_memory(self.long_term)

        return answer
    进阶方向

    真实项目中，长期记忆常用向量数据库（如 Chroma、FAISS）来存储。 它能把文字转成向量，通过相似度检索找到相关的历史信息，而不是把所有记录都塞给模型。 感兴趣的同学可以课后研究。

    6. 上下文窗口溢出怎么办

    对话越来越长，messages 会超出模型的上下文窗口限制。 常见处理方式：

    • 截断：只保留最近 N 轮对话，丢掉最早的
    • 摘要：让模型把历史对话总结成一段话，替换原始记录
    • 检索：用向量数据库只取回相关的历史记录

    本章小结

    • 大模型是无状态的，记忆需要我们自己维护 messages 列表
    • 短期记忆 = 内存中的消息列表，关闭程序即丢失
    • 长期记忆 = 持久化存储（文件/数据库），重启后仍在
    • 对话过长时需要截断、摘要或检索来避免溢出上下文窗口
