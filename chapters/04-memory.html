    给 Agent 加记忆

    上一章的 ask_llm 只能一问一答，模型记不住上一轮说了什么。 这一章我们给 Agent 加上「记忆」，让它能进行连贯的多轮对话。

    学习目标

    • 理解上下文窗口的含义
    • 用消息列表实现对话记忆
    • 写出一个能多轮对话的 Agent
    • 了解记忆的分类（短期/长期）

    1. 为什么需要记忆

    大模型本身是「无状态」的——它不会记得上次对话的内容。每次调用 API， 都是一次全新的请求。所以如果我们想让模型记住之前聊了什么， 就必须把历史对话一并发给它。

    类比理解

    把大模型想象成一个「每次见面都失忆的人」。你想让它理解上下文， 就得每次见面都把之前的聊天记录念给它听。这个「聊天记录」就是记忆。

    2. 用消息列表实现记忆

    原理很简单：维护一个 messages 列表，每轮对话都把用户问题和模型回答追加进去， 下次调用时把整个列表发给模型。 

    import os                          # 导入 os 模块
from dotenv import load_dotenv     # 导入读取 .env 的函数
import dashscope                   # 导入通义千问 SDK

load_dotenv()                      # 加载 .env 文件
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")  # 设置 API Key


class Agent:  # 定义一个 Agent 类，相当于一张"空白表格模板"
    # __init__ 是"出厂设置"函数：每次用这张模板复印一张新表格时，自动执行一次
    # 前面和后面的双下划线 __ 是 Python 规定的特殊写法，表示这是内置方法
    def __init__(self, system_prompt="你是一个乐于助人的助手。"):
        # self = "这张新复印出来的表格自己"（也就是刚创建的这个 Agent）
        # self.messages = 在这张表格的"记忆"栏里填上内容
        # 这里给新 Agent 装一个记忆列表，初始放入一条 system 消息
        self.messages = [{"role": "system", "content": system_prompt}]

    # chat 方法：接收用户输入，返回模型回答
    # 注意第一个参数必须是 self，Python 会自动把"调用者"传进来
    def chat(self, user_input: str) -> str:
        # self.messages.append 意思是"往我自己的记忆列表里加一条"
        # 1. 把用户输入加入记忆（messages 列表末尾追加一条 user 消息）
        self.messages.append({"role": "user", "content": user_input})

        # 2. 调用模型，传入完整的历史消息列表（self.messages）
        response = dashscope.Generation.call(
            model="qwen-turbo",
            messages=self.messages,
            result_format="message",
        )
        answer = response.output.choices[0].message.content  # 取出回答

        # 3. 把模型回答也加入我自己的记忆，这样下一轮对话模型能看到自己说过的话
        self.messages.append({"role": "assistant", "content": answer})
        return answer


if __name__ == "__main__":
    agent = Agent()  # 用 Agent 模板复印一张新表格（创建一个实例），此时 __init__ 自动运行
    print(agent.chat("我叫小明，今年 10 岁。"))  # 第一轮对话
    print(agent.chat("我叫什么名字？"))  # 第二轮，模型能记得上一轮的「小明」

    运行试试，第二个问题模型能答出「小明」，说明记忆生效了！

    3. 对话流程图

    第一轮：
  messages = [system, user("我叫小明")]
  → 模型回答 → messages = [system, user, assistant]

第二轮：
  messages = [system, user, assistant, user("我叫什么")]
  → 模型根据历史回答「小明」

    4. 记忆的分类

    短期记忆（上下文窗口）

    就是上面代码里的 messages 列表。它存在于一次会话中， 关掉程序就没了。受限于模型的上下文窗口大小（如 8K、32K token）。

    长期记忆（持久化存储）

    把重要信息存到数据库或文件中，下次启动程序还能读取。 比如记住用户的姓名、偏好等。常见方案：SQLite、向量数据库。

    5. 实现长期记忆

    我们用一个 JSON 文件来保存用户信息，实现简单的长期记忆。 创建 memory.json： 

    import os                          # os 模块：处理文件路径、判断文件是否存在
import json                        # json 模块：读写 JSON 格式的数据
from dotenv import load_dotenv     # 读取 .env 文件
import dashscope                   # 通义千问 SDK

load_dotenv()                      # 加载 .env
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")  # 设置 API Key

MEMORY_FILE = "memory.json"  # 定义长期记忆存储的文件名（常量，全大写）


def load_memory() -> dict:  # 读取长期记忆，返回一个字典
    if os.path.exists(MEMORY_FILE):  # 判断文件是否存在
        with open(MEMORY_FILE, "r", encoding="utf-8") as f:  # 以只读方式打开文件
            return json.load(f)  # 把 JSON 内容读成 Python 字典
    return {}  # 文件不存在就返回空字典


def save_memory(data: dict):  # 把字典保存到文件
    with open(MEMORY_FILE, "w", encoding="utf-8") as f:  # 以写入方式打开（会覆盖原有内容）
        json.dump(data, f, ensure_ascii=False, indent=2)  # 写入 JSON，ensure_ascii=False 保证中文不转义，indent=2 缩进美化


class Agent:
    def __init__(self):  # 出厂设置：每复印一张新表格时自动运行
        # 装短期记忆：在这张表格的"记忆"栏填上消息列表，初始放一条 system 消息
        self.messages = [{"role": "system", "content": "你是一个乐于助人的助手。"}]
        # 装长期记忆：从 memory.json 文件读取之前保存的信息（相当于读取存档）
        self.long_term = load_memory()

    def chat(self, user_input: str) -> str:  # self = 调用这个方法的那个 Agent 自己
        # 把长期记忆拼接到 system 提示中，让模型知道用户的背景信息
        if self.long_term:  # 如果我自己的长期记忆不为空
            context = "已知用户信息：" + json.dumps(self.long_term, ensure_ascii=False)  # 把字典转成字符串
            self.messages[0]["content"] = "你是一个乐于助人的助手。" + context  # 更新我自己的 system 消息

        self.messages.append({"role": "user", "content": user_input})  # 往我自己的记忆里加用户输入
        response = dashscope.Generation.call(
            model="qwen-turbo", messages=self.messages, result_format="message"
        )
        answer = response.output.choices[0].message.content
        self.messages.append({"role": "assistant", "content": answer})  # 往我自己的记忆里加模型回答

        # 如果用户提到了姓名，提取并保存到我自己的长期记忆
        if "我叫" in user_input:  # 判断字符串中是否包含"我叫"
            # split("我叫")[-1] 取"我叫"后面的部分，strip 去掉句末标点
            name = user_input.split("我叫")[-1].strip("。.！!")
            self.long_term["name"] = name  # 存入我自己的长期记忆字典
            save_memory(self.long_term)  # 写入文件，持久化保存

        return answer
    进阶方向

    真实项目中，长期记忆常用向量数据库（如 Chroma、FAISS）来存储。 它能把文字转成向量，通过相似度检索找到相关的历史信息，而不是把所有记录都塞给模型。 感兴趣的同学可以课后研究。

    6. 上下文窗口溢出怎么办

    对话越来越长，messages 会超出模型的上下文窗口限制。 常见处理方式：

    • 截断：只保留最近 N 轮对话，丢掉最早的
    • 摘要：让模型把历史对话总结成一段话，替换原始记录
    • 检索：用向量数据库只取回相关的历史记录

    本章小结

    • 大模型是无状态的，记忆需要我们自己维护 messages 列表
    • 短期记忆 = 内存中的消息列表，关闭程序即丢失
    • 长期记忆 = 持久化存储（文件/数据库），重启后仍在
    • 对话过长时需要截断、摘要或检索来避免溢出上下文窗口
