    并发编程实战

    岗位要求掌握多线程、多进程、AsyncIO，并能根据场景合理选型。 本章从并发与并行的概念讲起，深入剖析 GIL 对 Python 多线程的影响， 然后分别讲解多线程 threading、多进程 multiprocessing、AsyncIO 异步编程的核心用法， 最后给出技术选型决策表和异步 Web 框架简介，让你面试时能清晰回答「什么场景用什么」。

    学习目标

    • 理解并发与并行的区别，能区分 CPU 密集型与 IO 密集型任务
    • 理解 GIL 的原理及其对多线程的影响
    • 掌握 threading 多线程与线程池的使用，能处理线程安全问题
    • 掌握 multiprocessing 多进程与进程池，了解进程间通信
    • 掌握 AsyncIO 异步编程，能编写高并发 IO 异步代码
    • 能根据任务类型选择合适的并发方案（线程/进程/协程）

    1. 并发 vs 并行

    并发（Concurrency）vs 并行（Parallelism）

    并发：多个任务在同一时间段内交替执行（宏观上同时，微观上交替）， 比如单核 CPU 通过时间片轮转处理多个任务。
    并行：多个任务在同一时刻真正同时执行，需要多核 CPU。
    一句话：并发是「一个人同时吃三个汉堡」（轮流咬），并行是「三个人各吃一个汉堡」。 

    并发（单核，交替执行）：
  任务A: ████    ████    ████
  任务B:     ████    ████    ████
  时间 ─────────────────────────▶

并行（多核，真正同时）：
  CPU1: ████████████████ 任务A
  CPU2: ████████████████ 任务B
  时间 ─────────────────────────▶

    1.1 CPU 密集型 vs IO 密集型

    这是技术选型的关键依据：

    • CPU 密集型：大量计算，CPU 一直跑满。例如数据加密压缩、图像处理、机器学习训练、复杂数学运算。瓶颈在 CPU。
    • IO 密集型：大量等待 IO（网络请求、磁盘读写、数据库查询），CPU 大部分时间在等。例如爬虫、Web 请求、文件读写。瓶颈在 IO 等待。
    选型第一原则

    CPU 密集型 → 用多进程（绕过 GIL，利用多核）。
    IO 密集型 → 用多线程或AsyncIO（IO 等待时释放 GIL，高并发）。

    2. GIL 全局解释器锁

    2.1 什么是 GIL

    GIL（Global Interpreter Lock）是 CPython 解释器中特有的一把互斥锁， 保证同一时刻只有一个线程在执行 Python 字节码。 这是 CPython 的历史设计决策，主要是为了简化内存管理（引用计数的线程安全）。

    2.2 GIL 对多线程的影响

    • CPU 密集型：多线程不仅不会提速，反而更慢。因为线程频繁切换 + GIL 竞争开销。
    • IO 密集型：多线程有效。因为 IO 操作（如 socket recv）会释放 GIL，其他线程可以执行。
    # 验证：CPU 密集型多线程反而慢
import threading, time

def cpu_bound():
    # 纯计算，占满 CPU
    total = 0
    for i in range(10_000_000):
        total += i * i
    return total

# 单线程
start = time.time()
cpu_bound()
cpu_bound()
print("单线程耗时:", time.time() - start)  # 约 1.2s

# 多线程（GIL 导致变慢！）
start = time.time()
t1 = threading.Thread(target=cpu_bound)
t2 = threading.Thread(target=cpu_bound)
t1.start(); t2.start()
t1.join(); t2.join()
print("多线程耗时:", time.time() - start)  # 约 1.5s，比单线程还慢！
    为什么有了 GIL 还要考虑线程安全？

    GIL 只保证单条字节码指令的原子性，但很多操作不是单条指令。 例如 count += 1 实际是三步：加载 count、加 1、存回。 线程可能在这三步之间被切换，导致竞态条件。所以共享变量仍需加锁。 另外，IO 操作期间 GIL 会被释放，此时多个线程确实可能同时操作共享资源。

    3. 多线程 threading

    3.1 Thread 创建与启动

    import threading
import time

def fetch_url(url):
    """模拟一个 IO 密集型任务（网络请求）"""
    print(f"开始请求 {url}")
    time.sleep(2)  # 模拟网络延迟，sleep 时释放 GIL
    print(f"请求完成 {url}")

# 方式一：直接传函数
t1 = threading.Thread(target=fetch_url, args=("https://example.com",))
t2 = threading.Thread(target=fetch_url, args=("https://example.org",))
t1.start()  # 启动线程
t2.start()
t1.join()   # 等待线程结束
t2.join()
print("全部完成")

# 方式二：继承 Thread 类
class MyThread(threading.Thread):
    def __init__(self, url):
        super().__init__()
        self.url = url

    def run(self):  # 线程入口
        fetch_url(self.url)

t = MyThread("https://example.com")
t.start()
t.join()

    3.2 线程池 ThreadPoolExecutor

    手动创建线程开销大，用线程池复用线程。concurrent.futures 提供了统一接口。

    from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def fetch(url):
    time.sleep(1)  # 模拟 IO
    return f"结果: {url}"

urls = [f"https://api.example.com/item/{i}" for i in range(20)]

# 方式一：map 批量提交，结果按提交顺序返回
with ThreadPoolExecutor(max_workers=10) as executor:
    results = executor.map(fetch, urls)
    for r in results:
        print(r)

# 方式二：submit 逐个提交，as_completed 按完成顺序返回
with ThreadPoolExecutor(max_workers=10) as executor:
    futures = {executor.submit(fetch, url): url for url in urls}
    for future in as_completed(futures):
        url = futures[future]
        try:
            result = future.result(timeout=5)  # 获取结果，可设超时
            print(f"{url} -> {result}")
        except Exception as e:
            print(f"{url} 出错: {e}")

    3.3 线程同步

    多线程访问共享资源时需要同步机制，避免竞态条件。

    Lock（互斥锁）

    最基础的锁，同一时刻只允许一个线程进入临界区。acquire() 获取，release() 释放。 推荐用 with lock: 上下文管理器自动释放。

    RLock（可重入锁）

    同一个线程可以多次获取而不被自己阻塞（Lock 会死锁）。适合同一把锁在嵌套函数中多次获取。

    Condition（条件变量）

    基于 Lock，支持 wait() / notify() / notify_all()， 实现生产者-消费者模式：线程等待某个条件满足后再继续。

    Semaphore（信号量）

    控制最多 N 个线程同时访问资源。例如限制数据库连接池最大并发数。 Semaphore(5) 表示最多 5 个线程同时进入。

    3.4 线程安全问题

    多线程下不加锁的后果

    多个线程同时修改共享变量会导致数据错误。下面的例子不加锁，最终 count 远小于 2,000,000。 因为 count += 1 不是原子操作，线程切换会丢失更新。 

    import threading

count = 0
lock = threading.Lock()

def add_without_lock():
    global count
    for _ in range(100_000):
        count += 1  # 非原子操作，竞态条件

def add_with_lock():
    global count
    for _ in range(100_000):
        with lock:  # 加锁保证原子性
            count += 1

# 不加锁的结果（错误）
threads = [threading.Thread(target=add_without_lock) for _ in range(20)]
for t in threads: t.start()
for t in threads: t.join()
print("不加锁 count =", count)  # 远小于 2,000,000！

# 加锁的结果（正确）
count = 0
threads = [threading.Thread(target=add_with_lock) for _ in range(20)]
for t in threads: t.start()
for t in threads: t.join()
print("加锁 count =", count)  # 正好 2,000,000

    3.5 典型场景：IO 密集型爬虫

    import requests
from concurrent.futures import ThreadPoolExecutor

def crawl(url):
    """爬取单个页面（IO 密集型，适合多线程）"""
    resp = requests.get(url, timeout=10)
    return resp.status_code

urls = [f"https://example.com/page/{i}" for i in range(100)]

# 10 个线程并发爬取，比串行快 10 倍
with ThreadPoolExecutor(max_workers=10) as executor:
    results = list(executor.map(crawl, urls))

print(f"完成 {len(results)} 个页面")

    4. 多进程 multiprocessing

    4.1 Process 创建

    import multiprocessing
import time

def cpu_bound_task(n):
    """CPU 密集型计算"""
    total = 0
    for i in range(n):
        total += i * i
    return total

if __name__ == "__main__":
    # 单进程
    start = time.time()
    cpu_bound_task(10_000_000)
    cpu_bound_task(10_000_000)
    print("单进程耗时:", time.time() - start)  # 约 1.2s

    # 多进程（利用多核，绕过 GIL）
    start = time.time()
    p1 = multiprocessing.Process(target=cpu_bound_task, args=(10_000_000,))
    p2 = multiprocessing.Process(target=cpu_bound_task, args=(10_000_000,))
    p1.start(); p2.start()
    p1.join(); p2.join()
    print("多进程耗时:", time.time() - start)  # 约 0.6s，接近 2 倍加速！
    多进程能绕过 GIL

    每个进程有独立的 Python 解释器和独立的 GIL，所以多进程可以真正利用多核 CPU 并行执行。 这是 Python 处理 CPU 密集型任务的首选方案。但进程间通信开销大，数据需要序列化传递。

    4.2 进程池 Pool

    from multiprocessing import Pool
import time

def square(x):
    return x * x

if __name__ == "__main__":
    # 方式一：Pool
    with Pool(processes=4) as pool:
        # map 类似内置 map，但并行执行
        results = pool.map(square, range(10))
        print(results)  # [0, 1, 4, 9, ...]

        # apply_async 异步提交
        future = pool.apply_async(square, (100,))
        print(future.get(timeout=5))  # 10000

    # 方式二：ProcessPoolExecutor（与线程池接口一致）
    from concurrent.futures import ProcessPoolExecutor
    with ProcessPoolExecutor(max_workers=4) as executor:
        results = list(executor.map(square, range(10)))
        print(results)

    4.3 进程间通信

    进程间内存不共享，需要通过特殊机制通信：

    from multiprocessing import Process, Queue, Pipe

# ===== 方式一：Queue（线程和进程安全）=====
def producer(q):
    for i in range(5):
        q.put(f"消息 {i}")
    q.put(None)  # 结束标记

def consumer(q):
    while True:
        msg = q.get()
        if msg is None:
            break
        print("收到:", msg)

if __name__ == "__main__":
    q = Queue()
    p1 = Process(target=producer, args=(q,))
    p2 = Process(target=consumer, args=(q,))
    p1.start(); p2.start()
    p1.join(); p2.join()

# ===== 方式二：Pipe（双向管道，一对一）=====
def sender(conn):
    conn.send("你好，子进程！")
    conn.close()

if __name__ == "__main__":
    parent_conn, child_conn = Pipe()
    p = Process(target=sender, args=(child_conn,))
    p.start()
    print("父进程收到:", parent_conn.recv())
    p.join()

    5. AsyncIO 异步编程

    5.1 核心概念

    • 事件循环（Event Loop）：AsyncIO 的核心，循环调度协程执行，单线程驱动。
    • 协程（Coroutine）：用 async def 定义的函数，调用返回协程对象，需通过事件循环执行。
    • await：挂起当前协程，让出控制权给事件循环，等 IO 完成后恢复。
    • Task：对协程的封装，可并发调度。

    5.2 异步 HTTP 请求（aiohttp）

    import asyncio
import aiohttp
import time

async def fetch(session, url):
    """异步请求单个 URL"""
    async with session.get(url) as resp:
        return resp.status

async def main():
    urls = [f"https://example.com/page/{i}" for i in range(100)]
    async with aiohttp.ClientSession() as session:
        # 创建 100 个任务并发执行
        tasks = [fetch(session, url) for url in urls]
        results = await asyncio.gather(*tasks)  # 等所有任务完成
    print(f"完成 {len(results)} 个请求")

if __name__ == "__main__":
    start = time.time()
    asyncio.run(main())  # 启动事件循环
    print(f"耗时: {time.time() - start:.2f}s")
    # 100 个请求可能只需 1~2 秒，远超多线程！

    5.3 asyncio.gather / asyncio.wait

    import asyncio

async def task(name, seconds):
    await asyncio.sleep(seconds)
    return f"{name} 完成"

async def main():
    # gather: 并发执行所有协程，结果按参数顺序返回
    results = await asyncio.gather(
        task("A", 2),
        task("B", 1),
        task("C", 3),
    )
    print(results)  # ['A 完成', 'B 完成', 'C 完成']，顺序固定

    # wait: 返回 (done, pending) 集合，可设置 return_when
    tasks = [asyncio.create_task(task(name, s)) for name, s in [("A", 2), ("B", 1), ("C", 3)]]
    done, pending = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)
    for t in done:
        print("最先完成:", t.result())  # B 完成（1秒）

asyncio.run(main())

    5.4 同步代码转异步

    有些库（如 requests、pymysql）不支持异步，不能直接 await。用 run_in_executor 把同步函数丢到线程池里执行：

    import asyncio
import requests

def fetch_sync(url):
    """同步阻塞函数"""
    return requests.get(url).status_code

async def main():
    loop = asyncio.get_running_loop()
    urls = [f"https://example.com/page/{i}" for i in range(20)]

    # 把同步函数丢到默认线程池执行
    tasks = [
        loop.run_in_executor(None, fetch_sync, url)
        for url in urls
    ]
    results = await asyncio.gather(*tasks)
    print(f"完成 {len(results)} 个请求")

asyncio.run(main())
    AsyncIO 适合高并发 IO 场景

    AsyncIO 是单线程的，通过事件循环在 IO 等待时切换协程， 一个线程就能处理成千上万的并发连接（如 Web 服务器、爬虫、聊天服务器）。 但它不适合 CPU 密集型（会阻塞事件循环）， CPU 密集型任务应该用多进程，或用 run_in_executor 丢到进程池。

    6. 技术选型决策

    选型决策表（面试必背）
    任务类型              首选方案          原因
─────────────────────────────────────────────────────
CPU 密集型            多进程            绕过 GIL，利用多核
IO 密集型（高并发）    AsyncIO          单线程万级并发，开销最小
IO 密集型（简单）      多线程           写法简单，代码同步风格
IO + CPU 混合         多进程 + 多线程/  进程处理 CPU，线程处理 IO
                      AsyncIO

    面试核心：先判断任务类型（CPU 还是 IO 密集），再选方案。 CPU 密集选多进程，IO 密集高并发选 AsyncIO，简单 IO 选多线程。

    7. 异步 Web 框架

    FastAPI

    基于 Starlette + Pydantic 的现代异步 Web 框架。特点：原生 async/await 支持、 自动生成 OpenAPI 文档、类型提示自动校验、性能接近 Node.js 和 Go。 为什么快：底层用 Uvicorn（ASGI 服务器），单线程事件循环处理高并发 IO。

    aiohttp

    既是异步 HTTP 客户端也是服务端框架。特点：轻量、灵活，适合需要同时做异步客户端和服务端的场景。

    Sanic

    Python 3.5+ 异步 Web 框架，类似 Flask 但支持 async。特点：速度快、支持 ASGI。

    为什么 FastAPI 性能好？

    ① 基于 ASGI（异步服务器网关接口），原生支持 async/await，IO 不阻塞。
    ② 用 Uvicorn / Hypercorn 这种高性能异步服务器驱动。
    ③ Pydantic 用 C 扩展（pydantic-core）做数据校验，速度极快。
    ④ 自动生成 OpenAPI 文档，开发效率高。
    但注意：如果在 async 路由里调用了同步阻塞操作（如 requests、同步数据库驱动）， 会阻塞事件循环，性能反而下降。需要用对应的异步库（httpx、asyncpg）。

    8. 面试高频题

    Q1：GIL 是什么？对多线程有什么影响？

    参考答案：GIL 是 CPython 的全局解释器锁，同一时刻只允许一个线程执行 Python 字节码。 影响：① CPU 密集型多线程不仅不提速反而更慢（GIL 竞争 + 线程切换开销）； ② IO 密集型多线程有效（IO 操作释放 GIL，其他线程可执行）。 绕过 GIL 的方法：多进程、使用 C 扩展（如 NumPy）、使用无 GIL 的解释器（如 PyPy）。

    Q2：多线程和多进程的区别？

    参考答案：
    ① 线程共享同一进程的地址空间，进程有独立地址空间。
    ② 线程创建/切换开销小，进程开销大。
    ③ 线程间直接共享变量（需加锁），进程间通过 Queue/Pipe 通信（需序列化）。
    ④ 多线程受 GIL 限制（CPU 密集型无效），多进程能利用多核。
    ⑤ 线程崩溃可能影响整个进程，进程崩溃相互独立。

    Q3：什么时候用 AsyncIO？

    参考答案：高并发 IO 密集型场景。 例如 Web 服务器（大量请求等待网络）、爬虫（大量 HTTP 请求）、聊天/推送服务器（长连接）。 不适合 CPU 密集型（会阻塞事件循环）。AsyncIO 单线程就能处理万级并发， 比多线程创建/切换开销小得多。

    Q4：线程池和进程池的区别？

    参考答案：
    ① 线程池（ThreadPoolExecutor）：线程共享内存，通信方便，受 GIL 限制，适合 IO 密集型。
    ② 进程池（ProcessPoolExecutor）：进程独立，能利用多核，通信需序列化（pickle），适合 CPU 密集型。
    ③ 接口一致（都用 submit/map/as_completed），切换方便。
    ④ 进程池的任务参数必须可 pickle 序列化。

    Q5：协程和线程的区别？

    参考答案：
    ① 线程由操作系统调度（抢占式），协程由用户态调度（协作式，需主动 await 让出）。
    ② 线程切换开销大（内核态），协程切换开销极小（用户态函数调用）。
    ③ 线程数量有限（几百个就很多了），协程可以开上万个。
    ④ 线程需要锁保证安全，协程在单线程内运行，天然没有竞态（但 await 点之间仍需注意）。
    ⑤ 协程不能阻塞（否则整个事件循环卡住），线程可以阻塞。

    Q6：线程安全怎么保证？

    参考答案：
    ① 加锁：Lock / RLock 保护共享变量，with lock: 自动释放。
    ② 使用线程安全数据结构：queue.Queue、collections.deque。
    ③ 不可变对象：尽量使用不可变数据，避免共享可变状态。
    ④ Thread Local：threading.local() 让每个线程有独立副本。
    ⑤ 消息传递：用 Queue 代替直接共享变量，生产者-消费者模式。

    本章小结

    • 并发是交替执行，并行是真正同时；CPU 密集型选多进程，IO 密集型选线程或 AsyncIO。
    • GIL 是 CPython 特有的，CPU 密集型多线程反而慢，IO 密集型多线程有效。
    • 多线程用 ThreadPoolExecutor，共享变量必须加锁（Lock/RLock）防止竞态条件。
    • 多进程用 Pool 或 ProcessPoolExecutor，能绕过 GIL 利用多核，进程间用 Queue/Pipe 通信。
    • AsyncIO 单线程事件循环，async/await 语法，适合高并发 IO，不适合 CPU 密集型。
    • asyncio.gather 并发执行多个协程，run_in_executor 可把同步函数丢到线程池。
    • FastAPI 基于 ASGI 高性能异步框架，自动生成 OpenAPI 文档，性能接近 Go。
    • 技术选型核心：先判断 CPU 还是 IO 密集，再决定多进程/多线程/AsyncIO。
