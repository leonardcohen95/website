    1. 数据结构深入

    1.1 四大容器底层与时间复杂度

    Python 的四大内置容器各有底层数据结构支撑，理解它们才能写出高效代码。 list 底层是动态数组（over-allocate 预分配），tuple 是不可变数组， set 是哈希表（开放寻址），dict 3.7+ 也是哈希表但保持插入顺序。

    时间复杂度速查表（面试必背）
    操作              list    tuple   set      dict
索引 s[i]          O(1)    O(1)    -        O(1)
尾部 append        O(1)均摊  -       -        -
头部 insert(0)     O(n)    -       -        -
查找 in            O(n)    O(n)    O(1)     O(1)
删除 del s[i]      O(n)    -       O(1)     O(1)
长度 len           O(1)    O(1)    O(1)     O(1)
排序 sort          O(nlogn) -      -        -

    1.2 dict 3.7+ 有序原理

    Python 3.6 起 dict 内部用哈希表 + 稀疏索引数组 + 紧凑数组三段式结构。 哈希冲突通过开放寻址解决，插入顺序保存在紧凑数组 entries 中， 因此迭代时按插入顺序输出。这在 3.7 被正式写进语言规范。 

    # 3.7+ dict 保持插入顺序
d = {}
d["b"] = 2
d["a"] = 1
d["c"] = 3
print(list(d.keys()))  # ['b', 'a', 'c'] —— 按插入顺序

    1.3 切片与推导式

    切片 s[start:stop:step] 本质是调用 __getitem__(slice(start, stop, step))， 返回新对象，不修改原对象（list 切片是浅拷贝）。 推导式是 Python 风格的核心，比 for 循环更快（C 层实现循环）。 

    # 列表推导式：生成 1~10 的平方
squares = [x ** 2 for x in range(1, 11)]

# 带条件的推导式：偶数平方
even_sq = [x ** 2 for x in range(10) if x % 2 == 0]

# 字典推导式：键值翻转
m = {"a": 1, "b": 2}
rev = {v: k for k, v in m.items()}  # {1: 'a', 2: 'b'}

# 集合推导式：去重
nums = {x % 3 for x in range(10)}   # {0, 1, 2}

# 生成器推导式（注意是圆括号）：惰性，省内存
gen = (x ** 2 for x in range(10**6))

    1.4 浅拷贝 vs 深拷贝（面试高频）

    copy.copy（浅拷贝）只拷贝最外层容器，内部嵌套对象仍共享引用； copy.deepcopy（深拷贝）递归拷贝所有层级，完全独立。 对于不可变对象，两者都返回原对象引用（无拷贝必要）。 

    import copy

a = [1, [2, 3], {"k": "v"}]

b = copy.copy(a)        # 浅拷贝
b[1].append(4)
print(a[1])             # [2, 3, 4] —— 内部嵌套被共享，a 也变了

c = copy.deepcopy(a)    # 深拷贝
c[2]["new"] = 1
print(a[2])             # {'k': 'v'} —— 完全独立，a 不变
    面试问法：list 的三种拷贝方式

    ① b = a[:] 切片拷贝；② b = list(a) 构造拷贝； ③ b = copy.copy(a)。三种都是浅拷贝，嵌套可变对象仍共享。 要完全独立必须用 copy.deepcopy。

    1.5 可迭代对象 / 迭代器 / 生成器

    三者关系是面试常考点，用一张图理清：

     可迭代对象 (Iterable)
  ├── 实现 __iter__()，返回一个迭代器
  │     list / dict / str / range / file ...
  │
  ▼
 迭代器 (Iterator)
  ├── 实现 __iter__() 和 __next__()
  │     有状态，记住当前位置，只能遍历一次
  │
  ├── 生成器 (Generator)  —— 迭代器的子集
  │     ├── 含 yield 的函数，或生成器推导式
  │     └── 惰性求值，按需产生值，极省内存
    # 自定义迭代器：实现 __iter__ 和 __next__
class CountDown:
    def __init__(self, start):
        self.n = start
    def __iter__(self):
        return self           # 迭代器返回自身
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1

for i in CountDown(3):       # 3, 2, 1
    print(i)

    2. 装饰器（Decorator）

    装饰器

    接收一个函数并返回一个新函数的高阶函数，在不修改原函数代码的前提下增强其行为（日志、计时、权限校验等）。 语法糖 @dec 等价于 f = dec(f)，底层依赖闭包。

    2.1 闭包原理

    装饰器的基石是闭包：内部函数引用了外部函数的变量（自由变量）， 即使外部函数执行完毕，内部函数仍能访问这些变量。__closure__ 属性保存了自由变量。 

    def outer(x):
    def inner(y):
        return x + y        # x 是自由变量，被闭包捕获
    return inner

add5 = outer(5)
print(add5(3))             # 8
print(add5.__closure__)    # (<cell at ...: int object at 5>,)

    2.2 不带参数的装饰器

    装饰器本质是「接收函数、返回函数」的高阶函数。

    import functools

def log(func):
    @functools.wraps(func)            # 保留原函数元信息
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} 执行完毕")
        return result
    return wrapper

@log
def add(a, b):
    """两数相加"""
    return a + b

print(add(2, 3))         # 调用 add / add 执行完毕 / 5
print(add.__name__)      # add —— 没有 wraps 会变成 wrapper

    2.3 带参数的装饰器

    要给装饰器传参，需要多包一层：最外层接收参数，中间层接收函数，最内层执行逻辑。

    def repeat(times):                       # 最外层：接收装饰器参数
    def decorator(func):                # 中间层：接收被装饰函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # 最内层：执行逻辑
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(times=3)
def greet(name):
    print(f"Hello, {name}")

greet("World")          # 打印三次 Hello, World

    2.4 类装饰器

    类装饰器通过实现 __call__ 方法，让实例可被调用，适合维护状态（如计数、缓存）。

    class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func = func
        self.count = 0

    def __call__(self, *args, **kwargs):
        self.count += 1
        return self.func(*args, **kwargs)

@CountCalls
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

fib(10)
print(fib.count)         # 1 —— 调用次数统计
    多个装饰器：从下往上包装，从上往下执行

    @A @B def f() 等价于 f = A(B(f))。 包装顺序（定义时）：先执行 B 包裹 f，再用 A 包裹 B(f)，即从下往上。 执行顺序（调用时）：先执行 A 的 wrapper，再执行 B 的 wrapper，再执行 f，即从上往下。

    2.5 实战装饰器

    import time

# 计时装饰器
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

# 权限校验装饰器（Web 场景）
def require_permission(perm):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(user, *args, **kwargs):
            if perm not in user.get("permissions", []):
                raise PermissionError(f"缺少权限: {perm}")
            return func(user, *args, **kwargs)
        return wrapper
    return decorator

@timer
@require_permission("bond:read")
def query_bond(user, bond_code):
    return f"债券 {bond_code} 的行情数据"

query_bond({"permissions": ["bond:read"]}, "019547")

    3. 生成器（Generator）

    生成器

    一种特殊的迭代器，由含 yield 的函数或生成器推导式创建。惰性求值， 按需产生值而不一次性加载全部数据，极大节省内存。支持 send() 传值、 yield from 委托，是 Python 协程的基础。

    3.1 yield 原理

    函数体中出现 yield，该函数就变成生成器函数。调用它返回生成器对象， 函数体并不执行。每次 next() 推进到下一个 yield 并暂停， 保存栈帧，下次从暂停处继续。这就是惰性求值的基础。 

    def gen():
    print("第一步")
    yield 1
    print("第二步")
    yield 2

g = gen()              # 不打印任何东西，函数未执行
print(next(g))         # 第一步 / 1
print(next(g))         # 第二步 / 2
# next(g)             # StopIteration

    3.2 send / throw / close

    生成器不仅能产出值，还能通过 send() 接收外部传入的值（赋值给 yield 表达式左边）， 通过 throw() 注入异常，close() 关闭。这三个方法让生成器具备协程雏形。 

    def accumulator():
    total = 0
    while True:
        val = yield total        # yield 表达式的值 = send 传入的参数
        if val is None:
            break
        total += val

g = accumulator()
next(g)               # 预激，返回 0（必须先 next 或 send(None)）
print(g.send(10))     # 10
print(g.send(20))     # 30
g.close()
    为什么生成器能实现协程？

    协程的核心是「主动让出 CPU、保存状态、可恢复」。生成器的 yield 恰好做到： 执行到 yield 主动挂起，栈帧保存在生成器对象里，下次 next/send 从断点恢复。 Python 的 asyncio 协程早期就是基于生成器 + yield from 实现的。

    3.3 yield from 委托生成器

    yield from subgen 把生成器的职责委托给子生成器， 自动传递 send/throw/close，并把子生成器的 return 值作为 yield from 表达式的结果。 这是协程链式调用的关键。 

    def sub():
    yield 1
    yield 2
    return "done"          # 生成器的 return 值通过 yield from 传出

def main():
    result = yield from sub()
    print("子生成器返回:", result)

for v in main():
    print(v)               # 1, 2, 然后打印 "子生成器返回: done"

    3.4 惰性求值的内存优势

    列表推导式一次性把所有元素放进内存，生成器推导式逐个产生，处理大数据时差距巨大。

    # 100 万个元素
import sys

lst = [x ** 2 for x in range(1_000_000)]
gen = (x ** 2 for x in range(1_000_000))

print(sys.getsizeof(lst))   # ~8.6 MB
print(sys.getsizeof(gen))   # ~120 字节，几乎不占内存

    4. 上下文管理器（Context Manager）

    上下文管理器

    实现 __enter__ 和 __exit__ 的对象，配合 with 语句使用， 保证无论是否抛异常都能正确执行进入和退出逻辑。常用于文件操作、数据库连接、锁、计时等 需要「申请-释放」配对的资源管理场景。

    4.1 原理：__enter__ / __exit__

    上下文管理器保证无论 with 块是否抛异常，都能正确执行「进入」和「退出」逻辑。 类实现 __enter__（进入时执行，返回值赋给 as 变量）和 __exit__(exc_type, exc_val, exc_tb)（退出时执行，返回 True 可吞掉异常）。 

    class Timer:
    def __enter__(self):
        import time
        self.start = time.perf_counter()
        return self                          # as 变量

    def __exit__(self, exc_type, exc_val, exc_tb):
        elapsed = time.perf_counter() - self.start
        print(f"耗时 {elapsed:.4f}s")
        return False                         # False 不吞异常，True 吞掉

with Timer() as t:
    # 模拟耗时操作
    sum(range(1_000_000))

    4.2 contextlib 装饰器写法

    用 @contextmanager 把一个生成器变成上下文管理器，更简洁。

    from contextlib import contextmanager

@contextmanager
def open_file(path, mode="r"):
    f = open(path, mode, encoding="utf-8")   # __enter__ 部分
    try:
        yield f                               # yield 前=进入，yield 后=退出
    finally:
        f.close()                             # __exit__ 部分

with open_file("data.txt", "w") as f:
    f.write("hello")

    4.3 实战：数据库连接上下文管理器

    FICC 投研系统每天要连数据库，用上下文管理器保证连接必关闭。

    import sqlite3

class DBConnection:
    def __init__(self, db_path):
        self.db_path = db_path
        self.conn = None

    def __enter__(self):
        self.conn = sqlite3.connect(self.db_path)
        return self.conn                 # as 变量拿到连接对象

    def __exit__(self, exc_type, exc_val, exc_tb):
        if exc_type is None:
            self.conn.commit()           # 无异常则提交
        else:
            self.conn.rollback()         # 有异常则回滚
        self.conn.close()
        return False

with DBConnection("ficc.db") as conn:
    cur = conn.cursor()
    cur.execute("INSERT INTO bonds(code, name) VALUES(?, ?)",
                ("019547", "国债"))
    # 退出时自动 commit / rollback / close

    类型注解不影响运行时

    类型注解只是元信息，存在 __annotations__ 里，Python 解释器在运行时不做强制检查。 它是给人看、给 IDE 提示、给静态检查工具（mypy、pyright）用的。要在运行时校验需用 pydantic 等库。

    5.2 鸭子类型 vs 类型注解

    Python 是动态类型，遵循「鸭子类型」：只要走路像鸭子、叫像鸭子，就是鸭子。 即不关心对象类型，只关心它有没有需要的方法。类型注解是在此之上的补充，不改变鸭子类型本质。 

    class Duck:
    def quack(self):
        print("嘎嘎")

class Person:
    def quack(self):
        print("我也会嘎嘎")

def make_sound(animal):
    animal.quack()         # 不关心类型，只要有 quack 方法即可

make_sound(Duck())          # 嘎嘎
make_sound(Person())        # 我也会嘎嘎

    6. 内存与对象模型

    6.1 引用计数与垃圾回收

    CPython 主要靠引用计数回收内存：对象每被引用一次计数 +1，解除引用 -1，归零立即回收。 但引用计数无法解决循环引用，因此还有分代回收（0/1/2 三代，对象存活越久检查越少）， 定期扫描找出循环引用的垃圾。 

    import sys

a = [1, 2, 3]
print(sys.getrefcount(a))   # 2 (a + getrefcount 内部临时引用)
b = a
print(sys.getrefcount(a))   # 3
del b
print(sys.getrefcount(a))   # 2

    6.2 小整数池与字符串驻留

    CPython 对 -5 ~ 256 的整数做了缓存（小整数池），这些整数在整个程序中只有一个对象。 字符串驻留（intern）让相同的字面量字符串共享对象，节省内存。 这就是为什么 256 is 256 为 True，而 257 is 257 可能为 False（取决于实现）。 

    print(256 is 256)          # True（小整数池内）
print(257 is 257)          # 通常 False（交互式下），模块级同一行可能 True

a = "hello"
b = "hello"
print(a is b)              # True（字符串驻留）

    6.3 is vs ==（面试高频）

    == 比较的是值是否相等（调用 __eq__）； is 比较的是是否同一个对象（即内存地址 id() 是否相同）。 判断 None 必须用 is None（None 全局只有一个对象）。 

    a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)              # True  值相等
print(a is b)              # False 不是同一个对象

c = a
print(c is a)              # True  同一对象

    6.4 可变对象 vs 不可变对象

    不可变对象（int/str/tuple/frozenset）创建后值不能改，「修改」实际是创建新对象； 可变对象（list/dict/set）可原地修改。这导致默认参数陷阱——可变默认参数在函数定义时只创建一次。 

    # 经典坑：可变默认参数
def append_to(item, target=[]):
    target.append(item)
    return target

print(append_to(1))   # [1]
print(append_to(2))   # [1, 2] —— 第二次调用复用了同一个 list！

# 正确写法
def append_to(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target
    面试题：Python 内存泄漏怎么排查

    ① tracemalloc（标准库）：统计各模块内存分配，对比快照定位增长源。 ② objgraph：画出对象引用关系图，找出谁还在引用该释放的对象（多为全局容器、缓存、循环引用）。 ③ 常见泄漏原因：全局 list/dict 不断 append、事件回调未解注册、lru_cache 无上限、循环引用含 __del__。

    7. 面试高频题汇总

    Q1：装饰器的原理和执行顺序？

    参考答案要点

    ①原理：装饰器是接收函数并返回函数的高阶函数，底层依赖闭包和函数一等公民特性，语法糖 @dec 等价于 f = dec(f)。 ②执行顺序：定义时从下往上包装（A(B(f))），调用时从上往下执行（先 A 的 wrapper，再 B 的 wrapper，再 f）。 ③必须提 functools.wraps 保留原函数的 __name__、__doc__ 等元信息。

    Q2：生成器和迭代器的区别？

    参考答案要点

    ①迭代器是实现了 __iter__ 和 __next__ 的对象，有状态、只能遍历一次。 ②生成器是迭代器的一种，用 yield 或生成器推导式创建，自动实现迭代器协议，惰性求值、省内存。 ③生成器额外支持 send() 传值、throw() 抛异常、yield from 委托，是协程的基础。

    Q3：上下文管理器原理？

    参考答案要点

    ①实现 __enter__（进入 with 时调用，返回 as 的值）和 __exit__（退出时调用，无论是否异常）。 ②__exit__ 返回 True 可吞掉异常，返回 False 向上抛出。 ③也可用 @contextmanager + 生成器实现，yield 前为进入逻辑，yield 后为退出逻辑（通常用 try/finally 包裹）。

    Q4：is 和 == 的区别？

    参考答案要点

    == 比较值（调用 __eq__），is 比较身份（id() 是否相同，即是否同一对象）。 判断 None 必须用 is None。小整数池、字符串驻留会让部分常量 is 为 True，但不能依赖。

    Q5：Python 垃圾回收机制？

    参考答案要点

    ①引用计数为主：引用归零立即回收，实时性好但无法处理循环引用。 ②分代回收为辅：0/1/2 三代，新对象在 0 代，熬过扫描升级，存活越久扫描频率越低，提升效率。 ③标记-清除用于解决循环引用：从根对象出发标记可达对象，清除不可达的循环引用组。

    Q6：*args 和 **kwargs 的作用？

    参考答案要点

    ①*args 收集多余的位置参数为 tuple；**kwargs 收集多余的关键字参数为 dict。 ②让函数支持可变参数，常用于装饰器透传参数 def wrapper(*args, **kwargs)。 ③调用时也可解包：func(*lst, **dct)。

    本章小结

    • list 是动态数组、set/dict 是哈希表，查找 set/dict 为 O(1)，list 为 O(n)。
    • dict 3.7+ 通过哈希表 + 紧凑数组实现插入有序，已写入语言规范。
    • 浅拷贝只复制最外层、内部嵌套共享；深拷贝递归复制所有层级，用 copy.deepcopy。
    • 装饰器 = 高阶函数 + 闭包；多装饰器从下往上包装、从上往下执行，务必加 functools.wraps。
    • 生成器用 yield 实现惰性求值，send/throw/close + yield from 使其具备协程能力，极大节省内存。
    • 上下文管理器用 __enter__/__exit__ 或 @contextmanager 实现，保证资源正确释放（文件、DB 连接、锁）。
    • 类型注解是元信息，运行时不检查，配合 mypy 做静态检查；不改变鸭子类型本质。
    • 内存管理 = 引用计数（主）+ 分代回收（辅）+ 标记清除；is 比身份、== 比比值，小整数池为 -5~256。
