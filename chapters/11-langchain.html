    第 11 章 框架实战 约 30 分钟

    LangChain 入门：用框架快速搭 Agent

    前面我们手写了记忆、工具调用、ReAct，理解了原理。但实际项目中手写容易出 bug、 重复造轮子。这一章开始我们学习主流框架，先从最流行的 LangChain 入手，看看它如何把我们手写的逻辑封装成一行行简洁的调用。

    学习目标

    • 理解 LangChain 是什么、解决了什么问题
    • 掌握 LangChain 的核心组件：Model、Prompt、Chain、Tool、Agent
    • 学会用 LangChain 调用大模型和构造 Prompt 模板
    • 用 LangChain 快速实现一个带工具的 Agent
    • 了解 LCEL（LangChain 表达式语言）

    1. 什么是 LangChain

    LangChain 是一个开源的 LLM 应用开发框架。 它把「调用模型、管理提示词、串联多步骤、接入工具、对话记忆」等常见能力 封装成标准化组件，让你不用每次都从零写。

    大白话理解

    手写 Agent 就像自己用零件拼一台电脑；LangChain 像品牌整机， 它把内存、硬盘、CPU 都按标准接口装好了，你只需接上显示器就能用。 当然，你也可以随时打开机箱换零件。

    安装 LangChain（同时装 OpenAI 兼容客户端，用来连通义千问）：

    pip install langchain langchain-openai

    2. LangChain 的核心组件

    Model（模型）

    封装大模型调用。ChatOpenAI 是最常用的类，通义千问兼容 OpenAI 接口，可以直接用它。

    Prompt Template（提示词模板）

    带占位符的提示词，如「你是一个{role}，请回答{question}」，运行时填入变量。

    Chain（链）

    把多个步骤串起来，比如「模板 → 模型 → 输出解析器」就是一条链。

    Tool & Agent（工具与智能体）

    Tool 是可调用的外部函数，Agent 能自主决定调用哪些 Tool 来完成任务。

    Memory（记忆）

    管理对话历史，让多轮对话保持上下文。

    3. 用 LangChain 调用模型

    通义千问兼容 OpenAI 的接口格式，我们用 ChatOpenAI 指向通义的地址即可。 创建 langchain_demo.py： 

    import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

# 通义千问兼容 OpenAI 接口，所以用 ChatOpenAI，改 base_url 即可
model = ChatOpenAI(
    model="qwen-turbo",
    api_key=os.getenv("DASHSCOPE_API_KEY"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",  # 通义的兼容地址
)

# 定义一个提示词模板：{role} 和 {question} 是占位符，运行时替换
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个{role}，回答要简洁。"),
    ("user", "{question}"),
])

# StrOutputParser 把模型输出的消息对象转成纯字符串
parser = StrOutputParser()

# 用 | 把「模板 → 模型 → 解析器」串成一条链（LCEL 语法）
chain = prompt | model | parser

# invoke 执行链，传入占位符的值
result = chain.invoke({"role": "数学老师", "question": "1+1等于几？"})
print(result)  # 输出：1+1等于2。
    LCEL 是什么？

    LCEL（LangChain Expression Language）就是用管道符 | 把组件串起来， 像 Unix 管道一样。左边的输出作为右边的输入。 prompt | model | parser 表示：模板生成消息 → 模型处理 → 解析器取文本。

    4. 用 LangChain 定义工具和 Agent

    手写 Function Calling 要写一堆 JSON Schema。LangChain 用 @tool 装饰器， 直接把普通 Python 函数变成工具，自动生成 schema。 

    from langchain_core.tools import tool
from langchain.agents import create_tool_calling_agent, AgentExecutor


@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气。参数 city 是城市名称，如北京、上海。"""
    weather_db = {"北京": "晴，25°C", "上海": "多云，22°C", "广州": "小雨，28°C"}
    return weather_db.get(city, f"暂无{city}的天气数据")


@tool
def calculate(expression: str) -> str:
    """计算数学表达式，如 2+3*4。参数 expression 是要计算的表达式字符串。"""
    try:
        return str(eval(expression))
    except Exception as e:
        return f"计算错误：{e}"


# 把两个工具放进列表
tools = [get_weather, calculate]

# 定义 Agent 的提示词
agent_prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个智能助手，必要时调用工具来回答问题。"),
    ("placeholder", "{chat_history}"),  # 对话历史占位符
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),  # Agent 中间思考过程，固定写法
])

# create_tool_calling_agent 自动处理「模型选工具 → 执行 → 回传 → 再调用」的循环
agent = create_tool_calling_agent(model, tools, agent_prompt)

# AgentExecutor 负责驱动 Agent 循环执行，max_iterations 防止死循环
executor = AgentExecutor(agent=agent, tools=tools, verbose=True, max_iterations=5)

# 调用 Agent 执行任务
result = executor.invoke({"input": "北京今天天气怎么样？适合出门吗？"})
print(result["output"])

    5. 运行结果示意

    > Entering AgentExecutor...
> 模型决定调用 get_weather("北京")
> Tool 返回：晴，25°C
> 模型根据结果生成回答：北京今天晴，气温25°C，天气不错，适合出门。
> Finished chain.
北京今天晴，气温25°C，天气不错，适合出门。
    对比手写代码

    回想第 5 章，我们手写 Function Calling 需要自己解析 tool_calls、 执行函数、拼 role: "tool" 消息、再调用模型。 用 LangChain，AgentExecutor 把这些全自动化了， 我们只需定义工具和提示词。这就是框架的价值。

    6. 给 Agent 加对话记忆

    LangChain 提供 ChatMessageHistory 管理对话历史， 实现多轮对话只需把历史传进 chat_history。 

    from langchain_community.chat_message_histories import ChatMessageHistory

# 用一个列表存放对话历史（生产环境可换成 Redis、SQLite 等）
history = ChatMessageHistory()

def chat_with_history(user_input: str) -> str:
    result = executor.invoke({
        "input": user_input,
        "chat_history": history.messages,  # 把已有历史传给 Agent
    })
    # 把这一轮的用户输入和助手回答加入历史
    history.add_user_message(user_input)
    history.add_ai_message(result["output"])
    return result["output"]


if __name__ == "__main__":
    print(chat_with_history("我叫小明"))
    print(chat_with_history("我叫什么名字？"))  # Agent 能记得上一轮的「小明」

    7. LangChain 的优缺点

    • 优点：组件丰富、生态大、和各种模型/向量库集成好、省掉大量胶水代码
    • 缺点：版本更新快、API 经常变、抽象层级多导致报错时难调试
    学习建议

    用框架的前提是理解原理。如果你跳过前几章直接学 LangChain，出了问题会不知道是模型、 提示词还是工具的问题。建议先掌握第 3~6 章的手写实现，再来用框架，效率最高。

    本章小结

    • LangChain 把模型、提示词、工具、记忆等封装成标准化组件
    • 核心组件：Model、Prompt Template、Chain、Tool、Agent、Memory
    • 用 @tool 装饰器把普通函数变成工具，自动生成 schema
    • AgentExecutor 自动驱动「选工具 → 执行 → 回传」的循环
    • LCEL 用 | 管道符串联组件
