    Selenium 自动化测试面试实战

    Selenium 是 Web 自动化测试领域的事实标准，也是测试开发、运维自动化、爬虫岗位的 高频考点。本章从核心原理讲起，覆盖元素定位、等待机制、三大切换、常见问题处理， 以及 Page Object 设计模式。每一节都标注了「面试怎么问」，帮你把知识点转化为 面试表达。

    学习目标

    • 理解 Selenium 的组成与 WebDriver 工作原理
    • 掌握 8 种元素定位方式及其优先级
    • 吃透三种等待机制的区别与使用场景（面试必考）
    • 熟练处理 iframe、多窗口、alert 弹窗三大切换
    • 能用 Page Object 模式编写可维护的自动化测试
    • 掌握无头模式、反检测、文件上传等实战技巧

    1. Selenium 是什么

    Selenium 是一套用于浏览器自动化的开源工具集，它能模拟真实用户 操作浏览器（点击、输入、拖拽等），广泛用于 UI 自动化测试、数据采集、RPA 等场景。

    Selenium 三大组件

    Selenium WebDriver：核心，通过各浏览器厂商提供的驱动 （ChromeDriver、geckodriver 等）直接控制浏览器，支持 Python/Java/JS 等语言。
    Selenium Grid：分布式执行，把测试任务分发到多台机器/多浏览器并行跑。
    Selenium IDE：浏览器插件，录制回放，适合快速入门，生产少用。

    1.1 WebDriver 工作原理（面试常问）

    面试经常问「Selenium 是怎么控制浏览器的？」，用下面这个流程回答最清晰：

    你的脚本(Python)
    │  调用 Selenium Client API
    ▼
Selenium Client Library (selenium 包)
    │  发送 HTTP 请求 (W3C WebDriver 协议)
    ▼
Browser Driver (chromedriver.exe)  ← 一个本地 HTTP 服务
    │  通过浏览器的 DevTools/远程调试协议
    ▼
真实浏览器 (Chrome) 执行操作并返回结果
    面试回答要点

    关键点有三个：①WebDriver 是基于 HTTP 协议通信的； ②驱动程序（chromedriver）是一个本地 HTTP Server； ③Selenium 4 之后统一遵循 W3C WebDriver 标准协议， 不再有 Selenium 3 时代的 JSON Wire Protocol。

    1.2 环境搭建（Selenium 4.x）

    Selenium 4.6 之后内置了 Selenium Manager，会自动下载匹配的浏览器驱动， 不需要手动下载 chromedriver 了。这是面试官喜欢问的新特性。 

    # 安装
pip install selenium

# 最简启动（Selenium Manager 自动管理驱动）
from selenium import webdriver

driver = webdriver.Chrome()          # 自动找/下载匹配的 ChromeDriver
driver.get("https://www.example.com")
print(driver.title)
driver.quit()
    Selenium 4 API 变化（必知）

    Selenium 4 废弃了 executable_path 参数。如果你看到 webdriver.Chrome(executable_path="...") 这种写法， 在新版会直接抛 TypeError。正确写法是用 Service： 

    from selenium import webdriver
from selenium.webdriver.chrome.service import Service

# 方式一：自动管理驱动（推荐）
driver = webdriver.Chrome()

# 方式二：手动指定驱动路径（需要 Service）
service = Service(executable_path="/path/to/chromedriver")
driver = webdriver.Chrome(service=service)

    2. 元素定位 8 种方式

    自动化的第一步就是「找到元素」。Selenium 提供了 8 种定位方式，面试会问「你平时 怎么选定位方式？」，答案是：id > name > css_selector > xpath， 优先选稳定、唯一的属性。 

    from selenium.webdriver.common.by import By

# 1. id（最优先，唯一且稳定）
driver.find_element(By.ID, "username")

# 2. name（常用于表单）
driver.find_element(By.NAME, "password")

# 3. class name（注意：只能传单个 class，不能有空格）
driver.find_element(By.CLASS_NAME, "btn-primary")

# 4. tag name（标签名，通常不唯一）
driver.find_element(By.TAG_NAME, "input")

# 5. link text（精确匹配链接文字）
driver.find_element(By.LINK_TEXT, "登录")

# 6. partial link text（模糊匹配链接文字）
driver.find_element(By.PARTIAL_LINK_TEXT, "忘记密码")

# 7. css selector（功能强大，推荐）
driver.find_element(By.CSS_SELECTOR, "#login-form .btn")

# 8. xpath（万能，能定位复杂结构）
driver.find_element(By.XPATH, "//input[@name='username']")
    find_element vs find_elements

    find_element 返回第一个匹配元素，找不到抛 NoSuchElementException；find_elements 返回列表， 找不到返回空列表 []。判断元素是否存在用后者更安全。

    2.1 XPath 常用写法（面试高频）

    # 绝对路径（不推荐，页面结构变就挂）
/html/body/div[2]/form/input

# 相对路径 + 属性（推荐）
//input[@id='username']
//button[@type='submit' and @class='btn']

# 文本匹配
//a[text()='登录']
//a[contains(text(), '忘记')]

# 模糊匹配属性
//input[contains(@class, 'btn-')]
//div[starts-with(@id, 'user-')]

# 父子 / 兄弟关系
//div[@id='box']/following-sibling::p    # 后面的兄弟 p
//li[last()]                               # 最后一个 li
//ul/li[position()=3]                      # 第 3 个 li

    2.2 CSS Selector 常用写法

    # 选择器示例
#username                # id
.btn-primary             # class
input[name='password']   # 属性
div.card > p             # 直接子元素
div.card p               # 后代元素
input[type='text'][name='user']  # 多属性
li:nth-child(3)          # 第 3 个 li
    CSS vs XPath 怎么选？

    CSS 优先：语法简洁、浏览器原生支持、性能略好。 XPath 用在：需要按文本查找（CSS 做不到）、需要向前查找父元素 （CSS 只能向下）、复杂的轴关系定位。

    3. 元素操作

    找到元素后，常见操作如下：

    el = driver.find_element(By.ID, "username")

el.click()                    # 点击
el.send_keys("hello")         # 输入
el.clear()                    # 清空输入框
el.send_keys(Keys.ENTER)      # 按回车键

el.get_attribute("value")     # 获取属性值
el.text                       # 获取可见文本
el.is_displayed()             # 是否可见
el.is_enabled()               # 是否可用
el.is_selected()              # 是否被选中（复选框/单选）

    3.1 模拟键盘与鼠标（ActionChains）

    from selenium.webdriver.common.action_chains import ActionChains
from selenium.webdriver.common.keys import Keys

# 鼠标悬停
ActionChains(driver).move_to_element(menu).perform()

# 右键单击
ActionChains(driver).context_click(el).perform()

# 双击
ActionChains(driver).double_click(el).perform()

# 拖拽
ActionChains(driver).drag_and_drop(source, target).perform()

# 链式操作：悬停→点击→输入
ActionChains(driver) \
    .move_to_element(menu) \
    .click(submenu) \
    .send_keys("text") \
    .perform()

# 组合键：Ctrl+A 全选，Ctrl+C 复制
el.send_keys(Keys.CONTROL, "a")
el.send_keys(Keys.CONTROL, "c")

    3.2 下拉框处理（Select）

    from selenium.webdriver.support.ui import Select

select = Select(driver.find_element(By.ID, "city"))

select.select_by_index(1)          # 按索引（从 0 开始）
select.select_by_value("bj")       # 按 value 属性
select.select_by_visible_text("北京")  # 按可见文本

# 反选（仅多选下拉框）
select.deselect_all()
select.deselect_by_value("bj")

# 获取所有选项
options = select.options
first = select.first_selected_option
    注意

    Select 只能处理原生 <select> 标签。 现在很多网站用 div + ul 自定义下拉框，那就不能用 Select， 得先点击触发下拉，再点击对应选项。

    4. 三种等待机制（面试必考）

    这是 Selenium 面试出现率最高的知识点。面试官一定会问「强制等待、隐式等待、 显式等待有什么区别？」，务必背熟。

    强制等待 time.sleep()

    让程序死等 N 秒，不管元素是否出现。缺点：写死时间， 等少了不稳定，等多了浪费时间。只在调试时临时用，生产代码不要用。

    隐式等待 implicitly_wait()

    设置一个最长等待时间，在时间内轮询查找元素，找到就继续，超时抛异常。 全局生效，只需设置一次。缺点：只能等元素出现， 不能等「可点击」「文本变化」等条件。

    显式等待 WebDriverWait + EC

    针对单个元素/单个条件等待，最灵活、最推荐。 配合 expected_conditions 可以等各种状态。 

    import time
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# 1. 强制等待
time.sleep(3)

# 2. 隐式等待（全局，设置一次即可）
driver.implicitly_wait(10)

# 3. 显式等待（推荐）
wait = WebDriverWait(driver, 10, poll_frequency=0.5)
el = wait.until(EC.element_to_be_clickable((By.ID, "login-btn")))
el.click()

    4.1 常用 expected_conditions

    # 元素可见（在 DOM 中且可见）
EC.visibility_of_element_located((By.ID, "box"))

# 元素可点击
EC.element_to_be_clickable((By.ID, "btn"))

# 元素出现在 DOM（不一定可见）
EC.presence_of_element_located((By.ID, "box"))

# 文本出现
EC.text_to_be_present_in_element((By.ID, "msg"), "登录成功")

# 标题包含
EC.title_contains("首页")

# 元素消失
EC.invisibility_of_element_located((By.ID, "loading"))

# 可点击后点击（Selenium 4 新增）
EC.element_to_be_clickable((By.ID, "btn")).click(driver)
    面试回答模板

    问：三种等待的区别？
    答：强制等待是 time.sleep，死等固定时间，简单但浪费时间且不稳定； 隐式等待通过 implicitly_wait 设置全局超时， 轮询查找元素，找到就返回，但只能等元素存在； 显式等待用 WebDriverWait + expected_conditions， 可以针对具体元素和具体条件（可点击、文本出现等）等待，最灵活，生产环境优先用显式等待。

    5. 三大切换（iframe / 多窗口 / alert）

    页面中出现嵌套页面、新标签页、弹窗时，必须先切换「上下文」才能操作。

    5.1 切换 iframe

    # 按索引切换（第 0 个 iframe）
driver.switch_to.frame(0)

# 按 id 或 name 切换
driver.switch_to.frame("frameName")

# 按元素切换（先定位再切换）
iframe = driver.find_element(By.CSS_SELECTOR, "iframe.xxx")
driver.switch_to.frame(iframe)

# 切回主文档
driver.switch_to.default_content()

# 切回上一层 iframe（多层嵌套时）
driver.switch_to.parent_frame()
    常见坑

    操作完 iframe 内的元素后，必须切回 default_content 才能操作外面的元素。 很多人操作完忘了切回，导致外面的元素一直定位不到。

    5.2 切换多窗口

    # 获取当前窗口句柄
main = driver.current_window_handle

# 获取所有窗口句柄列表
handles = driver.window_handles

# 切换到最新打开的窗口
driver.switch_to.window(handles[-1])

# 关闭当前窗口并切回主窗口
driver.close()
driver.switch_to.window(main)

# 遍历所有窗口，按标题切换
for h in driver.window_handles:
    driver.switch_to.window(h)
    if "登录" in driver.title:
        break

    5.3 切换 alert / confirm / prompt 弹窗

    alert = driver.switch_to.alert

print(alert.text)      # 获取弹窗文本
alert.accept()         # 点击确定
alert.dismiss()        # 点击取消

# prompt 弹窗可以输入
alert.send_keys("hello")
alert.accept()

    8. Page Object 模式（POM）

    面试常问「你的自动化框架是怎么设计的？」Page Object Model 是最经典的答案。 核心思想：把页面操作封装成类，把元素定位和测试逻辑分离。 

    # pages/login_page.py
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

class LoginPage:
    def __init__(self, driver):
        self.driver = driver
        self.wait = WebDriverWait(driver, 10)

    # 元素定位统一管理
    USERNAME = (By.ID, "username")
    PASSWORD = (By.ID, "password")
    LOGIN_BTN = (By.CSS_SELECTOR, "button[type='submit']")

    # 操作封装成方法
    def enter_username(self, text):
        self.wait.until(EC.visibility_of_element_located(self.USERNAME)).send_keys(text)

    def enter_password(self, text):
        self.driver.find_element(*self.PASSWORD).send_keys(text)

    def click_login(self):
        self.wait.until(EC.element_to_be_clickable(self.LOGIN_BTN)).click()

    # 业务流程
    def login(self, username, password):
        self.enter_username(username)
        self.enter_password(password)
        self.click_login()


# tests/test_login.py
def test_login_success(driver):
    login_page = LoginPage(driver)
    login_page.login("admin", "123456")
    assert "首页" in driver.title
    POM 的好处（面试表达）

    ①可维护性：页面元素变了只改 Page 类，不用改所有用例； ②可读性：测试代码读起来像业务步骤（login、search）； ③复用性：多个用例可以共用同一个 Page 类的方法。

    9. 实战案例：自动登录并抓取数据

    下面是一个完整的实战脚本，综合了定位、等待、切换、截图等知识点：

    from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.common.exceptions import TimeoutException

class DemoSpider:
    def __init__(self):
        options = webdriver.ChromeOptions()
        options.add_argument("--headless=new")
        options.add_argument("--no-sandbox")
        self.driver = webdriver.Chrome(options=options)
        self.wait = WebDriverWait(self.driver, 10)

    def login(self, url, username, password):
        self.driver.get(url)
        # 显式等待用户名框可点击
        self.wait.until(EC.element_to_be_clickable((By.ID, "username"))).send_keys(username)
        self.driver.find_element(By.ID, "password").send_keys(password)
        self.driver.find_element(By.CSS_SELECTOR, "button[type=submit]").click()

        # 等待登录成功（标题变化）
        self.wait.until(EC.title_contains("首页"))
        print("登录成功")

    def get_data(self):
        # 等待表格加载
        self.wait.until(EC.presence_of_element_located((By.CSS_SELECTOR, "table tr")))
        rows = self.driver.find_elements(By.CSS_SELECTOR, "table tbody tr")
        data = []
        for row in rows:
            cols = row.find_elements(By.TAG_NAME, "td")
            data.append([c.text for c in cols])
        return data

    def run(self):
        try:
            self.login("https://example.com/login", "admin", "123456")
            data = self.get_data()
            for row in data:
                print(row)
            self.driver.save_screenshot("result.png")
        except TimeoutException:
            print("等待超时，请检查页面元素")
            self.driver.save_screenshot("error.png")
        finally:
            self.driver.quit()

if __name__ == "__main__":
    DemoSpider().run()

    10. 面试高频问题速查

    Q1: 元素定位不到怎么办？

    排查顺序：①定位表达式是否正确（先在浏览器 F12 控制台验证）； ②元素是否在 iframe 中（需切换）；③元素是否需要等待（加显式等待）； ④元素是否被遮挡/不可见；⑤是否有相同 id 的多个元素。

    Q2: click() 不生效怎么办？

    ①元素被遮挡，用 execute_script("arguments[0].click()", el) 执行 JS 点击； ②元素不可见，先滚动到可视区 scrollIntoView()； ③用 ActionChains 模拟鼠标点击。

    Q3: 如何保证脚本稳定性？

    ①用显式等待代替 time.sleep；②用相对 XPath/CSS，不用绝对路径； ③用 id/name 等稳定属性定位；④加异常处理和失败截图；⑤用 Page Object 模式 降低维护成本；⑥测试数据和测试逻辑分离。

    Q4: Selenium 3 和 Selenium 4 的区别？

    ①Selenium 4 统一使用 W3C WebDriver 协议，不再用 JSON Wire Protocol； ②废弃 executable_path，改用 Service； ③内置 Selenium Manager 自动管理驱动；④新增相对定位器 （above/below/near 等）；⑤优化了元素截图等 API。

    Q5: Selenium 怎么实现并发执行？

    三种方式：①用 pytest-xdist 多进程跑 pytest 用例； ②用 concurrent.futures.ThreadPoolExecutor 开多线程（注意 driver 不共享）； ③用 Selenium Grid 分布式，把用例分发到多台机器。每个线程/进程要有自己独立的 driver 实例。

    本章小结

    • Selenium 核心是 WebDriver，通过 HTTP 协议 + 浏览器驱动控制真实浏览器。
    • Selenium 4 用 Service 替代 executable_path，内置 Selenium Manager 自动管理驱动。
    • 元素定位优先 id，其次 css/xpath；XPath 适合文本定位和复杂结构。
    • 三种等待：强制（不推荐）、隐式（全局，等存在）、显式（推荐，等具体条件）。
    • 三大切换：iframe、多窗口、alert，操作后记得切回。
    • Page Object 模式把元素定位和测试逻辑分离，提升可维护性。
    • 实战中常用无头模式、JS 执行、反检测参数、失败截图来提升稳定性。
