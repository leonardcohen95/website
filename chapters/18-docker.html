    Docker 容器化实战

    容器是现代运维的标配。本章从镜像构建、容器网络、数据卷到故障排查和性能优化， 覆盖 Docker 运维的方方面面。学完你能熟练把应用容器化，并解决面试中常见的 「容器启动失败」「镜像太大」「容器网络不通」等问题。

    学习目标

    • 理解 Docker 镜像、容器、数据卷、网络四大核心概念
    • 能编写高效的 Dockerfile 构建镜像
    • 掌握 docker-compose 编排多容器应用
    • 能排查容器启动、网络、资源类故障
    • 了解容器性能调优手段

    1. 核心概念

    镜像（Image）

    应用的「模板」，只读。由多层文件系统叠加而成，每一层对应 Dockerfile 的一条指令。 镜像可以分层复用，这是 Docker 高效的关键。

    容器（Container）

    镜像的运行实例。在镜像层之上加了一层可写层。容器删除后可写层数据也没了， 所以要持久化的数据必须挂数据卷。

    数据卷（Volume）

    绕过容器可写层，直接把宿主机目录或 Docker 管理的卷挂载到容器里。 数据卷在容器删除后依然存在，用于持久化数据库、日志等数据。

    网络（Network）

    容器间通信靠网络。默认有 bridge、host、none 三种，生产中常用自定义 bridge 或 overlay（跨主机）。

    2. 安装与基础命令

    # 安装（CentOS）
yum install -y yum-utils
yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
yum install -y docker-ce docker-ce-cli containerd.io
systemctl start docker
systemctl enable docker

# 配置国内镜像加速（拉取快很多）
cat > /etc/docker/daemon.json << 'EOF'
{
  "registry-mirrors": ["https://你的加速器地址"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "3" }
}
EOF
systemctl restart docker

# 常用命令速查
docker pull nginx:latest          # 拉镜像
docker run -d -p 80:80 nginx      # 后台运行并映射端口
docker ps                         # 查看运行中的容器
docker ps -a                      # 查看所有容器（含停止的）
docker logs -f 容器ID             # 看日志（-f 实时）
docker exec -it 容器ID /bin/bash  # 进入容器
docker stop/start/restart 容器ID  # 启停
docker rm 容器ID                  # 删除容器
docker rmi 镜像名                 # 删除镜像

    3. Dockerfile 最佳实践

    写好 Dockerfile 是容器化的核心。下面是一个 Java 应用的示例，标注了优化点：

    # ===== 多阶段构建：编译阶段和运行阶段分离，最终镜像不含编译工具 =====
FROM maven:3.8-openjdk-11 AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline        # 先下载依赖，利用缓存
COPY src ./src
RUN mvn package -DskipTests

# ===== 运行阶段：只需要 JRE，镜像小很多 =====
FROM openjdk:11-jre-slim
WORKDIR /app
COPY --from=builder /app/target/myapp.jar .

# 安全：不要用 root 运行
RUN useradd -r -u 1001 appuser
USER appuser

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "myapp.jar"]
    镜像瘦身技巧
    • 多阶段构建：编译环境和运行环境分开，最终镜像只留运行时。
    • 用 slim/alpine 基础镜像：比默认镜像小一半以上。
    • 合并 RUN 指令：每条 RUN 产生一层，合并减少层数并清理缓存。
    • .dockerignore：排除 .git、node_modules 等不需要的文件。
    • 先 COPY 依赖文件再 COPY 源码：代码变更不会让依赖缓存失效。

    3.1 合并 RUN 并清理

    # 反例：每句一条 RUN，产生多层，且缓存没清
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y vim

# 正例：合并成一条，最后清缓存
RUN apt-get update && \
    apt-get install -y --no-install-recommends curl vim && \
    rm -rf /var/lib/apt/lists/*

    4. 数据卷与持久化

    # 方式一：挂载宿主机目录（Bind Mount）
docker run -d -v /data/mysql:/var/lib/mysql mysql:8

# 方式二：Docker 管理的卷（Volume，推荐）
docker volume create mydata
docker run -d -v mydata:/var/lib/mysql mysql:8

# 查看卷
docker volume ls
docker volume inspect mydata

# 容器间共享数据
docker run -d --name db -v dbdata:/var/lib/mysql mysql:8
docker run -d --volumes-from db backup sh -c 'tar czf /backup.tar /var/lib/mysql'
    生产环境不要把数据放容器里

    容器删除 = 可写层数据丢失。数据库、上传文件、日志等必须挂数据卷。 面试时被问「容器删了数据怎么办」，标准答案：数据不放在容器里，用 Volume。

    5. 容器网络

    5.1 网络模式

    docker run --network bridge  # 默认，独立网络命名空间，通过 docker0 桥接
docker run --network host    # 共享宿主机网络，性能好但端口冲突
docker run --network none    # 无网络
docker run --network container:容器ID  # 共享另一个容器的网络栈

    5.2 自定义网络实现容器互联

    # 创建自定义 bridge 网络（支持容器名 DNS 解析）
docker network create mynet

# 启动两个容器加入同一网络
docker run -d --name web --network mynet nginx
docker run -d --name api --network mynet myapi

# 从 web 容器里可以直接用容器名访问 api
docker exec web curl http://api:8080

# 暴露端口给宿主机
docker run -d --name web --network mynet -p 8080:80 nginx
    端口映射的坑

    -p 8080:80 前面是宿主机端口，后面是容器端口。 如果只写 -p 80，Docker 会随机分配宿主机端口，用 docker ps 查看。 默认映射到 0.0.0.0（所有网卡），生产可指定 -p 127.0.0.1:8080:80 只本机访问。

    6. docker-compose 编排

    多容器应用（比如 Web + DB + Redis）用 docker-compose 一键编排：

    # docker-compose.yml
version: "3.8"

services:
  web:
    build: .
    ports:
      - "8080:8080"
    environment:
      - DB_HOST=db
      - DB_PASSWORD=${DB_PASSWORD}   # 从 .env 文件读取
    depends_on:
      - db
      - redis
    restart: unless-stopped          # 异常退出自动重启

  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: secret
    volumes:
      - dbdata:/var/lib/mysql
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    restart: unless-stopped

volumes:
  dbdata:                             # 声明命名卷

    启动和管理：

    docker-compose up -d            # 后台启动
docker-compose ps               # 查看服务状态
docker-compose logs -f web      # 看某个服务日志
docker-compose down             # 停止并删除容器（保留卷）
docker-compose down -v          # 连卷一起删
docker-compose build            # 重新构建镜像

    7. 故障排查

    7.1 容器启动失败

    # 1. 看退出码
docker ps -a
# Exited (1)  → 应用报错
# Exited (137) → OOM 被 kill
# Exited (139) → 段错误

# 2. 看日志
docker logs 容器ID
docker logs --tail 100 容器ID

# 3. 看容器详细信息
docker inspect 容器ID
# 关注 State、Mounts、NetworkSettings、Config.Cmd

# 4. 启动一个临时容器排查
docker run --rm -it --entrypoint /bin/sh 镜像名

    7.2 资源限制与 OOM

    # 限制内存和 CPU，防止容器吃光宿主机资源
docker run -d \
  --memory=512m --memory-swap=512m \    # 内存 512M，禁用 swap
  --cpus=1 \                             # 最多用 1 核
  --oom-kill-disable \                   # OOM 时不杀容器（慎用）
  myapp

# 查看容器资源使用
docker stats

# 排查 OOM
dmesg | grep -i oom
docker inspect 容器ID | grep -i oom
    退出码速查
    • 0：正常退出
    • 1：应用报错
    • 137：被 OOM Killer 杀掉（内存不足）
    • 139：段错误（Segfault）
    • 143：收到 SIGTERM 正常终止

    7.3 镜像体积过大

    # 查看镜像每层大小
docker history 镜像名

# 清理无用的镜像、容器、卷
docker system prune -a
docker volume prune

# 查看 Docker 占用
docker system df

    8. 性能调优

    • 存储驱动：用 overlay2（默认），性能最好。
    • 日志大小限制：在 daemon.json 配 max-size，防止日志撑满磁盘。
    • 资源限制：每个容器设 memory 和 cpus，避免互相影响。
    • 网络模式：高性能场景用 --network host 减少网络栈开销。
    • 数据卷用本地 SSD：数据库等 IO 密集型应用，数据卷放高速盘。

    本章小结

    • Docker 四大核心：镜像（模板）、容器（实例）、数据卷（持久化）、网络（通信）。
    • Dockerfile 用多阶段构建、合并 RUN、清理缓存来缩小镜像。
    • 生产数据必须挂 Volume，容器删除不影响数据。
    • 容器互联用自定义 bridge 网络，支持容器名 DNS。
    • 多容器编排用 docker-compose，配 depends_on 和 restart 策略。
    • 排障：看退出码、看日志、看 inspect；137 是 OOM，要加内存限制。
