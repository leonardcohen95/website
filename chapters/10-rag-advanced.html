    第 10 章 RAG 实战 约 35 分钟

    RAG 进阶：向量库与检索优化

    上一章我们用「暴力遍历」做相似度检索，文档一多就慢。这一章我们引入 向量数据库（Milvus / Qdrant）来加速， 并学习多路召回、重排序、上下文压缩三大优化手段， 让 RAG 检索又快又准。

    学习目标

    • 理解为什么需要向量数据库，了解 Milvus、Qdrant 等主流选型
    • 用 Qdrant 搭建本地向量库并完成检索
    • 掌握多路召回：向量检索 + 关键词检索结合
    • 理解重排序（Reranking）对准确率的提升
    • 学会上下文压缩，减少无效 token 消耗

    1. 为什么需要向量数据库

    上一章的 retrieve 函数要把问题向量和每一个块向量都算一遍相似度。 如果有 10 万块，就要算 10 万次，查询可能要好几秒。 向量数据库通过特殊的索引结构（如 HNSW 图）， 能在百万级数据中毫秒级找到最相似的向量。

    类比理解

    暴力遍历就像在一本没有目录的书里逐页找内容；向量数据库就像书末的「索引」， 直接告诉你相关内容在第几页。索引是预先建好的，查询时直接定位，非常快。

    2. 主流向量数据库对比

    数据库        特点                              适用场景
----------------------------------------------------------
Milvus        功能最全、分布式、支持十亿级        企业级大规模
Qdrant        Rust 编写、性能好、API 简洁        中小规模、追求性能
Chroma        轻量、Python 友好、可嵌入式        原型开发、个人项目
FAISS         Meta 开源、只是库不是数据库        本地快速实验
Weaviate      自带 GraphQL 接口                  复杂查询需求
    本章用哪个？

    我们用 Qdrant，因为它可以在内存中直接运行（不需要先装 Docker）， 同时性能和 API 设计都很优秀，和生产环境用法一致。 安装：pip install qdrant-client。

    3. 用 Qdrant 搭建向量库

    Qdrant 的核心概念是 Collection（集合），类似数据库里的「表」。 每个集合里存很多 Point（点），每个点包含一个向量和对应的元数据（原文、来源等）。 

    import os
from dotenv import load_dotenv
import dashscope
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct

load_dotenv()
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")


def embed(text: str) -> list[float]:
    """文本转向量（复用第 9 章的函数）"""
    resp = dashscope.TextEmbedding.call(model="text-embedding-v3", input=text)
    return resp.output.embeddings[0].embedding


# QdrantClient(":memory:") 表示在内存中运行，不写磁盘，适合快速实验
client = QdrantClient(":memory:")

# 向量维度：text-embedding-v3 默认输出 1024 维
VECTOR_SIZE = 1024

# 创建一个集合（collection），指定向量维度和距离度量方式（余弦）
client.create_collection(
    collection_name="my_kb",
    vectors_config=VectorParams(size=VECTOR_SIZE, distance=Distance.COSINE),
)

    把文本块写入向量库：

    def upsert_chunks(chunks: list[str]):
    """把一批文本块转成向量并写入 Qdrant"""
    points = []
    for i, text in enumerate(chunks):
        vec = embed(text)                       # 每块转成向量
        # PointStruct 是 Qdrant 的数据单元：id + vector + payload（元数据）
        points.append(PointStruct(
            id=i,
            vector=vec,
            payload={"text": text},             # 把原文存在 payload 里，方便取回
        ))
    # upsert = update + insert：有则更新，无则插入
    client.upsert(collection_name="my_kb", points=points)


def search_kb(question: str, top_k: int = 3) -> list[str]:
    """在 Qdrant 中检索最相关的 top_k 个文本块"""
    q_vec = embed(question)                     # 问题向量化
    hits = client.search(
        collection_name="my_kb",
        query_vector=q_vec,
        limit=top_k,                            # 返回最相似的 top_k 个
    )
    # 从命中结果里取出原文（payload.text）
    return [hit.payload["text"] for hit in hits]
    生产环境怎么部署 Qdrant？

    生产环境用 docker run -p 6333:6333 qdrant/qdrant 启动服务， 然后把 QdrantClient(":memory:") 换成 QdrantClient("http://localhost:6333") 即可，代码其余部分不变。 Milvus 用法类似，也是启动服务后用客户端连接。

    4. 多路召回（Multi-path Retrieval）

    只用向量检索有个缺点：它按「语义相似」找，可能漏掉关键词完全匹配的结果。 比如用户搜「保修期」，向量检索可能找到「售后政策」，却漏了直接写着「保修期一年」的块。 多路召回就是同时用多种方式检索，再合并去重，覆盖率更高。 

    def keyword_search(chunks: list[str], question: str, top_k: int = 3) -> list[str]:
    """简单的关键词检索：把问题拆成词，统计每个块命中了多少个词"""
    keywords = question.replace("？", "").replace("?", "").split()  # 简单按空格分词
    scored = []
    for c in chunks:
        score = sum(1 for kw in keywords if kw in c)  # 统计命中关键词个数
        scored.append((score, c))
    scored.sort(key=lambda x: x[0], reverse=True)     # 命中越多排越前
    return [c for s, c in scored[:top_k] if s > 0]    # 只返回有命中的


def multi_retrieve(chunks: list[str], question: str, top_k: int = 3) -> list[str]:
    """多路召回：向量检索 + 关键词检索，结果合并去重"""
    vec_results = search_kb(question, top_k)            # 第 1 路：向量检索
    kw_results = keyword_search(chunks, question, top_k)  # 第 2 路：关键词检索
    # 合并两路结果并去重（保持顺序）
    merged = []
    for c in vec_results + kw_results:
        if c not in merged:
            merged.append(c)
    return merged[:top_k]  # 最终只取 top_k 个
    多路召回的常见组合
    • 稠密向量检索（Dense）：语义相似，上一章的做法
    • 稀疏关键词检索（Sparse）：BM25、Elasticsearch，精确匹配
    • 混合检索（Hybrid）：两者结合，互相补全

    5. 重排序（Reranking）

    多路召回可能拿回一堆结果，但排序未必准确。重排序就是用一个更精准的模型， 对召回的结果重新打分排序，把真正相关的排到前面。

    为什么不直接用重排模型检索全部？

    重排模型虽然准，但慢、贵。所以策略是：先用快但粗的向量检索召回 top 50， 再用慢但精的重排模型对这 50 个排序，取 top 3。这样兼顾速度和精度。

    通义提供了 rerank 模型，直接调用：

    def rerank(question: str, docs: list[str], top_k: int = 3) -> list[str]:
    """用重排模型对检索结果重新排序"""
    resp = dashscope.TextReRank.call(
        model="gte-rerank",                       # 通义的重排模型
        query=question,                           # 用户问题
        documents=docs,                           # 待排序的文本列表
        top_n=top_k,                              # 返回前 top_k 个
    )
    # output.results 按相关性从高到低排列，.text 取出原文
    return [item.text for item in resp.output.results]

    6. 上下文压缩（Context Compression）

    检索回来的文本块可能很长，里面有很多和问题无关的内容。直接塞进 prompt 会浪费 token、 还可能干扰模型。上下文压缩就是从每个块里只提取和问题相关的句子， 让上下文更精炼。

    最简单的压缩方式：让模型从每个块里摘出相关句子。

    def compress(question: str, docs: list[str]) -> list[str]:
    """用大模型压缩上下文，只保留和问题相关的内容"""
    compressed = []
    for doc in docs:
        prompt = f"""用户问题：{question}
下面是一段参考资料：
{doc}
请从参考资料中提取与用户问题相关的句子，无关内容直接删除。如果整段都不相关，回复「无」。"""
        resp = dashscope.Generation.call(
            model="qwen-turbo",
            messages=[{"role": "user", "content": prompt}],
            result_format="message",
        )
        result = resp.output.choices[0].message.content.strip()
        if result != "无":
            compressed.append(result)           # 只保留压缩后有内容的块
    return compressed
    压缩的代价

    上下文压缩本身要多次调用模型，会增加延迟和成本。一般在文档块很长、 或 top_k 较大时才用。如果你的块本来就很短（如 200 字），可能不需要压缩。

    7. 完整的优化版 RAG

    把上面所有优化串起来，就是一个生产级 RAG 的检索流程：

    def ask_rag_advanced(chunks: list[str], question: str) -> str:
    # 1. 多路召回：向量 + 关键词，扩大覆盖面
    recalled = multi_retrieve(chunks, question, top_k=10)
    # 2. 重排序：用精准模型把最相关的排前面
    reranked = rerank(question, recalled, top_k=3)
    # 3. 上下文压缩：只保留相关句子
    context_docs = compress(question, reranked)
    # 4. 拼 prompt 生成答案
    context = "\n---\n".join(context_docs)
    prompt = f"""请根据以下参考资料回答问题。

参考资料：
{context}

问题：{question}"""
    resp = dashscope.Generation.call(
        model="qwen-turbo",
        messages=[{"role": "user", "content": prompt}],
        result_format="message",
    )
    return resp.output.choices[0].message.content

    本章小结

    • 向量数据库（Milvus、Qdrant）通过索引实现毫秒级相似检索
    • 多路召回 = 向量检索 + 关键词检索，提升召回覆盖率
    • 重排序用更精准的模型对召回结果二次排序，提升准确率
    • 上下文压缩只保留相关内容，减少 token 浪费和干扰
    • 生产级 RAG 流程：多路召回 → 重排序 → 压缩 → 生成
