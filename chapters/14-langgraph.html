    LangGraph：用图编排复杂 Agent 工作流

    LangChain 适合线性的 Chain，但真实 Agent 往往需要循环、条件分支、状态管理， 比如「规划 → 执行 → 检查 → 不行就重做」。LangGraph 就是为这种复杂流程而生的， 它用「图（Graph）」来描述 Agent 的执行逻辑。这一章我们用 LangGraph 实现任职资格中提到的 Plan-and-Solve（先规划再求解） 工作流。

    学习目标

    • 理解 LangGraph 的核心概念：图、节点、边、状态
    • 学会用 StateGraph 定义工作流
    • 掌握条件边（Conditional Edge）实现分支逻辑
    • 实现 Plan-and-Solve 工作流
    • 理解 LangGraph 与 LangChain、AutoGen 的关系

    1. 为什么需要 LangGraph

    LangChain 的 Chain 是线性的：一步接一步，不能回头。 但 Agent 经常需要循环（ReAct 的思考-行动循环）和分支（检查结果决定下一步）。 LangGraph 允许你画一张「流程图」：节点是操作，边是流向，还能根据状态走不同分支。

    大白话理解

    LangChain 的 Chain 像单行地铁：只能往前开。 LangGraph 像地铁线路图：可以换乘、可以环线、可以根据情况选不同线路。 复杂的 Agent 流程就需要这种「图」结构。

    安装：

    pip install langgraph langchain langchain-openai

    2. LangGraph 的核心概念

    State（状态）

    一个在节点之间传递的共享数据结构（通常是字典），记录当前任务的进度、历史消息等。

    Node（节点）

    一个处理步骤，接收 State，处理后返回更新后的 State。比如「规划」「执行」「检查」。

    Edge（边）

    节点之间的连线，表示执行顺序。分普通边（固定下一个）和条件边（根据状态决定下一个）。

    Graph（图）

    由节点和边组成的完整工作流，定义好后用 compile() 编译成可执行的应用。

    3. 实现 Plan-and-Solve 工作流

    Plan-and-Solve 的思路是：先让模型把大任务拆成步骤（Plan）， 再逐步执行（Solve），最后检查是否完成。流程图如下： 

    START → 规划(Plan) → 执行(Solve) → 检查(Check)
                                 ↑              ↓
                                 └── 未完成 ─────┘ （循环，直到完成）
                                        ↓ 已完成
                                      END

    创建 langgraph_demo.py：

    import os
from dotenv import load_dotenv
from typing import TypedDict
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, END

load_dotenv()

# 配置 LLM（通义千问兼容 OpenAI 接口）
model = ChatOpenAI(
    model="qwen-turbo",
    api_key=os.getenv("DASHSCOPE_API_KEY"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)


# ---- 1. 定义状态 State ----
# TypedDict 用来描述状态字典的结构（有哪些字段、什么类型）
class AgentState(TypedDict):
    task: str           # 用户的原始任务
    plan: str           # 规划出的步骤
    result: str         # 执行结果
    done: bool          # 是否完成（用来决定是否继续循环）


# ---- 2. 定义节点函数 ----
# 每个节点接收状态，返回要更新的字段
def plan_node(state: AgentState):
    """规划节点：让模型把任务拆成步骤"""
    prompt = f"请把以下任务拆解成 3 个可执行的步骤，只输出步骤列表：\n{state['task']}"
    resp = model.invoke(prompt)
    return {"plan": resp.content}  # 返回更新后的 plan 字段


def solve_node(state: AgentState):
    """执行节点：根据规划逐步完成任务"""
    prompt = f"任务：{state['task']}\n规划步骤：{state['plan']}\n请根据步骤给出完成结果。"
    resp = model.invoke(prompt)
    return {"result": resp.content}  # 返回更新后的 result 字段


def check_node(state: AgentState):
    """检查节点：判断结果是否完成，没完成就打回"""
    prompt = f"任务：{state['task']}\n结果：{state['result']}\n这个结果是否完整解决了任务？请只回答「是」或「否」。"
    resp = model.invoke(prompt)
    # 模型回答「是」则 done=True，否则 done=False
    done = "是" in resp.content
    return {"done": done}


# ---- 3. 定义条件边函数 ----
# 条件边根据状态决定下一个走哪个节点
def should_continue(state: AgentState):
    if state["done"]:
        return END          # 已完成，走向终点
    return "solve"          # 未完成，回到执行节点重做


# ---- 4. 构建图 ----
graph = StateGraph(AgentState)              # 创建图，指定状态类型
graph.add_node("plan", plan_node)           # 添加规划节点
graph.add_node("solve", solve_node)         # 添加执行节点
graph.add_node("check", check_node)         # 添加检查节点

graph.set_entry_point("plan")               # 入口：从规划开始
graph.add_edge("plan", "solve")             # 规划 → 执行
graph.add_edge("solve", "check")            # 执行 → 检查
# 条件边：检查后根据 should_continue 的返回值决定下一步
graph.add_conditional_edges("check", should_continue)

# compile 把图编译成可执行的应用
app = graph.compile()

    运行：

    if __name__ == "__main__":
    # invoke 执行整个图，传入初始状态
    final_state = app.invoke({"task": "写一篇关于人工智能的 100 字短文"})
    print("规划：", final_state["plan"])
    print("结果：", final_state["result"])

    4. 运行流程示意

    [plan] 规划步骤：
  1. 确定主题和核心观点
  2. 围绕核心展开论述
  3. 总结升华

[solve] 执行结果：
  人工智能正在深刻改变我们的生活……

[check] 检查：是（完整解决了任务）
→ 走向 END

结果：人工智能正在深刻改变我们的生活……
    LangGraph 的循环能力

    上面的流程中，如果 check 判断「否」，就会回到 solve 重新执行， 形成循环。这就是 LangGraph 相比线性 Chain 最大的优势—— 支持有环的图，非常适合 ReAct、Plan-and-Solve 这类需要反复迭代的 Agent。

    5. 用 LangGraph 实现 ReAct Agent

    第 6 章的 ReAct 模式（思考→行动→观察循环）天然适合用 LangGraph 实现。 下面是简化版的 ReAct 图结构： 

    from langgraph.prebuilt import ToolNode
from langchain_core.tools import tool
from langgraph.graph import MessagesState

@tool
def get_weather(city: str) -> str:
    """查询城市天气，参数 city 为城市名。"""
    return {"北京": "晴 25°C"}.get(city, "未知")

model_with_tools = model.bind_tools([get_weather])  # 把工具绑定到模型


def reason_node(state: MessagesState):
    """思考节点：模型决定是否调用工具"""
    response = model_with_tools.invoke(state["messages"])
    return {"messages": [response]}  # 把模型回复加入消息列表


# 条件边：模型是否调用了工具
def route_after_reason(state: MessagesState):
    last_msg = state["messages"][-1]
    if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
        return "tools"     # 调用了工具 → 去执行工具
    return END             # 没调用工具 → 结束


# ToolNode 是 LangGraph 内置节点，自动执行模型请求的工具
tool_node = ToolNode([get_weather])

react_graph = StateGraph(MessagesState)
react_graph.add_node("reason", reason_node)
react_graph.add_node("tools", tool_node)

react_graph.set_entry_point("reason")
react_graph.add_conditional_edges("reason", route_after_reason)
react_graph.add_edge("tools", "reason")  # 工具执行完 → 回到思考节点

react_app = react_graph.compile()
    ReAct 图的执行路径
    reason（思考：要不要用工具？）
  ├─ 调用工具 → tools（执行工具）→ reason（再思考）
  └─ 不调用   → END（输出最终答案）

    这个循环会一直进行，直到模型不再调用工具、直接给出答案。

    6. LangGraph 与其他框架的关系

    框架            定位                          擅长
------------------------------------------------------------
LangChain       通用 LLM 组件库               线性流程、简单 Agent
LangGraph       图编排框架                     循环、分支、复杂状态机
LangGraph       构建在 LangChain 之上          可以复用 LangChain 的所有组件
AutoGen         对话驱动的多智能体             群聊协作
CrewAI          角色驱动的多智能体             流水线任务
    选型建议
    • 简单线性流程 → LangChain
    • 需要循环/条件分支的复杂 Agent → LangGraph
    • 多 Agent 自由讨论 → AutoGen
    • 多 Agent 角色分工流水线 → CrewAI

    本章小结

    • LangGraph 用「图」描述 Agent 流程，支持循环和条件分支
    • 核心概念：State（状态）、Node（节点）、Edge（边）
    • Plan-and-Solve = 规划 → 执行 → 检查（未完成则循环）
    • 条件边（add_conditional_edges）根据状态决定下一步走向
    • LangGraph 构建在 LangChain 之上，适合复杂状态机式的 Agent
