    规划与反思：ReAct 模式

    现在的 Agent 已经有了记忆和工具，但它还是「想到啥做啥」。 这一章我们学习 ReAct 模式，让 Agent 学会 先思考、再行动、观察结果、再思考，像人一样解决复杂问题。

    学习目标

    • 理解 ReAct（Reasoning + Acting）的核心思想
    • 实现「思考-行动-观察」的循环
    • 让 Agent 能自主解决多步骤问题
    • 了解反思（Reflection）机制

    1. 什么是 ReAct

    ReAct = Reasoning（推理）+ Acting（行动）。 它的核心是让模型在每一步行动前，先输出一段「思考」，说明为什么要这么做， 然后再执行动作，观察结果，再决定下一步。

    一个 ReAct 的例子

    用户：「北京今天适合跑步吗？」

    Thought: 用户问是否适合跑步，我需要先知道北京今天的天气。
Action: get_weather("北京")
Observation: 晴，25°C，空气质量优

Thought: 天气晴朗、温度适宜、空气质量好，适合跑步。
Action: finish("北京今天晴，25°C，空气质量优，非常适合户外跑步！")

    2. 为什么需要 ReAct

    • 复杂任务：需要多步操作的问题，一步到位容易出错
    • 可解释性：每步都有 Thought，我们能看到 Agent 的思路
    • 纠错能力：观察结果不对，可以重新规划

    3. 实现 ReAct Agent

    我们用一个巧妙的方式实现：在 system prompt 里规定模型的输出格式 （Thought / Action / Observation），然后我们的代码解析 Action 并执行。 

    import os                        # os 模块
import json                      # json 模块
from dotenv import load_dotenv   # 读取 .env
import dashscope                 # 通义千问 SDK

load_dotenv()                    # 加载 .env
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")  # 设置 API Key

# 三引号字符串可以跨行，这里用来写 system prompt，规定模型的输出格式
SYSTEM_PROMPT = """你是一个会思考的 AI 助手。解决问题时，请严格按照以下格式输出：

Thought: （你对当前问题的思考，下一步要做什么）
Action: 函数名(参数)
（等待执行结果）

Observation 会由系统提供。当你认为任务完成时，输出：
Final Answer: （最终答案）

可用工具：
- get_weather(city): 查询城市天气
- calculate(expression): 计算数学表达式

注意：每次只输出一个 Thought 和一个 Action，不要输出 Observation。"""


def get_weather(city):  # 定义查天气工具
    # 用字典.get() 查询，找不到返回"未知"
    return {"北京": "晴 25°C", "上海": "小雨 18°C"}.get(city, "未知")


def calculate(expr):  # 定义计算器工具
    try:
        return str(eval(expr))   # eval 执行表达式，str 转字符串
    except:
        return "计算错误"         # 出错返回提示


# TOOLS 字典把函数名映射到函数对象，方便通过名字调用
TOOLS = {"get_weather": get_weather, "calculate": calculate}

    接下来写循环执行的核心逻辑：

    def run_react(question: str, max_steps: int = 5) -> str:
    # max_steps 默认 5，限制最多思考 5 步，防止死循环
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},  # 系统提示，规定输出格式
        {"role": "user", "content": question},          # 用户的问题
    ]

    # for 循环执行最多 max_steps 次（一步 = 一次思考+行动）
    for step in range(max_steps):
        # 调用模型，让它输出 Thought 和 Action
        response = dashscope.Generation.call(
            model="qwen-turbo",
            messages=messages,
            result_format="message",
        )
        text = response.output.choices[0].message.content  # 取出模型输出文本
        messages.append({"role": "assistant", "content": text})  # 加入对话历史
        print(f"--- 第 {step + 1} 步 ---\n{text}\n")  # 打印当前步

        # 如果模型输出了 Final Answer，说明任务完成，返回答案
        if "Final Answer:" in text:
            return text.split("Final Answer:")[-1].strip()  # 取 Final Answer: 后面的内容

        # 解析 Action 行，执行对应工具
        if "Action:" in text:
            # 列表推导式：把文本按行拆分，找出以 "Action:" 开头的那一行
            action_line = [l for l in text.split("\n") if l.startswith("Action:")][0]
            action = action_line.replace("Action:", "").strip()  # 去掉 "Action:" 前缀
            # 解析函数名：取 "(" 前面的部分
            func_name = action.split("(")[0].strip()
            # 解析参数：取 "(" 和 ")" 之间的内容
            args_str = action[action.index("(") + 1 : action.rindex(")")]
            # 按逗号分割参数，去掉引号和空格
            args = [a.strip().strip('"\'') for a in args_str.split(",")]

            if func_name in TOOLS:  # 如果工具存在
                result = TOOLS[func_name](*args)  # *args 把列表拆开作为参数传入
            else:
                result = f"未知工具：{func_name}"

            obs = f"Observation: {result}"  # 构造观察结果
            messages.append({"role": "user", "content": obs})  # 把观察结果发给模型
            print(obs + "\n")

    # 超过最大步数还没完成，返回提示
    return "未能在规定步数内完成任务。"


if __name__ == "__main__":
    answer = run_react("北京今天适合跑步吗？")
    print("最终答案：", answer)

    4. 执行过程

    --- 第 1 步 ---
Thought: 我需要先查询北京今天的天气情况。
Action: get_weather("北京")

Observation: 晴 25°C

--- 第 2 步 ---
Thought: 北京今天晴，25°C，天气很好，适合跑步。
Final Answer: 北京今天晴，25°C，非常适合户外跑步！

最终答案： 北京今天晴，25°C，非常适合户外跑步！
    关键技巧

    ReAct 的精髓在于让模型输出结构化的思考过程。 我们通过 prompt 约束输出格式，再用代码解析。模型的 Thought 虽然不直接执行， 但它帮助模型「理清思路」，从而做出更准确的 Action。

    5. 反思（Reflection）

    比 ReAct 更进一步的是反思机制：Agent 完成任务后， 再让模型检查自己的回答是否正确，如果有问题就重新来一遍。 

    def reflect(question: str, answer: str) -> bool:
    """让模型反思答案是否正确，返回 True 表示需要重做"""
    # f-string 把 question 和 answer 拼进提示词
    prompt = f"问题：{question}\n我的答案：{answer}\n请判断这个答案是否正确、完整。如果有问题，说明问题在哪；如果正确，回复「OK」。"
    resp = dashscope.Generation.call(
        model="qwen-turbo",
        messages=[{"role": "user", "content": prompt}],
        result_format="message",
    )
    result = resp.output.choices[0].message.content  # 取出反思结果
    print("反思结果：", result)
    return "OK" not in result  # 如果结果不含"OK"，说明有问题，返回 True 需要重做

    6. ReAct 的优缺点

    • 优点：能处理复杂多步任务、过程透明可解释、能纠错
    • 缺点：消耗更多 token（每步都要调用）、速度较慢、可能死循环（需要 max_steps 限制）

    本章小结

    • ReAct = Reasoning + Acting，让 Agent 先思考再行动
    • 核心是「Thought → Action → Observation」循环
    • 通过 prompt 约束输出格式，代码解析并执行 Action
    • 反思机制让 Agent 能自我检查和修正
    • 需要设置最大步数防止死循环
