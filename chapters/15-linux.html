    Linux 系统管理与性能调优

    Linux 是运维工程师的基本功。本章从系统安装配置讲起，带你掌握日常故障排查的思路， 并对 CPU、内存、磁盘、网络四大子系统做性能调优。学完本章，你能应对面试官关于 「系统卡顿怎么办」「CPU 飙高怎么排查」这类高频问题。

    学习目标

    • 掌握 Linux 系统安装与基础配置要点
    • 建立「自上而下、由表及里」的故障排查方法论
    • 熟练使用 top、vmstat、iostat、ss 等排查命令
    • 理解 CPU、内存、磁盘、网络的调优手段

    1. 系统安装与基础配置

    生产环境通常使用 CentOS/RHEL 或 Ubuntu Server。 安装时几个关键选项直接影响后续运维：

    分区规划

    不要把所有数据丢在一个 / 分区。推荐单独划分： /boot（1G）、swap（内存的 1~2 倍，大内存机器可小些）、 /（50G 左右）、/var（日志，给足空间）、 /data（业务数据）。这样日志撑满不会导致系统盘写满而宕机。

    文件系统选择

    通用场景用 XFS（RHEL 默认，大文件性能好）； 小文件多、需要快照可选 ext4； 海量数据可考虑 ZFS（有校验和、快照）。

    网络与主机名

    配置静态 IP、设置有意义的主机名（如 db-prod-01）、 配置 /etc/hosts 或内网 DNS，避免运维时搞混机器。

    1.1 安装后的初始化脚本

    新机器到手，第一件事不是装业务，而是做安全和性能基线：

    #!/bin/bash
# 1. 关闭 SELinux（生产环境按安全策略决定，这里演示）
setenforce 0
sed -i 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config

# 2. 关闭防火墙或放行必要端口（按实际情况）
systemctl stop firewalld
systemctl disable firewalld

# 3. 时间同步（日志排障全靠时间准确）
yum install -y chrony
systemctl enable --now chronyd

# 4. 调整文件描述符上限（高并发必备）
echo '* soft nofile 65535' >> /etc/security/limits.conf
echo '* hard nofile 65535' >> /etc/security/limits.conf

# 5. 关闭 swap（数据库和容器场景强烈建议）
swapoff -a
sed -i '/ swap / s/^/#/' /etc/fstab

# 6. 优化内核参数
cat >> /etc/sysctl.conf << 'EOF'
net.ipv4.tcp_syncookies = 1            # 开启 SYN 洪水保护
net.ipv4.tcp_tw_reuse = 1              # 允许 TIME_WAIT 套接字重用
net.ipv4.tcp_fin_timeout = 30          # 缩短 FIN_WAIT2 超时
net.core.somaxconn = 65535             # 增大监听队列
vm.swappiness = 0                      # 尽量不用 swap
vm.overcommit_memory = 1               # 允许过量分配内存（Redis 需要）
EOF
sysctl -p
    注意

    上面的参数是通用基线，具体值要结合业务调整。比如 tcp_tw_reuse 在 NAT 环境下可能有副作用，生产改动前务必在测试环境验证。

    2. 故障排查方法论

    面试官最爱问「线上服务突然变慢，你怎么排查？」。优秀的运维不是靠猜，而是有一套 自上而下的排查路径：

    排查四步法
    ① 看现象：什么服务、什么时间、什么错误日志
② 定范围：是单机还是集群？是网络还是应用？
③ 查资源：CPU / 内存 / 磁盘 / 网络哪个先异常
④ 定位根因：结合日志和监控，找到具体进程或代码

    2.1 一眼看清系统状态

    登录机器后，先跑这几条命令建立全局认知：

    uptime          # 系统运行时间、1/5/15 分钟平均负载
free -h         # 内存使用
df -h           # 磁盘使用
top -b -n 1 | head -20   # CPU 和进程快照
ss -tnlp        # 监听的端口
dmesg | tail    # 内核日志（硬件/驱动错误）
journalctl -xe --since "10 minutes ago"  # 系统日志
    关于 Load Average

    uptime 显示的三个数字是 1/5/15 分钟平均负载。 它表示「正在运行 + 等待运行 + 不可中断睡眠（D 状态）」的进程数。 判断是否过载要看相对于 CPU 核数：8 核机器 load 到 8 算满， 到 16 就是严重过载。load 持续升高说明系统有瓶颈。

    3. CPU 排查与调优

    3.1 CPU 飙高排查

    用 top 找到占用 CPU 最高的进程，然后深入分析线程：

    # 1. top 找到高 CPU 进程，记录 PID（比如 1234）
top

# 2. 看这个进程的哪些线程占 CPU
top -Hp 1234

# 3. 把线程 PID 转成 16 进制（jstack 需要）
printf '%x\n' 线程PID

# 4. 如果是 Java 进程，用 jstack 定位代码行
jstack 1234 | grep 0x线程ID -A 30

# 5. 如果是 C/C++ 进程，用 perf 或 pstack
perf top -p 1234
pstack 1234 | head -50
    CPU 使用类型

    top 里 %Cpu(s) 行有几个关键值： us（用户态，业务代码）、 sy（内核态，系统调用多）、 wa（等待 IO，通常是磁盘瓶颈）、 si（软中断，网络包多时高）。 wa 高别看 CPU，去查磁盘；si 高去查网络。

    3.2 CPU 调优手段

    • 进程绑核：用 taskset -c 0-3 ./app 把进程绑定到指定核，减少缓存失效。
    • 关闭节能：CPU 频率调速器设为 performance，避免降频。
    • 减少上下文切换：线程数不要远超核数，用 vmstat 1 看 cs 列。
    • IRQ 绑核：网卡中断分散到多核，避免单核被中断打满。

    4. 内存排查与调优

    4.1 内存不够用了怎么办

    free -h
#              total   used   free  shared  buff/cache  available
# Mem:          15Gi   12Gi   1.0Gi   0.1Gi        2.0Gi       2.5Gi
# Swap:         2.0Gi   0Bi   2.0Gi
    别被 free 骗了

    Linux 会把空闲内存拿去做 buff/cache（文件缓存），这是好事。 真正能用的内存看 available 列，它已经算上了可回收的缓存。 只有 available 很低且 swap 开始上涨，才是真的内存不足。

    4.2 定位内存大户

    # 按内存排序找进程
ps aux --sort=-%mem | head -10

# 看某个进程的内存详情（RSS 是实际占用物理内存）
cat /proc/1234/status | grep -E 'VmRSS|VmSize|VmSwap'

# 查 OOM 日志（谁被系统杀掉了）
dmesg | grep -i 'oom\|killed process'
journalctl -k | grep -i oom

    4.3 内存调优

    • 关闭 swap：数据库和容器场景，swap 会导致性能剧烈抖动。
    • 调整 swappiness：vm.swappiness=0 尽量用物理内存。
    • 内存大页：数据库开启 HugePages 减少 TLB miss。
    • 限制 cgroup：用 cgroup 给进程设内存上限，防止单个服务吃光内存。

    5. 磁盘排查与调优

    5.1 磁盘满了

    # 看哪个分区满
df -h

# 找大文件（从根目录开始）
du -h --max-depth=1 / | sort -rh | head -10

# 找超过 1G 的文件
find / -type f -size +1G -exec ls -lh {} \;

# 常见元凶：日志
du -sh /var/log/*
journalctl --disk-usage          # systemd 日志占用
journalctl --vacuum-size=500M    # 清理到 500M
    删除文件后空间没释放

    如果文件被进程打开着，rm 只是删掉了目录项，空间要等进程关闭句柄才释放。 用 lsof | grep deleted 找到占用已删除文件的进程，重启或截断它： truncate -s 0 /proc/进程PID/fd/文件描述符。

    5.2 磁盘慢

    # 看 IO 等待和读写速度
iostat -xz 1

# 关键列：%util（设备繁忙度）、await（平均等待毫秒）、r/s w/s（读写次数）
# %util 接近 100% 说明磁盘打满；await 大于 20ms 说明响应慢

# 看哪个进程在大量读写
iotop -oP

# 查看 inode 是否耗尽（小文件极多的场景）
df -i

    5.3 磁盘调优

    • SSD 优化：开启 TRIM（fstrim），使用 noatime 挂载。
    • IO 调度器：SSD 用 none 或 noop，机械盘用 deadline。
    • 分离读写：日志盘和数据盘分开，redo log 放高速盘。
    • 挂载参数：defaults,noatime,nodiratime 减少元数据写入。

    6. 网络排查与调优

    6.1 网络不通

    # 物理层到应用层逐层排查
ip addr                      # 网卡是否 up、IP 是否正确
ip route                     # 路由是否正确
ping 网关IP                  # 能不能到网关
telnet/ nc -vz 目标IP 端口    # 端口通不通
ss -tnlp | grep 端口         # 服务是否在监听
traceroute 目标IP            # 路由路径
tcpdump -i eth0 port 80      # 抓包看流量

    6.2 连接数爆满

    # 查看各种状态的连接数
ss -ant | awk '{print $1}' | sort | uniq -c | sort -rn

# TIME_WAIT 过多：开启重用
# ESTABLISHED 过多：看是不是被攻击或应用没释放连接
# CLOSE_WAIT 过多：应用没调 close()，是代码 bug

# 查看连接跟踪表是否满
dmesg | grep 'nf_conntrack: table full'

    6.3 网络调优

    • 增大文件描述符：高并发必备，ulimit -n 65535。
    • TIME_WAIT 重用：net.ipv4.tcp_tw_reuse=1。
    • 增大 backlog：net.core.somaxconn=65535。
    • 网卡多队列：开启 RSS/RPS，把网络包分散到多核处理。

    本章小结

    • 系统安装要做好分区、文件系统、网络、安全基线配置。
    • 故障排查遵循「现象 → 范围 → 资源 → 根因」四步法。
    • CPU 看 us/sy/wa/si，wa 高查磁盘，si 高查网络。
    • 内存看 available 不是 free，OOM 查 dmesg。
    • 磁盘满查大文件和已删除但被占用的文件；磁盘慢看 iostat 的 %util。
    • 网络排查从物理层到应用层逐层定位，连接状态分析很重要。
