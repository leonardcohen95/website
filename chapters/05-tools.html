    让 Agent 会用工具

    这是 Agent 区别于普通聊天机器人的关键一步！本章我们学习 Function Calling（函数调用），让 Agent 能调用外部工具， 比如查天气、做计算、读文件。

    学习目标

    • 理解 Function Calling 的原理
    • 学会定义工具（函数）的 schema
    • 实现一个能查天气的 Agent
    • 掌握「模型选择工具 → 执行工具 → 结果回传」的完整流程

    1. 什么是 Function Calling

    Function Calling 是大模型提供的一种能力：你告诉模型有哪些函数可用、 每个函数的参数是什么，模型会根据用户问题自动决定是否调用某个函数、 以及传什么参数。

    工作流程
    用户：北京今天天气怎么样？
   │
   ▼ 模型判断需要调用「查天气」工具，返回函数名和参数
   ▼ { "name": "get_weather", "arguments": {"city": "北京"} }
   │
   ▼ 你的代码执行 get_weather("北京")，拿到结果
   ▼ { "temp": "25°C", "condition": "晴" }
   │
   ▼ 把结果回传给模型
   ▼
模型：北京今天晴，气温 25°C。

    2. 定义工具

    首先，我们写一个真实的函数（工具），再用 JSON Schema 描述它的参数， 让模型知道怎么调用。 

    import json                      # json 模块：解析和生成 JSON 数据
import os                        # os 模块：读取环境变量
from dotenv import load_dotenv   # 读取 .env 文件
import dashscope                 # 通义千问 SDK

load_dotenv()                    # 加载 .env 文件
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")  # 设置 API Key


def get_weather(city: str) -> str:
    """查询指定城市的天气（模拟数据，实际可对接天气 API）"""
    weather_db = {                # 用一个字典模拟天气数据库
        "北京": "晴，25°C",
        "上海": "多云，22°C",
        "广州": "小雨，28°C",
    }
    # dict.get(key, default)：如果 key 存在返回对应值，否则返回 default
    return weather_db.get(city, f"暂无 {city} 的天气数据")


# tools 是工具描述列表，用 JSON Schema 格式告诉模型有哪些工具可用
tools = [
    {
        "type": "function",       # 类型是函数
        "function": {
            "name": "get_weather",                  # 函数名，要和上面的函数一致
            "description": "查询指定城市的当前天气",   # 函数用途描述，模型靠这个判断是否调用
            "parameters": {                          # 参数描述
                "type": "object",
                "properties": {
                    "city": {                        # 参数名 city
                        "type": "string",            # 参数类型是字符串
                        "description": "城市名称，如北京、上海",  # 参数说明
                    }
                },
                "required": ["city"],                # 必填参数列表
            },
        },
    }
]
    JSON Schema 是什么

    JSON Schema 是一种用 JSON 描述数据结构的格式。这里我们用它告诉模型： get_weather 函数需要一个 city 字符串参数。 模型会按照这个格式生成参数，我们再解析出来执行函数。

    3. 实现带工具调用的 Agent

    def chat_with_tools(user_input: str) -> str:
    # 初始化消息列表，包含 system 和 user 两条消息
    messages = [
        {"role": "system", "content": "你是一个助手，必要时调用工具。"},
        {"role": "user", "content": user_input},
    ]

    # 第一次调用模型，传入 tools 告诉它有哪些工具可用
    response = dashscope.Generation.call(
        model="qwen-turbo",
        messages=messages,
        tools=tools,                  # 关键：把工具列表传给模型
        result_format="message",
    )

    msg = response.output.choices[0].message  # 取出模型返回的消息对象

    # hasattr 检查 msg 是否有 tool_calls 属性，且不为空
    if hasattr(msg, "tool_calls") and msg.tool_calls:
        # 遍历模型请求的所有工具调用（可能一次调用多个工具）
        for call in msg.tool_calls:
            func_name = call.function.name          # 取出函数名
            args = json.loads(call.function.arguments)  # 把参数字符串解析成字典
            print(f"模型调用了 {func_name}，参数：{args}")

            # 根据函数名执行对应的 Python 函数
            if func_name == "get_weather":
                result = get_weather(args["city"])

            # 把模型的 tool_call 消息和工具结果都加入 messages
            messages.append(msg)
            messages.append({
                "role": "tool",                # role 为 tool 表示这是工具执行结果
                "tool_call_id": call.id,        # 关联到对应的 tool_call
                "content": result,              # 工具返回的结果
            })

        # 再次调用模型，让它根据工具结果生成自然语言回答
        response = dashscope.Generation.call(
            model="qwen-turbo",
            messages=messages,
            tools=tools,
            result_format="message",
        )
        return response.output.choices[0].message.content

    # 如果模型没有调用工具，直接返回它的回答
    return msg.content


if __name__ == "__main__":
    print(chat_with_tools("北京今天天气怎么样？"))   # 会调用 get_weather 工具
    print(chat_with_tools("1+1等于几？"))            # 不需要工具，模型直接回答

    4. 执行流程拆解

    1. 用户提问 → 发给模型，同时附带可用工具列表
    2. 模型判断：这个问题需要工具吗？
    3. 如果需要，返回 tool_calls（函数名 + 参数）
    4. 我们的代码根据函数名执行对应 Python 函数
    5. 把函数结果以 role: "tool" 的消息发回模型
    6. 模型基于工具结果，生成自然语言回答

    5. 再多加一个工具：计算器

    工具可以有多个，模型会自己选择用哪个：

    def calculate(expression: str) -> str:
    """计算一个数学表达式"""
    try:                               # try 块：尝试执行可能出错的代码
        return str(eval(expression))   # eval 把字符串当代码执行，str() 转成字符串返回
    except Exception as e:             # except 捕获异常，e 是异常对象
        return f"计算错误：{e}"         # 出错时返回错误信息


# tools.append() 往工具列表中追加一个新工具描述
tools.append({
    "type": "function",
    "function": {
        "name": "calculate",                               # 函数名
        "description": "计算数学表达式，如 2+3*4",          # 用途描述
        "parameters": {
            "type": "object",
            "properties": {
                "expression": {"type": "string", "description": "数学表达式"}  # 参数
            },
            "required": ["expression"],                    # 必填参数
        },
    },
})

    然后在 chat_with_tools 中加上分支：

    if func_name == "get_weather":          # 如果模型要调用查天气
    result = get_weather(args["city"])    # 执行 get_weather，传入 city 参数
elif func_name == "calculate":            # 否则如果要调用计算器
    result = calculate(args["expression"])  # 执行 calculate，传入表达式
    安全提醒

    上面的 eval() 能执行任意代码，在真实项目中非常危险。 这里只是演示，生产环境请用 ast.literal_eval 或专门的表达式解析库。

    6. 工具描述的重要性

    模型是否调用工具、传什么参数，完全取决于你写的 description。 描述越清晰，模型调用越准确。

    • 函数名：见名知意，如 get_weather
    • 函数描述：说明这个函数什么时候该用
    • 参数描述：说明每个参数的含义和格式

    本章小结

    • Function Calling 让模型能决定调用哪个外部函数
    • 流程：模型返回函数调用 → 代码执行 → 结果回传 → 模型生成最终回答
    • 工具需要用 JSON Schema 描述名称、参数和用途
    • 可以同时定义多个工具，模型自动选择
