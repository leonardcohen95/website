    多 Agent 协作

    一个 Agent 的能力有限，就像一个人不可能什么都精通。 这一章我们学习多 Agent 协作：让多个各有所长的 Agent 分工合作，完成更复杂的任务。

    学习目标

    • 理解为什么需要多 Agent
    • 掌握常见的多 Agent 协作模式
    • 实现一个「作家 + 编辑」的协作示例
    • 了解主流多 Agent 框架

    1. 为什么需要多个 Agent

    • 专业分工：写作、编程、数据分析各有专长，一个 Agent 难以精通所有领域
    • 质量提升：一个 Agent 写，另一个 Agent 审，互相纠错
    • 并行处理：多个任务同时进行，提高效率
    • 复杂任务：把大任务拆成子任务，分给不同 Agent

    2. 常见协作模式

    流水线（Pipeline）

    Agent 一个接一个处理，前一个的输出是后一个的输入。比如：作家写稿 → 编辑审稿 → 排版发布。

    主从（Boss-Worker）

    一个「老板 Agent」负责拆解任务和分配，多个「工人 Agent」负责执行。

    群聊（Group Chat）

    多个 Agent 在一个对话里自由讨论，像开会一样，最后得出结论。

    3. 实现：作家 + 编辑

    我们用「流水线」模式实现：一个 Agent 写短文，另一个 Agent 审稿并修改。

    import os                          # os 模块
from dotenv import load_dotenv     # 读取 .env
import dashscope                   # 通义千问 SDK

load_dotenv()                      # 加载 .env
dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")  # 设置 API Key


# 这就是你问的那行代码！
# def 定义函数，llm 是函数名
# system_prompt: str 表示第一个参数 system_prompt 是字符串类型
# user_prompt: str 表示第二个参数 user_prompt 也是字符串
# -> str 表示函数返回值是字符串
def llm(system_prompt: str, user_prompt: str) -> str:
    """通用 LLM 调用"""
    # 调用通义千问，传入 system 和 user 两条消息
    response = dashscope.Generation.call(
        model="qwen-turbo",
        messages=[
            {"role": "system", "content": system_prompt},  # system 消息：设定角色
            {"role": "user", "content": user_prompt},      # user 消息：具体任务
        ],
        result_format="message",
    )
    return response.output.choices[0].message.content  # 返回模型回答


# ---- 角色 1：作家 ----
# 常量（全大写）定义作家的人设
WRITER_SYSTEM = "你是一位才华横溢的科普作家，擅长用生动有趣的语言讲解科技知识。"

def writer(topic: str) -> str:  # 作家函数：接收主题，返回文章
    prompt = f"请围绕「{topic}」写一篇 200 字左右的科普短文。"  # 构造写作指令
    return llm(WRITER_SYSTEM, prompt)  # 调用 llm，传入作家人设和指令


# ---- 角色 2：编辑 ----
EDITOR_SYSTEM = """你是一位严格的资深编辑，审稿时关注：
1. 事实是否准确
2. 逻辑是否通顺
3. 语言是否通顺易懂
请直接输出修改后的最终版本，不要解释修改了什么。"""

def editor(draft: str) -> str:  # 编辑函数：接收草稿，返回修改稿
    prompt = f"请审阅并润色以下文章：\n\n{draft}"  # \n 是换行符
    return llm(EDITOR_SYSTEM, prompt)


# ---- 流水线协作 ----
def publish(topic: str) -> str:
    print("【作家】正在写作...")
    draft = writer(topic)  # 第一步：作家写初稿
    print(draft, "\n")  # \n 打印一个空行

    print("【编辑】正在审稿...")
    final = editor(draft)  # 第二步：编辑修改初稿
    print(final, "\n")
    return final  # 返回最终版本


if __name__ == "__main__":
    publish("为什么天空是蓝色的")  # 运行流水线

    5. 更进一步：加入审稿反馈循环

    让编辑不直接改，而是给反馈，作家再根据反馈修改。这样更接近真实的协作。 

    def editor_feedback(draft: str) -> str:
    """编辑只提修改意见，不直接改写"""
    prompt = f"请审阅以下文章，给出具体的修改意见（不超过 3 条）：\n\n{draft}"
    return llm(EDITOR_SYSTEM, prompt)  # 用编辑人设调用模型，返回意见


def writer_revise(topic: str, draft: str, feedback: str) -> str:
    """作家根据反馈修改"""
    # 把主题、原文、编辑意见都放进 prompt
    prompt = f"主题：{topic}\n原文：{draft}\n编辑意见：{feedback}\n请根据意见修改文章。"
    return llm(WRITER_SYSTEM, prompt)  # 用作家人设调用模型，返回修改稿


def publish_with_revision(topic: str, rounds: int = 2):
    draft = writer(topic)  # 作家先写初稿
    for i in range(rounds):  # 循环 rounds 次审稿修改
        print(f"=== 第 {i+1} 轮审稿 ===")
        feedback = editor_feedback(draft)  # 编辑提意见
        print("编辑意见：", feedback)
        draft = writer_revise(topic, draft, feedback)  # 作家根据意见修改
    return draft  # 返回最终稿

    6. 主流多 Agent 框架

    如果你要做更复杂的多 Agent 系统，可以借助成熟框架：

    • LangGraph：LangChain 出品，用图的方式编排 Agent，灵活强大
    • AutoGen：微软出品，支持多 Agent 对话和协作
    • CrewAI：把 Agent 当「船员」，有角色、任务、流程概念
    • MetaGPT：模拟软件公司的角色分工（产品经理、架构师、工程师）
    学习建议

    建议先把本教程前 6 章的原理吃透，再去用框架。 框架只是帮你省掉写调度代码的麻烦，核心还是 LLM、记忆、工具、ReAct 这些概念。 不理解原理直接用框架，出了问题很难调试。

    本章小结

    • 多 Agent 通过分工协作提升质量和效率
    • 常见模式：流水线、主从、群聊
    • 实现核心是：给每个 Agent 不同的 system prompt（角色设定）
    • 成熟框架有 LangGraph、AutoGen、CrewAI 等
