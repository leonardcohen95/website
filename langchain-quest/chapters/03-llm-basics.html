    LLM 基础概念

    在深入 LangChain 之前，我们需要理解大语言模型（LLM）的基本概念。Token、Temperature、上下文窗口、消息格式……这些是用好 LangChain 的基础。

    学习目标

    • 理解 Token 及其对费用和长度的影响
    • 掌握 Temperature、max_tokens、top_p 等生成参数
    • 理解上下文窗口的概念
    • 熟悉 SystemMessage、HumanMessage、AIMessage 消息类型

    1. Token：LLM 的基本单位

    LLM 不是按字符或单词处理文本，而是按 Token。Token 可以是一个完整的单词、词的一部分、标点符号或单个字符。

    • 英文：约 4 个字符 ≈ 1 个 token，100 个 token ≈ 75 个单词
    • 中文：通常 1 个汉字 ≈ 1-2 个 token

    Token 数量直接影响费用（API 按 token 计费）和速度（token 越多生成越慢）。

    💡 估算 token

    可以用 OpenAI 的 tiktoken 库精确计算 token 数：import tiktoken; enc = tiktoken.encoding_for_model("gpt-3.5-turbo"); len(enc.encode("你好世界"))

    2. 生成参数

    🌡️ Temperature（温度）

    控制生成的随机性。0 = 最确定（适合事实问答），1 = 最随机（适合创意写作），默认约 0.7。

    📏 max_tokens（最大生成 token 数）

    限制模型输出的最大长度，避免回复过长或超出上下文窗口。

    🎯 top_p（核采样）

    只从累积概率达到 p 的 token 中采样，控制输出多样性。p=0.1 只选概率最高的，p=1 考虑所有 token。

    3. 上下文窗口

    每个 LLM 都有上下文窗口限制（如 gpt-3.5-turbo 为 16K，gpt-4 为 128K）。输入和输出的 token 总和不能超过该限制，否则会报错。

    这就是为什么长对话需要 Memory 管理（摘要、截断），长文档需要 RAG 检索——都要把内容控制在上下文窗口内。

    4. 消息类型

    LangChain 用不同的消息类表示对话中的不同角色：

    • SystemMessage：系统消息，设定 AI 的角色、语气、行为规则
    • HumanMessage：用户输入的消息
    • AIMessage：AI 回复的消息
    • FunctionMessage / ToolMessage：工具调用的返回结果
    from langchain_core.messages import SystemMessage, HumanMessage

messages = [
    SystemMessage(content="你是一个耐心的编程导师，用中文回答问题。"),
    HumanMessage(content="什么是 Token？")
]
response = llm.invoke(messages)

    本章小结

    • Token 是 LLM 处理文本的基本单位，影响费用和速度
    • Temperature 控制随机性，max_tokens 控制输出长度，top_p 控制多样性
    • 上下文窗口限制输入+输出的总 token 数
    • 消息类型：SystemMessage（角色设定）、HumanMessage（用户）、AIMessage（AI）
