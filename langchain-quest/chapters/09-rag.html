闯关地图

    RAG 检索增强生成

    RAG（Retrieval-Augmented Generation，检索增强生成）是 LLM 应用中最重要的技术之一。它通过检索外部知识来增强 LLM 的回答，解决知识过时和幻觉问题，无需微调即可让 LLM 基于私有数据回答。

    学习目标

    • 理解 RAG 的核心思想和流程
    • 掌握构建 RAG 系统的步骤
    • 使用 RetrievalQA 链实现问答
    • 理解不同的 chain_type（stuff、map_reduce、refine）

    1. RAG 是什么

    RAG 的核心思想：先检索，再生成。用户提问时，先从知识库中检索相关文档，然后将文档内容和问题一起传给 LLM，让 LLM 基于检索结果生成回答。

    2. RAG 的完整流程

    离线（构建知识库）：

    1. 加载文档（Document Loader）
    2. 切分文档（Text Splitter）
    3. 向量化（Embeddings）
    4. 存入向量数据库（VectorStore）

    在线（回答问题）：

    1. 用户提问
    2. 将问题向量化，从向量库检索相关文档
    3. 将检索结果 + 问题拼入 prompt
    4. LLM 生成回答

    3. 用 LangChain 实现 RAG

    from langchain.chains import RetrievalQA
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma

# 1. 构建向量库（离线）
vectorstore = Chroma.from_documents(chunks, OpenAIEmbeddings())

# 2. 创建检索器
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 3. 创建 RAG 链
qa_chain = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(),
    chain_type="stuff",
    retriever=retriever,
    return_source_documents=True
)

# 4. 提问
result = qa_chain.invoke("如何申请退款？")
print(result["result"])
print("来源：", [doc.metadata for doc in result["source_documents"]])

    4. chain_type 详解

    📦 stuff

    将所有检索文档塞入一个 prompt。简单快速，但文档多时会超出上下文窗口。适合文档少的场景。

    🗺️ map_reduce

    先对每个文档单独生成回答（map），再汇总所有回答（reduce）。适合文档多的场景，但调用 LLM 次数多。

    ✨ refine

    逐个文档处理，每次用前一个的回答和当前文档一起 refine 答案。质量高但慢，适合需要精确综合的场景。

    5. RAG 的优势

    • 无需微调：更新知识库即可，不用重新训练
    • 知识实时更新：文档更新后重新向量化即可
    • 减少幻觉：基于检索到的事实回答
    • 可溯源：回答可以附带来源文档
    ⚠️ 注意

    RAG 能显著减少幻觉，但不能完全消除。应在 prompt 中要求 LLM "只基于提供的文档回答，如果文档中没有相关信息就说不知道"。

    本章小结

    • RAG = 检索 + 生成，先检索相关文档再让 LLM 回答
    • 流程：加载→切分→向量化→存储→检索→生成
    • RetrievalQA 是 RAG 的核心链
    • chain_type：stuff（全塞入）、map_reduce（分批汇总）、refine（逐次优化）
