闯关地图

    数据连接

    LLM 应用往往需要处理外部数据：PDF 文档、网页、数据库、CSV 文件……LangChain 提供了 Document Loader 和 Text Splitter 来加载和处理这些数据，为后续的向量化和检索做准备。

    学习目标

    • 使用 Document Loader 加载各种数据源
    • 理解 Document 对象的结构
    • 使用 Text Splitter 切分长文档
    • 掌握 chunk_size 和 chunk_overlap 的调优

    1. Document 对象

    LangChain 用 Document 对象表示一段文本，包含两个核心字段：

    • page_content：文本内容
    • metadata：元数据字典（来源、页码、创建时间等）

    2. 常用 Document Loader

    📄 TextLoader

    加载纯文本文件（.txt）。

    📕 PyPDFLoader

    加载 PDF 文件，每页转为一个 Document，metadata 包含页码。

    🌐 WebBaseLoader / BSHTMLLoader

    加载网页 HTML 并提取文本。

    📊 CSVLoader

    加载 CSV 文件，每行或每列转为 Document。

    from langchain_community.document_loaders import PyPDFLoader, TextLoader, WebBaseLoader

# 加载 PDF
loader = PyPDFLoader("docs/产品手册.pdf")
docs = loader.load()

# 加载网页
loader = WebBaseLoader("https://example.com/docs")
docs = loader.load()

    3. Text Splitter

    长文档需要切分为较小的 chunk，才能向量化和检索。最常用的是 RecursiveCharacterTextSplitter：

    from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每个 chunk 的最大字符数
    chunk_overlap=50,      # 相邻 chunk 的重叠字符数
    separators=["\n\n", "\n", "。", "！", "？", " ", ""]
)
chunks = splitter.split_documents(docs)

    它按分隔符列表递归尝试，尽量在段落、句子边界切分，保持语义完整。

    4. chunk_size 与 chunk_overlap

    • chunk_size：每个文本块的大小。太小会丢失上下文，太大会引入噪声。常见取值 200-1000 字符。
    • chunk_overlap：相邻块的重叠部分，避免关键信息被切断。通常取 chunk_size 的 10%-20%。
    💡 调优建议

    FAQ 类文档：chunk 小一些（200-400），精确匹配
    长文/报告：chunk 大一些（500-1000），保留上下文
    overlap 建议 50-100 字符，确保语义连续

    本章小结

    • Document Loader 加载各种数据源为 Document 对象
    • Document 含 page_content（文本）和 metadata（元数据）
    • RecursiveCharacterTextSplitter 按语义边界切分文档
    • chunk_size 和 chunk_overlap 需要根据文档类型调优
