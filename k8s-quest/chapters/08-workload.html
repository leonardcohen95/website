    其他工作负载

    Deployment 适合无状态应用，但现实中的应用类型多种多样：有需要稳定身份的有状态应用、需要在每个节点运行的守护进程、只执行一次的任务、还有定时运行的任务。K8s 为这些场景分别提供了 StatefulSet、DaemonSet、Job 和 CronJob。本章带你认识这些工作负载并学会选择。

    学习目标

    • 理解 StatefulSet 的特点：稳定网络标识和持久化存储
    • 掌握 DaemonSet 的用途：每个节点运行一个 Pod
    • 学会使用 Job 执行一次性任务
    • 掌握 CronJob 的定时任务配置
    • 能够根据场景选择合适的工作负载类型

    1. StatefulSet —— 有状态应用

    🏛️ StatefulSet

    StatefulSet 用于管理有状态应用，为每个 Pod 提供稳定的网络标识 （固定的 DNS 名称和顺序编号）和稳定的持久化存储。 与 Deployment 不同，StatefulSet 的 Pod 是有序创建和删除的。

    StatefulSet 的 Pod 名称是固定的，格式为 {statefulset-name}-{序号}，例如 mysql-0、mysql-1、mysql-2。

    🔑 StatefulSet 的三大特性

    1. 稳定的网络标识：每个 Pod 有固定的 DNS 名称（需配合 Headless Service）
    2. 稳定的持久化存储：每个 Pod 绑定独立的 PVC，Pod 重建后数据不丢失
    3. 有序部署和伸缩：Pod 按序号顺序创建，删除时逆序进行 

    apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        volumeMounts:
        - name: data
          mountPath: /var/lib/mysql
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 10Gi
    💡 典型应用

    数据库（MySQL、PostgreSQL）、分布式存储（Elasticsearch、Kafka、ZooKeeper）、 主从复制集群等需要稳定身份和存储的应用。

    2. DaemonSet —— 每个节点一个 Pod

    🛡️ DaemonSet

    DaemonSet 确保每个节点上都运行一个 Pod 副本。 当有新节点加入集群时，DaemonSet 会自动在该节点上创建 Pod； 节点离开时，对应的 Pod 会被回收。

    DaemonSet 不需要指定 replicas 数量，Pod 数量等于节点数量（受节点选择器和污点容忍影响）。

    apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluentd
spec:
  selector:
    matchLabels:
      app: fluentd
  template:
    metadata:
      labels:
        app: fluentd
    spec:
      containers:
      - name: fluentd
        image: fluentd:latest
        volumeMounts:
        - name: varlog
          mountPath: /var/log
      volumes:
      - name: varlog
        hostPath:
          path: /var/log
    💡 典型应用

    日志收集 Agent（Fluentd、Filebeat）、节点监控 Agent（Prometheus Node Exporter）、 网络插件（Calico、Flannel）、存储插件等需要在每个节点运行的组件。

    3. Job —— 一次性任务

    📋 Job

    Job 用于执行一次性任务，确保一个或多个 Pod 成功完成任务后退出。 任务完成后，Pod 进入 Completed 状态，不会被重启。

    Job 支持配置完成数（completions）和并行度（parallelism），适合批处理任务。

    apiVersion: batch/v1
kind: Job
metadata:
  name: data-migration
spec:
  completions: 1
  parallelism: 1
  backoffLimit: 3
  template:
    spec:
      containers:
      - name: migrate
        image: myapp:migrate
        command: ['python', 'migrate.py']
      restartPolicy: OnFailure
    🔑 Job 的关键参数

    • completions：需要成功完成的 Pod 数量
    • parallelism：同时运行的 Pod 数量
    • backoffLimit：失败重试次数上限
    • restartPolicy：必须为 OnFailure 或 Never（不能是 Always）

    4. CronJob —— 定时任务

    ⏰ CronJob

    CronJob 基于时间调度 Job，类似 Linux 的 crontab。 你可以设置定时规则，让 K8s 按计划自动创建和运行 Job。

    CronJob 使用标准的 5 段 cron 表达式来定义调度时间：

    apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup
spec:
  schedule: "0 2 * * *"      # 每天凌晨 2 点
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: backup:latest
            command: ['sh', '-c', 'backup.sh']
          restartPolicy: OnFailure
    🕐 Cron 表达式速查

    分 时 日 月 周，例如：
    • 0 2 * * *：每天凌晨 2 点
    • */5 * * * *：每 5 分钟
    • 0 0 1 * *：每月 1 号凌晨
    • 0 9 * * 1-5：工作日每天 9 点

    ⚠️ CronJob 的注意点

    • 默认时区为 UTC，需注意时区差异
    • concurrencyPolicy 控制是否允许任务并发执行（Allow / Forbid / Replace）
    • 建议设置 startingDeadlineSeconds 防止任务延迟堆积

    5. 工作负载选型对比

    面对不同的应用场景，如何选择合适的工作负载？下表可以帮你快速决策：

    📊 四种工作负载对比

    Deployment：无状态应用，需要滚动更新和回滚（Web 服务、API 服务）

    StatefulSet：有状态应用，需要稳定网络标识和存储（数据库、Kafka）

    DaemonSet：每个节点运行一个 Pod（日志收集、监控 Agent、网络插件）

    Job：一次性任务，完成后退出（数据迁移、批处理、计算任务）

    CronJob：定时任务，按计划运行（定时备份、报表生成、清理任务）

    本章小结

    • StatefulSet 适合有状态应用，提供稳定网络标识和持久化存储，Pod 有序创建和删除
    • DaemonSet 确保每个节点运行一个 Pod，常用于日志、监控、网络插件
    • Job 执行一次性任务，完成后退出，支持 completions 和 parallelism
    • CronJob 按 cron 表达式定时运行 Job，类似 crontab
    • 选型口诀：无状态 Deployment，有状态 StatefulSet，每节点 DaemonSet，一次性 Job，定时 CronJob
