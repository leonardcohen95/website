    Deployment 部署

    Deployment 是 Kubernetes 中最常用的工作负载控制器。它管理 Pod 的副本数量，确保你的应用始终以期望的状态运行，并支持滚动更新、回滚、暂停等高级部署能力。掌握 Deployment，你就能从容应对应用的发布和变更。

    学习目标

    • 理解 Deployment 的作用：管理 Pod 副本，维持期望状态
    • 掌握滚动更新的工作原理和参数配置
    • 学会使用 kubectl rollout 进行回滚、暂停、恢复
    • 区分 RollingUpdate 和 Recreate 两种部署策略
    • 理解 maxSurge 和 maxUnavailable 参数的含义
    • 学会查看 rollout status 和 history

    1. Deployment 是什么

    🚀 Deployment

    Deployment 用于声明式地管理 Pod 副本。你只需声明"我要 3 个 nginx Pod"， Deployment 就会通过 ReplicaSet 确保始终有 3 个 Pod 在运行——Pod 挂了会自动重建， 多了会自动删除。

    Deployment 底层依赖 ReplicaSet（副本集）来控制 Pod 数量， 日常使用中你几乎不需要直接操作 ReplicaSet，Deployment 会帮你管理。 

    apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deploy
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
    💡 三层关系

    Deployment → ReplicaSet → Pod
    Deployment 管理多个 ReplicaSet（每个版本对应一个 RS），ReplicaSet 管理一组 Pod 副本。 回滚本质上就是切换到旧版本的 ReplicaSet。

    2. 滚动更新

    当你更新 Deployment 的 Pod 模板（比如修改镜像版本）时，K8s 会触发一次滚动更新， 逐个替换旧 Pod，实现零停机发布。

    🔄 滚动更新流程（以 3 副本为例）

    1. 创建新版本的 ReplicaSet
    2. 逐步增加新 RS 的 Pod 数量，同时减少旧 RS 的 Pod 数量
    3. 每一步都会等待新 Pod 就绪（readinessProbe 通过）才继续
    4. 直到所有 Pod 都替换为新版本，旧 RS 被保留（用于回滚） 

    # 更新镜像版本，触发滚动更新
kubectl set image deployment/nginx-deploy nginx=nginx:1.26

# 实时查看滚动更新进度
kubectl rollout status deployment/nginx-deploy

    3. 部署策略：RollingUpdate 与 Recreate

    Deployment 支持两种部署策略，通过 strategy.type 字段指定：

    🔄 RollingUpdate（默认）

    滚动更新，逐个替换 Pod，更新过程中服务不中断。 这是默认策略，适用于大多数无状态应用。

    💥 Recreate

    先杀掉所有旧 Pod，再创建新 Pod。更新过程中服务会短暂中断。 适用于不允许同时运行两个版本的场景（如数据库迁移、单实例应用）。 

    strategy:
  type: Recreate
    ⚠️ Recreate 的风险

    Recreate 策略会导致服务在更新期间完全不可用。除非你的应用明确不允许多版本共存， 否则建议始终使用 RollingUpdate。

    4. maxSurge 与 maxUnavailable

    RollingUpdate 策略下，有两个关键参数控制更新的节奏和可用性：

    📈 maxSurge

    更新过程中最多可以比期望副本数多出多少个 Pod。 可以是绝对值（如 1）或百分比（如 25%）。默认值为 25%。 maxSurge 越大，更新速度越快，但消耗的资源也越多。

    📉 maxUnavailable

    更新过程中最多允许多少个 Pod 不可用。 可以是绝对值（如 1）或百分比（如 25%）。默认值为 25%。 maxUnavailable 越小，服务可用性越高，但更新速度越慢。 

    strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1          # 最多多 1 个 Pod
    maxUnavailable: 0    # 不允许任何 Pod 不可用（零停机）
    💡 参数组合建议

    • maxSurge: 1, maxUnavailable: 0：最稳妥，始终保证全部副本可用，更新稍慢
    • maxSurge: 25%, maxUnavailable: 25%：默认配置，平衡速度与可用性
    • maxSurge: 100%, maxUnavailable: 0：先全部启动新版本，再关闭旧版本

    5. 回滚

    如果新版本有问题，Deployment 支持快速回滚到上一个版本或任意历史版本。 

    # 回滚到上一个版本
kubectl rollout undo deployment/nginx-deploy

# 查看历史版本
kubectl rollout history deployment/nginx-deploy

# 回滚到指定版本（revision 编号）
kubectl rollout undo deployment/nginx-deploy --to-revision=2
    📜 版本历史的保留

    Deployment 默认保留最近 10 个 ReplicaSet 版本（通过 revisionHistoryLimit 配置）。 每个版本对应一次 Pod 模板变更。回滚时只需切换到对应的旧 ReplicaSet 即可。

    6. 暂停与恢复

    有时候你需要连续修改多个字段，但不希望每改一次就触发一次滚动更新。 这时可以先暂停 Deployment，修改完毕后再恢复。 

    # 暂停滚动更新
kubectl rollout pause deployment/nginx-deploy

# 暂停期间可以多次修改而不触发更新
kubectl set image deployment/nginx-deploy nginx=nginx:1.27
kubectl set resources deployment/nginx-deploy -c=nginx --limits=cpu=500m

# 恢复滚动更新（此时才会真正执行一次更新）
kubectl rollout resume deployment/nginx-deploy
    💡 为什么需要暂停

    如果不暂停，每执行一次 kubectl set 命令就会触发一次滚动更新， 多次修改会导致多次滚动更新。暂停后批量修改，再恢复，可以只触发一次更新。

    7. 状态查看

    K8s 提供了多个命令来查看 Deployment 的更新状态和历史：

    # 查看滚动更新状态（阻塞直到完成）
kubectl rollout status deployment/nginx-deploy

# 查看更新历史
kubectl rollout history deployment/nginx-deploy

# 查看 Deployment 详情（包括事件）
kubectl describe deployment nginx-deploy

# 查看 ReplicaSet
kubectl get rs
    🔍 常用排查命令

    • kubectl get deploy：查看 Deployment 副本数（DESIRED / CURRENT / UP-TO-DATE / AVAILABLE）
    • kubectl get pods：查看 Pod 状态
    • kubectl rollout history：查看版本变更记录
    • kubectl describe deploy：查看事件和错误信息

    本章小结

    • Deployment 管理 Pod 副本，通过 ReplicaSet 确保期望数量运行
    • 滚动更新逐个替换 Pod，实现零停机发布
    • kubectl rollout undo 可以回滚到上一个或指定版本
    • 策略有 RollingUpdate（默认，逐个替换）和 Recreate（先删后建，会中断）
    • maxSurge 控制最多多出的 Pod 数，maxUnavailable 控制最多不可用的 Pod 数
    • kubectl rollout pause/resume 可以暂停和恢复滚动更新
    • kubectl rollout status/history 查看更新状态和历史版本
