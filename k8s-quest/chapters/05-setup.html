    搭建本地集群

    光说不练假把式。本章我们会真正动手，用 minikube 在本地搭建一个单节点 K8s 集群，然后部署你的第一个应用并访问它。完成本章后，你就拥有了一个可以随时练习的本地 K8s 环境。

    学习目标

    • 了解 minikube 和 kind 两种本地集群工具
    • 成功安装并启动 minikube 集群
    • 用 kubectl 验证集群状态
    • 部署第一个应用并暴露服务
    • 通过 minikube service 访问应用

    1. 本地集群工具：minikube 与 kind

    在本地机器上跑一个完整的 K8s 集群有多种方案，最常用的有两个：

    🐳 minikube

    官方推荐的本地 K8s 工具，在虚拟机或容器里运行一个单节点集群。 功能丰富，支持多种驱动（VirtualBox、Docker、KVM 等）， 还自带 dashboard、ingress 等插件，非常适合初学者。

    🎯 kind

    Kubernetes IN Docker 的缩写，把整个集群跑在 Docker 容器里。 启动极快、资源占用小，适合 CI/CD 场景和高级用户。 但功能插件不如 minikube 丰富。

    💡 本教程选择 minikube

    minikube 对新手最友好，文档齐全，一条命令就能拉起集群。 本章后续操作全部基于 minikube。

    2. 安装 minikube

    安装前请确保你的机器上已安装 Docker（或其他支持的容器/虚拟化驱动）。以下是常见系统的安装方式：

    # macOS（Homebrew）
brew install minikube

# Windows（Chocolatey）
choco install minikube

# Linux（直接下载二进制）
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube

# 验证安装
minikube version
    ⚠️ 前置依赖

    minikube 默认使用 Docker 驱动，所以请先安装并启动 Docker Desktop。 如果你的系统不支持 Docker，也可以选择 VirtualBox、Hyper-V 等驱动。

    3. 启动集群 —— minikube start

    # 启动集群（默认使用 Docker 驱动）
minikube start

# 指定驱动和资源（可选）
minikube start --driver=docker --cpus=2 --memory=4096

# 查看集群状态
minikube status

    首次启动会下载 K8s 组件镜像，需要等待几分钟。启动成功后，你会看到 "Done! kubectl is now configured to use ..." 的提示。

    4. 验证集群 —— kubectl get nodes

    集群启动后，用 kubectl 确认节点状态。一个健康的单节点集群应该显示如下：

    # 查看节点状态
kubectl get nodes

# 预期输出（STATUS 为 Ready 表示正常）
# NAME       STATUS   ROLES           AGE   VERSION
# minikube   Ready    control-plane   2m    v1.30.0

# 查看系统命名空间下的 Pod，确认核心组件正常运行
kubectl get pods -n kube-system
    ✅ 健康检查清单

    节点 STATUS = Ready ✅
    kube-system 下的 Pod 全部 Running ✅
    满足这两个条件，就说明你的本地集群就绪了！

    5. 部署第一个应用

    现在让我们用经典的 nginx 镜像部署第一个应用。一条命令搞定：

    # 创建一个名为 nginx 的 Deployment，使用 nginx 镜像
kubectl create deployment nginx --image=nginx

# 查看 Deployment 和 Pod 状态
kubectl get deploy
kubectl get pods

    等待 Pod 的 STATUS 变为 Running，说明应用已成功部署。

    6. 暴露服务并访问

    Pod 跑起来了，但默认只能在集群内部访问。要从外部访问，需要创建一个 Service：

    # 将 nginx Deployment 暴露为 NodePort 类型的 Service，端口 80
kubectl expose deployment nginx --type=NodePort --port=80

# 查看 Service
kubectl get svc

# 用 minikube 打开浏览器访问服务（自动获取 NodePort 并打开）
minikube service nginx

    执行 minikube service nginx 后，会自动打开浏览器，你就能看到 nginx 的欢迎页面了！🎉

    🧹 清理环境

    练习完毕后，可以清理资源：
    kubectl delete deployment nginx
    kubectl delete svc nginx
    或者直接停掉集群：minikube stop，下次用 minikube start 再启动。

    本章小结

    • minikube 是本地搭建 K8s 集群的首选工具，kind 适合 CI 场景
    • minikube start 一键启动集群，minikube status 查看状态
    • kubectl get nodes 验证节点是否 Ready
    • kubectl create deployment 部署应用
    • kubectl expose 暴露服务，minikube service 访问应用
