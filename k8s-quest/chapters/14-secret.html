    Secret 密钥

    上一章我们学习了 ConfigMap，但它不适合存储敏感信息。Kubernetes 提供了 Secret 专门用于管理密码、Token、证书等敏感数据。Secret 与 ConfigMap 的使用方式非常相似，但它对数据做了 base64 编码，并且在节点上以 tmpfs（内存文件系统）存储，相对更安全。本章我们来学习 Secret 的类型、创建与使用。

    学习目标

    • 理解 Secret 的作用及其与 ConfigMap 的区别
    • 掌握 Secret 的常用类型（Opaque、dockerconfigjson、tls）
    • 理解 base64 编码并非加密
    • 掌握 Secret 的两种使用方式（环境变量、Volume 挂载）
    • 了解生产环境中 Secret 管理的最佳实践

    1. Secret 是什么

    Secret 是 Kubernetes 中用于存储敏感信息的对象，例如数据库密码、API Token、TLS 证书等。与 ConfigMap 类似，Secret 也以键值对形式存储数据，但它的值是经过 base64 编码的。

    ⚠️ base64 不是加密！

    Secret 中的数据只是做了 base64 编码，并非加密。 任何人拿到编码后的值都可以轻松解码。因此 Secret 只是"避免明文直接可见"， 真正的安全性需要配合 RBAC、加密 etcd、外部密钥管理系统等手段。

    2. Secret 的类型

    Secret 有多种类型，常用的有以下几种：

    🔑 Opaque

    默认类型，用于存储任意的键值对数据。用户需要自行对值进行 base64 编码。 这是最常用的类型，适用于密码、token 等通用敏感数据。

    🐳 kubernetes.io/dockerconfigjson

    用于存储私有 Docker 镜像仓库的认证信息（.dockerconfigjson）。 Pod 通过 imagePullSecrets 引用它来拉取私有镜像。

    🔐 kubernetes.io/tls

    用于存储 TLS 证书和私钥。数据中必须包含 tls.crt（证书）和 tls.key（私钥）两个键。 常用于 Ingress 的 HTTPS 配置。

    3. 创建 Secret

    方式一：从字面量创建（Opaque）

    kubectl create secret generic db-secret \
  --from-literal=username=admin \
  --from-literal=password=S3cretPass!

    方式二：从文件创建

    # 从文件创建，文件名作为键，文件内容作为值
kubectl create secret generic app-secret \
  --from-file=username.txt \
  --from-file=password.txt

# 创建 dockerconfigjson 类型的 Secret（用于拉取私有镜像）
kubectl create secret docker-registry regcred \
  --docker-server=registry.example.com \
  --docker-username=myuser \
  --docker-password=mypassword \
  --docker-email=myuser@example.com

# 创建 TLS 类型的 Secret
kubectl create secret tls tls-secret \
  --cert=tls.crt \
  --key=tls.key

    方式三：从 YAML 定义创建

    apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
data:
  username: YWRtaW4=          # "admin" 的 base64 编码
  password: UzNjcmV0UGFzcyE=  # "S3cretPass!" 的 base64 编码
    💡 如何生成 base64

    echo -n "admin" | base64 → YWRtaW4=
    解码：echo "YWRtaW4=" | base64 -d
    注意使用 -n 避免换行符被编码进去。

    4. 使用 Secret

    Secret 的使用方式与 ConfigMap 基本相同。

    方式一：作为环境变量注入

    apiVersion: v1
kind: Pod
metadata:
  name: pod-secret-env
spec:
  containers:
  - name: app
    image: nginx
    env:
    - name: DB_USERNAME
      valueFrom:
        secretKeyRef:
          name: db-secret
          key: username
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-secret
          key: password

    方式二：作为 Volume 挂载

    apiVersion: v1
kind: Pod
metadata:
  name: pod-secret-volume
spec:
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: secret-volume
      mountPath: /etc/secret
      readOnly: true
  volumes:
  - name: secret-volume
    secret:
      secretName: db-secret
    💡 Volume 挂载的安全优势

    Secret 以 Volume 方式挂载时，数据存储在节点的 tmpfs（内存文件系统）中， 不会写入磁盘。Pod 删除时 tmpfs 也会被清除，比环境变量方式更安全。

    方式三：作为 imagePullSecrets 拉取私有镜像

    apiVersion: v1
kind: Pod
metadata:
  name: pod-private-image
spec:
  containers:
  - name: app
    image: registry.example.com/myapp:v1
  imagePullSecrets:
  - name: regcred        # 引用 dockerconfigjson 类型的 Secret

    5. Secret vs ConfigMap

    对比项ConfigMapSecret
    用途非敏感配置敏感信息（密码、token、证书）
    存储形式明文base64 编码
    Volume 挂载磁盘文件tmpfs（内存）
    特殊类型无dockerconfigjson、tls 等

    6. 生产环境建议

    • 不要把 Secret 提交到 Git 仓库：即使是 base64 编码，也等于明文。
    • 启用 etcd 加密：配置 EncryptionConfiguration，让 Secret 在 etcd 中以加密形式存储。
    • 使用外部密钥管理系统：如 HashiCorp Vault、AWS Secrets Manager、阿里云 KMS 等，通过 External Secrets Operator 等工具同步到 K8s。
    • 遵循最小权限原则：通过 RBAC 严格限制谁能读取 Secret。

    本章小结

    • Secret 用于存储敏感信息（密码、token、证书），值以 base64 编码存储
    • 常用类型：Opaque（通用）、kubernetes.io/dockerconfigjson（镜像仓库认证）、kubernetes.io/tls（TLS 证书）
    • base64 是编码不是加密，不要误以为 Secret 绝对安全
    • 使用方式：环境变量注入、Volume 挂载（tmpfs，更安全）、imagePullSecrets
    • 生产环境建议：etcd 加密 + 外部密钥管理系统 + RBAC 最小权限
