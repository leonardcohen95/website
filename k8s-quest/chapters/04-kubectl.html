    kubectl 入门

    kubectl 是与 Kubernetes 集群交互的命令行工具，可以理解为 K8s 的"遥控器"。无论是查看资源、创建应用还是排查问题，都离不开它。本章带你掌握 kubectl 的核心命令和使用套路。

    学习目标

    • 掌握 kubectl 命令的基本语法结构
    • 熟练使用 get、describe、create、apply、delete 等核心命令
    • 了解 logs、exec 用于排查和调试 Pod
    • 理解 namespace 的概念和用法
    • 记住常用资源类型的缩写

    1. kubectl 命令语法

    kubectl 命令遵循一个统一的语法模式：

    kubectl [action] [resource] [name] [flags]
    • action（动作）：你想做什么，如 get、describe、create、delete
    • resource（资源类型）：操作的对象，如 pods、deployments、services
    • name（资源名称）：可选，指定具体某个资源，不填则列出全部
    • flags（参数）：可选，如 -n 指定命名空间、-o wide 输出更多信息
    💡 小技巧

    资源类型可以用缩写：pods → pod，deployments → deploy，services → svc， configmaps → cm，secrets → secret，namespaces → ns。熟练使用缩写能大幅提高效率。

    2. 查看资源 —— get 与 describe

    kubectl get —— 列出资源

    最常用的命令，用于查看资源列表。后面的章节你会频繁用到它。

    # 查看所有 Pod
kubectl get pods

# 查看所有 Deployment（用缩写 deploy）
kubectl get deploy

# 查看所有 Service
kubectl get svc

# 查看更详细的信息（如 Pod 所在节点、IP）
kubectl get pods -o wide

# 以 YAML 格式查看某个 Pod 的完整定义
kubectl get pod my-pod -o yaml

# 查看所有命名空间的 Pod
kubectl get pods -A

    kubectl describe —— 查看资源详情

    get 看概览，describe 看详情。describe 会展示资源的完整描述、事件（Events）等，是排查问题的利器。

    # 查看某个 Pod 的详情和事件
kubectl describe pod my-pod

# 查看某个节点的详情
kubectl describe node node-1

    3. 创建与更新资源 —— create 与 apply

    kubectl create —— 直接创建

    通过命令行参数或 YAML 文件创建资源。如果资源已存在会报错。

    # 用命令直接创建一个 Deployment
kubectl create deployment nginx --image=nginx

# 从 YAML 文件创建
kubectl create -f nginx-deploy.yaml

    kubectl apply —— 声明式创建/更新

    apply 是声明式的：你告诉 K8s"我期望的状态是什么"，K8s 会自动对比并调整。如果资源不存在就创建，已存在就更新。这是生产环境的推荐做法。

    # 根据 YAML 文件创建或更新资源
kubectl apply -f nginx-deploy.yaml

# 应用整个目录下的所有 YAML
kubectl apply -f ./manifests/
    create vs apply

    create：命令式，只能创建，已存在会报错。
    apply：声明式，可创建也可更新，幂等（多次执行结果相同）。
    日常开发和生产环境推荐用 apply。

    4. 删除资源 —— delete

    # 删除一个 Pod
kubectl delete pod my-pod

# 删除一个 Deployment
kubectl delete deploy nginx

# 按 YAML 文件删除对应资源
kubectl delete -f nginx-deploy.yaml

    5. 调试与排障 —— logs 与 exec

    kubectl logs —— 查看容器日志

    Pod 运行不正常时，第一时间看日志。

    # 查看 Pod 日志
kubectl logs my-pod

# 持续跟踪日志（类似 tail -f）
kubectl logs -f my-pod

# 多容器 Pod 指定容器名
kubectl logs my-pod -c main-container

    kubectl exec —— 进入容器

    类似 docker exec，可以在运行中的容器里执行命令，进入交互式 shell 调试。

    # 进入容器的交互式 shell
kubectl exec -it my-pod -- /bin/sh

# 在容器内执行单条命令
kubectl exec my-pod -- ls /app
    ⚠️ 注意 -- 的含义

    exec 命令中，-- 后面的内容会原样传给容器内的命令。 务必加上 -it 才能进入交互式终端（i=输入，t=终端）。

    6. 命名空间（Namespace）

    Namespace 是 K8s 用来隔离资源的逻辑分组机制。不同命名空间里的资源互相不可见， 适合用来区分不同的环境（dev、staging、prod）或不同的团队。 

    # 查看所有命名空间
kubectl get ns

# 创建一个命名空间
kubectl create namespace dev

# 在指定命名空间中操作资源（加 -n 参数）
kubectl get pods -n dev
kubectl apply -f nginx.yaml -n dev

# 不指定 -n 时，默认使用 default 命名空间
    🏷️ 常用资源类型速查

    pod（pods）、deploy（deployments）、svc（services）、cm（configmaps）、 secret（secrets）、ns（namespaces）、node（nodes）、rs（replicasets）、 pvc（persistentvolumeclaims）、ing（ingresses）。

    本章小结

    • kubectl 命令语法：kubectl [action] [resource] [name] [flags]
    • get 看列表，describe 看详情，是最常用的两个查询命令
    • create 是命令式创建，apply 是声明式创建/更新，推荐用 apply
    • logs 看日志，exec 进容器，是排查问题的利器
    • namespace 用于逻辑隔离资源，用 -n 指定
