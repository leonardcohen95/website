闯关地图

    核心概念速览

    上一章我们了解了 K8s 的"硬件"架构。这一章，我们来认识 K8s 的"软件"概念——也就是你会天天打交道的那些 API 对象：Pod、Deployment、Service、ConfigMap、Secret、Volume。掌握这些，才算真正入门 K8s。

    学习目标

    • 理解 Pod 是 K8s 最小的部署单元
    • 掌握 Deployment 管理 Pod 副本和滚动更新的能力
    • 了解 Service 如何提供服务发现和负载均衡
    • 知道 ConfigMap 与 Secret 的用途区别
    • 理解 Volume 解决容器数据持久化的问题

    1. Pod —— 最小部署单元

    🫛 Pod

    Pod 是 Kubernetes 中最小的部署单元。一个 Pod 包含一个或多个紧密协作的容器， 它们共享网络命名空间（同一个 IP 和端口空间）和存储卷。 K8s 不直接管理容器，而是管理 Pod。

    通常我们一个 Pod 只放一个容器，但在某些场景（如 sidecar 模式）下， 一个 Pod 会包含多个容器，比如一个主应用容器 + 一个日志采集容器。

    🌰 类比

    Pod 就像一个"豆荚"，里面装着一颗或多颗"豆子"（容器）。 同一个豆荚里的豆子共享水分和养分（共享网络和存储）。 K8s 调度的最小单位是豆荚，而不是豆子。

    2. Deployment —— Pod 的管理者

    🚀 Deployment

    Deployment 用于管理 Pod 的副本数量并支持滚动更新。 你声明"我要 3 个副本"，Deployment 就会确保始终有 3 个 Pod 在运行； 你更新镜像版本，它会逐个替换旧 Pod，实现零停机发布。

    Deployment 底层通过 ReplicaSet 来控制 Pod 副本数，日常使用中你几乎不需要直接操作 ReplicaSet。

    🔄 滚动更新的工作方式

    假设你有 3 个 Pod 运行着 v1 版本。当你把镜像更新为 v2 时，Deployment 会：
    1. 先启动 1 个 v2 的 Pod
    2. 确认 v2 Pod 正常后，杀掉 1 个 v1 的 Pod
    3. 重复上述过程，直到所有 Pod 都变成 v2
    整个过程服务不中断，出问题还能一键回滚到 v1。

    3. Service —— 服务发现与负载均衡

    🌐 Service

    Pod 的 IP 是会变的（重启、迁移后 IP 就变了），直接访问 Pod IP 不靠谱。 Service 为一组 Pod 提供一个固定的访问入口（ClusterIP）， 并对这组 Pod 进行负载均衡。其他服务只需访问 Service 的名字或 IP， 无需关心后端 Pod 的变化。

    Service 通过 Label Selector 来选择后端 Pod——只要 Pod 的标签匹配，就会被纳入这个 Service 的负载均衡池。

    🏷️ 标签（Label）的魔力

    K8s 用 Label（键值对，如 app=nginx）来组织和选择对象。 Service 就是靠 Label Selector 找到它要代理的 Pod。 这是一种解耦的设计：Service 和 Pod 之间没有硬编码的关联，全靠标签匹配。

    4. ConfigMap 与 Secret —— 配置管理

    把配置写死在镜像里是反模式。K8s 提供了两种对象来管理配置：

    ⚙️ ConfigMap

    用于存储非敏感的配置信息，如环境变量、配置文件内容。 可以挂载到 Pod 中作为环境变量或文件使用，实现配置与镜像分离。

    🔐 Secret

    用于存储敏感信息，如密码、API Key、TLS 证书。 用法与 ConfigMap 类似，但数据以 base64 编码存储（注意：这不是加密，生产环境应配合 RBAC 和加密机制）。

    5. Volume —— 数据持久化

    💾 Volume

    容器里的文件系统是临时的，容器一删数据就没了。 Volume 提供持久化存储，它挂载到 Pod 中， 容器可以在 Volume 里读写数据，即使容器销毁重建，数据依然保留。

    Volume 支持多种后端：emptyDir（Pod 内临时共享）、hostPath（节点本地目录）、NFS、云存储等。

    ⚠️ emptyDir 的注意点

    emptyDir 类型的 Volume 虽然能让 Pod 内多个容器共享数据， 但它的生命周期和 Pod 绑定——Pod 被删除时，emptyDir 里的数据也会被清除。 要真正持久化，需要用持久卷（PV/PVC，后续章节讲解）。

    本章小结

    • Pod 是 K8s 最小部署单元，可含一个或多个容器
    • Deployment 管理 Pod 副本数量，支持滚动更新和回滚
    • Service 为一组 Pod 提供固定访问入口和负载均衡，靠 Label Selector 匹配
    • ConfigMap 管普通配置，Secret 管敏感配置
    • Volume 解决容器数据持久化问题
