    K8s 架构总览

    要玩转 Kubernetes，首先得搞懂它的"骨架"。本章我们用一个生动的港口类比，带你理解 K8s 的整体架构：谁是调度中心，谁是干活的货船，以及它们各自装了什么组件。

    学习目标

    • 理解 Master 节点与 Node 节点的分工
    • 掌握控制平面与数据平面的概念
    • 说出核心组件 kube-apiserver、etcd、kube-scheduler、kube-controller-manager 的作用
    • 了解 Node 上的 kubelet、kube-proxy、container runtime

    1. 一个集群 = 两种节点

    一个 Kubernetes 集群（Cluster）由两类节点组成：

    • Master 节点（控制平面 / Control Plane）：集群的"大脑"，负责全局决策和调度，不直接跑用户的业务容器。
    • Node 节点（数据平面 / Data Plane）：真正干活的"工人"，运行你的应用容器。
    🏗️ 港口类比

    把 K8s 集群想象成一个大型港口：
    Master = 港口调度中心。调度员在办公楼里看全局地图，决定哪艘船停哪个泊位、装卸什么货。
    Node = 停靠的货船。每艘船上装着集装箱（容器），按照调度中心的指令装卸货物。
    你（运维人员）只需要向调度中心下指令，具体怎么执行由它协调各个货船完成。

    2. Master 节点（控制平面）的核心组件

    控制平面由 4 个核心组件组成，它们协同工作，让整个集群有序运转。

    🚪 kube-apiserver

    集群的唯一入口。所有操作（kubectl 命令、组件间通信）都要经过 API Server，它负责认证、鉴权和校验请求。它是控制平面的"前台接待"。

    💾 etcd

    集群的"数据库"，保存整个集群的状态数据（节点、Pod、配置等）。它是一个高可用的分布式键值存储，API Server 的数据都来自这里。

    📋 kube-scheduler

    调度器。负责把新创建的 Pod 分配到合适的 Node 上。它会综合考虑资源需求、亲和性、污点等因素，就像港口调度员安排货船泊位。

    ⚙️ kube-controller-manager

    控制器管理器。运行各种 Controller，不断把集群的"实际状态"调整到"期望状态"。比如 Pod 挂了自动拉起、节点异常时迁移 Pod。

    💡 记忆口诀

    API Server 管入口，etcd 管存储，Scheduler 管分配，Controller 管纠偏。 四者各司其职，共同构成集群的"大脑"。

    3. Node 节点（数据平面）的核心组件

    每个 Node 上运行着 3 个核心组件，负责真正地跑容器和管理网络。

    👷 kubelet

    Node 上的"管家"。它接收 API Server 下发的指令，确保本节点上的容器正常运行。它会周期性地向 Master 汇报节点状态和 Pod 状态。

    🌐 kube-proxy

    Node 上的"网络代理"。它在每个节点上维护网络规则，实现 Service 的负载均衡和服务发现，让集群内部的网络通信畅通无阻。

    📦 Container Runtime

    容器运行时，真正负责创建和运行容器的底层软件。常见的有 containerd、CRI-O 等。Docker 曾经是主流，现在已被 containerd 取代。

    4. 控制平面 vs 数据平面

    理解了两类节点和它们的组件，就不难理解"控制平面"和"数据平面"这两个概念了：

    • 控制平面（Control Plane）：= Master 节点的所有组件。负责"做决策"——调度、管理、监控整个集群。
    • 数据平面（Data Plane）：= 所有 Node 节点。负责"执行决策"——真正运行容器、处理流量。
    ⚠️ 生产环境提醒

    生产环境中，控制平面通常由 3 个或更多 Master 节点组成高可用集群（etcd 需要奇数节点来选举 Leader）。 测试环境可以把控制平面和数据平面放在同一台机器上（比如 minikube）。

    本章小结

    • K8s 集群由 Master（控制平面）和 Node（数据平面）两类节点组成
    • Master 核心组件：kube-apiserver、etcd、kube-scheduler、kube-controller-manager
    • Node 核心组件：kubelet、kube-proxy、container runtime
    • 控制平面做决策，数据平面执行决策，二者通过 API Server 通信
    • 港口类比：Master=调度中心，Node=货船
