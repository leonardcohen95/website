    ConfigMap 配置

    应用程序的配置（如数据库地址、日志级别、功能开关等）不应该硬编码在镜像里，否则每次修改配置都要重新构建镜像。Kubernetes 提供了 ConfigMap 来存储非敏感的配置数据，并可以将其以环境变量或文件的形式注入到容器中。本章我们来学习 ConfigMap 的创建与使用。

    学习目标

    • 理解 ConfigMap 的作用和适用场景
    • 掌握 ConfigMap 的三种创建方式
    • 掌握将 ConfigMap 注入容器的两种方式（环境变量、Volume 挂载）
    • 理解 ConfigMap 热更新的行为差异
    • 了解 ConfigMap 的使用注意事项

    1. ConfigMap 是什么

    ConfigMap 是 Kubernetes 中用于存储非敏感配置数据的 API 对象。它以键值对的形式保存配置，可以在 Pod 中作为环境变量、命令行参数或配置文件使用。

    ⚠️ ConfigMap 不存储敏感信息

    ConfigMap 中的数据以明文形式存储，不应用于存放密码、密钥、token 等敏感信息。 敏感数据请使用下一章的 Secret。

    2. 创建 ConfigMap

    ConfigMap 有多种创建方式：

    方式一：从字面量创建（--from-literal）

    kubectl create configmap app-config \
  --from-literal=DB_HOST=mysql.default.svc.cluster.local \
  --from-literal=LOG_LEVEL=info \
  --from-literal=FEATURE_FLAG=true

    方式二：从文件创建（--from-file）

    # 假设 app.properties 文件内容如下：
# db.host=127.0.0.1
# db.port=3306

kubectl create configmap app-config --from-file=app.properties

# 也可以指定键名
kubectl create configmap app-config --from-file=config=app.properties

    方式三：从目录创建

    # 目录下所有文件都会成为 ConfigMap 的一个键值对
kubectl create configmap app-config --from-file=./config-dir/

    方式四：从 YAML 定义创建

    apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DB_HOST: "mysql.default.svc.cluster.local"
  LOG_LEVEL: "info"
  app.properties: |
    db.host=127.0.0.1
    db.port=3306

    查看 ConfigMap：kubectl get configmap app-config -o yaml

    3. 使用 ConfigMap

    ConfigMap 创建后，可以通过两种方式注入到容器中。

    方式一：作为环境变量注入

    apiVersion: v1
kind: Pod
metadata:
  name: pod-env
spec:
  containers:
  - name: app
    image: nginx
    env:
    - name: DB_HOST
      valueFrom:
        configMapKeyRef:
          name: app-config       # ConfigMap 名称
          key: DB_HOST           # 要引用的键
    envFrom:
    - configMapRef:
        name: app-config        # 把整个 ConfigMap 所有键值对注入为环境变量
    💡 envFrom 的便捷之处

    当 ConfigMap 中有很多键值对时，使用 envFrom 可以一次性把所有键值对注入为环境变量， 不需要逐个用 configMapKeyRef 引用。

    方式二：作为 Volume 挂载为文件

    apiVersion: v1
kind: Pod
metadata:
  name: pod-volume
spec:
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config     # 挂载到容器内的目录
  volumes:
  - name: config-volume
    configMap:
      name: app-config           # 引用 ConfigMap

    挂载后，ConfigMap 中的每个键值对会以文件形式出现在 /etc/config 目录下，文件名即键名，内容即值。

    4. ConfigMap 热更新

    当你修改了 ConfigMap 的内容后，已经在使用它的 Pod 会如何反应？

    • Volume 挂载方式：ConfigMap 更新后，挂载的文件会被自动更新（有一定延迟，约数十秒）。这是最推荐的使用方式。
    • 环境变量方式：ConfigMap 更新后，已注入的环境变量不会自动更新，需要重启 Pod 才能生效。
    ⚠️ 热更新的局限

    即使使用 Volume 挂载方式，应用程序本身也需要支持重新读取配置文件才能生效。 有些应用启动时只读一次配置，这种情况下仍需重启 Pod。

    本章小结

    • ConfigMap 用于存储非敏感的配置数据，以键值对形式存在
    • 创建方式：--from-literal、--from-file、--from-env-file、YAML 定义
    • 使用方式：环境变量注入（env / envFrom）、Volume 挂载为文件
    • 热更新：Volume 挂载会自动更新，环境变量不会自动更新
    • ConfigMap 不应存储敏感信息，敏感数据用 Secret
